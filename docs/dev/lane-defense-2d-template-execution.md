# 类 PVZ 横向分路塔防模板执行方案

日期：2026-10-29。执行仓库：`C:\Users\wuyu\My\ember-unity-framework`。

配套文档：[胆小鱼之梦消费项目执行方案](timid-fish-nightmare-project-execution.md)。

本方案要求在 Ember 中新增直接继承 `base` 的 `lane-defense-2d` 模板，提供横向棋盘、分路敌人、卡牌放置、基础战斗、波次、胜负和正式启动流程。胆小鱼的彩色弹丸、转向、反射、分裂、传送、合成、护盾组合、养成和剧情全部由消费项目实现。

用户已明确：模板提供基础；老项目代码缺陷很多，不应照搬。老项目只作为需求、资源和迁移线索，新模板及产品逻辑依据 Ember 契约重新设计。本文是待执行方案，没有创建模板、修改代码、切换模板、保存、Bump 或发布。下面的新增类型名是建议名，不是现成 API。

## 1 目标与架构决策

### 1.1 交付关系

```text
com.ember 公共基础设施
└── base 共用启动和业务接线
    ├── platformer-2d
    ├── topdown-2d
    └── lane-defense-2d（本次新增）
        └── 消费项目部署后拥有的 Assets
            └── 胆小鱼装置、弹道组合、关卡、美术、剧情与成长
```

新模板与俯视、平台模板平级。不继承 `topdown-2d` 的玩家移动、武器图与检查点，也不继承 `source3d-2p5d` 的相机操作语义。产品名称不进入公共包、base 或通用模板命名。

“消费项目实现模板”在本方案中指部署通用模板后实现自己的产品。它不意味着必须把胆小鱼再封存成公开子模板；产品正式活动部署身份仍是 `lane-defense-2d`。如果以后需要多个胆小鱼衍生产品，再单独评估正式派生模板。

### 1.2 可见结果

- 经 Framework → Main → Gameplay 进入一块固定正交棋盘。
- 示例使用 5 行 × 9 列，敌人从右向左移动，基地在左侧；行列数是配置，不写死在算法中。
- 选卡后点击空格放置；支持取消、资源不足、冷却、占用和不可建造反馈。
- 至少包含中性示例射手、阻挡物、普通敌人；不使用植物、僵尸或胆小鱼产品素材。
- 射手同路索敌、生成基础直线弹丸、命中造成伤害；敌人遇阻挡攻击，穿过左边界扣基地生命。
- 波次可配置、可开始、可结束；胜败、暂停、重开和返回主菜单形成闭环。
- 消费项目可以更换攻击、弹丸处理、放置限制及结算策略，不必重写棋盘和场景生命周期。
- 一个新 Unity 消费工程可通过正式部署启动示例；仅在开发仓库可运行不算交付完成。

### 1.3 范围选择

| 方案 | 成本与问题 | 结论 |
| --- | --- | --- |
| 从老工程直接抽模板 | 会把单例、Tag 查找、方向耦合、产品美术和缺陷一起带入 | 不采用，用户明确要求避免照搬 |
| 在俯视模板上删改玩家玩法 | 引入大量无关 Player、武器与恢复契约，父模板变化也会增加迁移负担 | 不采用 |
| 从 base 新建分路塔防模板 | 需要新增棋盘与战斗，但职责清晰，能独立验证部署 | 推荐并作为执行基线 |

首版不做通用塔防平台、全功能节点编程器、联网、任意寻路、多人、3D 高度系统、完整 Buff 框架或战斗中任意时刻存读档。模板不实现镜子、转向器等产品装置，甚至不以“高级示例”名义附带它们。

## 2 读取基线与复用依据

本次静态检查读取到：Unity `6000.5.4f1`，本地 `com.ember 0.24.3`，框架 HEAD `b04da0d`，正式编辑身份 `topdown-2d 0.1.0`。工作区有大量既有修改；这些值不是发布声明，执行 F0 时必须重新读取。

`base/template.json` 当前版本是 `0.10.0`，实时 `contentHash` 与 `versionedContentHash` 不同，表明实时内容与封存基线存在差异。不能只凭版本号选择父内容，更不能直接使用当前 topdown 的 Assets 当作 base。新模板父基线必须由项目中心确认，避免把未封存父修改或其他模板业务意外带入。

| 已有能力 | 已读取依据 | 本次用法 |
| --- | --- | --- |
| Module 生命周期 | 公共架构规则、`IEmberModule` 装配机制 | `LaneDefenseModule` 属于可选 Gameplay 业务，不新增必备 Manager |
| 场景准备与所有权 | base `GameSceneScope`、`GameSceneParticipant`、`GameSceneSession` | 通过显式参与者准备一个战斗会话，成功提交后启动 |

| 存储 | base `PlayerDataModule`、`IProgressCodec<T>` | 可复用槽位后端；业务 DTO、版本、恢复语义由模板或产品定义 |
| 时间 | `EmberTimeManager` 等现有设施 | 实施时核对暂停与时间所有权，业务不分散写 `Time.timeScale` |
| UI | EUI 开发中心、公共页面与控件 | 新建 HUD、选卡 Item、结果弹窗，保持中心生成和绑定流程 |

读取的 base 中 `GameInputModule` 和 `PlayerDataModule` 均为 `Enabled=false`。需要使用时必须在新模板显式启用并完成配置，不能假定继承后自动可用。若首版只做关卡内重开且没有持久化示例，不为形式启用空存储模块；交付说明要明确是否包含进度示例。

旧项目使用 Physics2D、正交相机和菱形 Grid。`Level_1`、`Level_18` 中相机为正交，size 为 5.4，Grid 的 cell size 为 `(0.9, 0.51966, 1)`；`UtilsThisGame` 写死了 30° 斜向。旧方案的投影、格子、方向和碰撞强耦合，不能以旋转相机替代重建。新模板从矩形逻辑网格开始，不携带旧坐标补丁。

## 4 结构与依赖

建议保持一个主业务 Module，由普通服务组成内部运行时，不把每种职责都做成全局模块。

```text
Assets/Game/Module/LaneDefense/
  Runtime/          棋盘、会话、放置、战斗、波次、配置与事件
  Editor/           制作窗口、校验、预览、关卡试跑
  Tests/EditMode/   纯规则与配置验证
  Tests/PlayMode/   生命周期、场景、输入、碰撞与清理
Assets/Game/UI/Runtime/Module/LaneDefense/   EUI 中心生成
Assets/GameResource/Resources/Config/LaneDefense/
Assets/GameResource/Resources/UI/Module/LaneDefense/
Assets/GameResource/Prefabs/LaneDefense/
Assets/Game/Scenes/                         正式示例场景
Assets/Game/Documentation/lane-defense-2d/  正式使用、扩展、术语与验收
```

资源是否进入 Resources 依实际加载方案决定。Runtime、Editor、Tests 明确程序集边界；Runtime 不引用 UnityEditor、NUnit 或产品程序集。UI 依赖业务查询和命令，业务不持有卡牌 GameObject、TMP 文本或页面引用。Editor 可以引用 Runtime，公共包不得反向引用 LaneDefense。

建议职责：

| 组件或服务 | 唯一责任 |
| --- | --- |
| `LaneDefenseModule` | 随 Gameplay 装配，登记当前有效会话；不跨关保留场景实例 |
| `LaneDefenseSceneParticipant` | 准备配置、棋盘、资源和会话，返回可启动、可释放结果 |
| `BattleSession` | 状态、时间推进、实体与资源所有权、终局、释放 |
| `BoardModel` / `BoardProjection` | 逻辑网格和占用 / 显示投影与拾取，二者分离 |
| `PlacementService` | 预览检查与最终原子提交，统一拒绝原因 |
| `LaneCombatService` | 同路目标、阻挡、攻击、基础伤害与实体移除 |
| `ProjectileRuntime` | 基础弹丸生成、移动、命中、回收以及可替换处理边界 |
| `WaveRunner` | 时序、已生成/待生成/存活登记及波次结束 |
| `BattlePresenter` | 将事件和只读状态映射到场景表现、EUI 与音效 |

内部服务可以在实现中合并，关键是所有权明确且可独立测试，不以类数量衡量完成度。

## 5 必须先固定的运行契约

### 5.1 棋盘坐标与视角

定义 `Cell(row, column)`：row 从上到下递增，column 从左到右递增；逻辑连续坐标 x 向右、y 向上。可将格中心定义为 `(column + 0.5, rows - row - 0.5)`。屏幕、世界、逻辑位置经过同一个投影转换；格子宽高和相机缩放不改变规则。

正交相机看向 XY 平面，棋盘是矩形分行布局。透视感由背景、装置 Sprite、脚底锚点和排序形成；不能把 Z 或 Sprite 底边当作逻辑行号。`TryScreenToCell` 在棋盘外必须失败，不吸附到最近空格。默认一格一个主体，地形可建造标记与主体占用分开；产品需要多层占用时显式扩展。

排序以逻辑脚底位置为依据，同一角色使用 SortingGroup 组织身体、血条及特效，弹丸和 UI 使用明确层。相邻行的大型 Sprite 可以视觉重叠，但不能因此互相阻挡或误伤。

默认敌人绑定一条 lane，沿 x 轴向左移动。默认射手只选同 lane、前方、射程内的合法敌人。**同路限制是默认攻击策略，不是所有投射物的全局限制**：产品可提供跨行弹道，但不得改变敌人 lane 或依赖渲染坐标碰运气。

### 5.2 定义、运行态与标识

- 定义资产保存稳定字符串 ID、数值、Prefab/表现引用；运行态保存实体 ID、生命、位置、计时与占用。
- 运行期间不能修改共享 ScriptableObject 定义。关卡启动冻结必要配置，编辑器草稿不影响当前会话。
- `EntityId` 配合会话代次；对象池实例复用不能复用旧逻辑身份。清理后迟到回调不得命中新实体。
- 不以数组下标、枚举顺序、Prefab 名称或场景层级名作为长期业务 ID。
- 校验重复 ID、缺失引用、负数费用、非正攻击间隔、越界 lane、波次排序和格子冲突。

建议配置包含 `BoardDefinition`、`UnitDefinition`、`EnemyDefinition`、`ProjectileDefinition`、`WaveDefinition`、`LevelDefinition`、`BattleRuleSet`。首版使用简单 SO 即可，不必为全部配置新增配表工具；数值改用现有配表时，由源表生成，不手改生成物。

### 5.3 放置事务

命令携带会话、卡牌/单位 ID、目标格及产品可选的朝向参数。所有检查都在提交时重新执行：会话是否可交互、阶段是否允许、卡是否可用、费用是否足够、是否冷却、库存/同时存在上限、地形与占用、必要资源是否准备好。

预览不能扣钱、占格、启动攻击或生成真实业务对象。一次成功提交统一完成扣费、占用、实体生成和卡牌状态更新；任一必要步骤失败则回滚整个提交，不能半扣费。快速双击、触摸重复回调、拖拽松开只能提交一次。

默认提供“选卡 → 点击格子 → 放置”和取消；拖拽是同一命令的额外输入适配，不另建规则。是否选择方向由消费项目的放置工作流扩展，模板默认朝右，不自带胆小鱼八向选择器。

移除命令必须带原因：主动拆除、战斗死亡、关卡重置、场景退出等。资源返还及库存归还由显式规则执行，不能在 `OnDestroy` 隐式返款。场景清理不会产生经济收益。

### 5.4 战斗与碰撞

模板负责基础生命、一次攻击周期、一次命中和实体终止。Physics2D 可承担几何查询，但命中结果由业务服务统一提交。对高速弹丸采用上一位置到目标位置的扫掠或等效连续检测，命中排序采用距离与稳定实体 ID；不依赖 Unity 多个 Trigger 回调的先后。

默认弹丸命中一个目标后终止，包含 TTL/边界回收、来源、伤害值、身份、会话、位置和速度。命中去重、对象池重置、取消及终止原因属于基础正确性。产品效果载荷和路由链属于消费项目。

同一次弹丸更新只能有一个处理者决定去留。扩展返回明确结果，例如继续、已消费或由产品接管；命名可调整，但不能默认处理器与产品处理器各扣一次血。产品创建派生弹丸必须走同一会话登记/释放入口。为扩展预留契约，不在模板中实现反射、分裂或传送策略。

敌人攻击阻挡物时记录目标身份；目标被移除后恢复移动。基地扣血、击杀和逃逸是互斥的终止结果，一个实体最多登记一次。伤害结果至少区分“未命中、被阻挡、造成伤害、终结”，避免使用含义不明的 bool 承载护盾结果。

### 5.5 会话、波次与终局

建议状态：Preparing → Ready → Running → Intermission → Running → Won/Lost → Disposed。暂停是独立意图/句柄，不强行覆盖当前波次状态。默认 Ready/Intermission 可以布置，Running 是否允许布置由规则配置；暂停时默认不提交建造命令。

每个波次使用显式 spawn entries：敌人定义、lane、生成时刻/间隔及必要变体参数。结束条件是“本波生成任务全部完成且本波有效存活敌人为零”，不把最后生成的敌人当作最后存活敌人。空波次、生成失败、取消和重复开始都有定义：空波次可立即完成；必要资源缺失属于配置失败，不能静默算胜利。

所有波完成且无剩余敌人时胜利；基地生命 `<= 0` 时失败。同一模拟步同时满足时，默认失败优先，先汇总该步事件再结算一次。终局封闭新命令、停止生成和攻击、释放未完成任务，随后展示结果。退出场景不算胜利、不发奖励。

### 5.6 时间、准备与清理

只设一个战斗时间入口。冷却、攻击、刷怪和弹丸按相同战斗时间推进；UI、加载遮幕及保存等待使用合适的非战斗时间，不能被用户暂停卡住。倍速可作为配置能力，不能混用多套缩放重复乘倍速。

`PrepareAsync` 检查配置、加载资源、建立候选会话但不刷怪；准备失败释放已获取内容。`Start` 接管候选会话，完整可交互后才开放输入。Module 激活不等于场景已准备，UI 打开不等于战斗已开始。

会话唯一持有实体、定时任务、事件订阅、池租约、相机和输入所有权；`Dispose` 可重复调用。重开创建新会话代次，旧延迟攻击、音效回调、弹丸与 UI 事件全部失效。场景重载和应用退出沿 base 的 stop/drain 契约完成，不能增加平行生命周期。

### 5.7 存档与重开边界

首版必须有“按本关初始配置重开”；不要求恢复战斗中任意时刻。若提供模板级进度示例，只保存关卡 ID、已完成状态、选卡配置等稳定数据，使用 base 存储后端并处理失败。

消费项目负责产品成长和旧档导入。首版不宣称能存储弹道链、合成缓存或传送配对的半途状态。今后增加中途存档要独立定义快照屏障、产品扩展状态和版本迁移，不能通过序列化整个 GameObject 场景实现。

## 6 消费扩展契约与两端交接

扩展点只保留已有需求对应的少数入口。优先组合与普通接口，不新建万能插件总线。下面的契约名称为设计建议，F1 时冻结实际签名和所有权。

| 契约 | 模板默认行为 | 消费项目可替换行为 | 必须保持的不变量 |
| --- | --- | --- | --- |
| 放置策略 | 单格、默认朝右、基础费用与冷却 | 多方向、配对装置、产品限制 | 最终提交原子、取消不扣费 |
| 攻击策略 | 同路前方索敌并直线发射 | 无目标发射、指定出口、产品技能 | 同一会话计时与取消 |
| 投射物处理 | 直线移动、一次命中、消费后回收 | 产品弹道运行器及节点交互 | 唯一命中提交者、身份隔离、预算与释放 |
| 命中规则 | 基础伤害 | 颜色、护盾、治疗、状态效果 | 单次结算、结构化结果、无重复死亡 |
| 经济来源 | 配置初始资源，提供统一增减入口 | 命中产费、技能或奖励产出 | 校验来源、上限和重复事件 |
| 终局观察 | 输出不可变战斗结果 | 星级、金币、解锁和战役推进 | 结果 ID 稳定、奖励幂等 |
| 表现适配 | 示例 Sprite、动画、HUD | 猫、鱼缸、装置端口与音效 | 不驱动权威规则、不按 Sprite 推断位置 |

产品可以完全替换默认投射物运行器，模板只约定会话注册、更新、命中提交和释放。两个运行器不能同时处理同一实体。若现有通用契约不能支持产品，不在消费 PackageCache 打补丁：先提交最小公共问题，再在框架仓库做必要修复。

框架交接必须给出：包 tag/commit、模板 ID/version、实时及封存 hash、父 ID/version/hash、实际 Unity 版本、输入 Action 名、运行程序集、资源/场景路径、扩展契约签名、示例用法、已测范围、未测项和部署步骤。未发布字段写“未发布”，不填写推测的未来版本。

## 7 编辑器与 UI 制作要求

工作台入口建议 `Ember/LaneDefense/塔防开发工具`。首版含关卡配置选择、棋盘网格预览、出生点与基地位置、波次清单、缺失引用诊断、正式启动试跑。先提供可用的 Inspector 和校验，再增加必要可视化，不把完整自定义关卡编辑器变成首版阻塞项。

所有入口使用正式 `EmberProjectSetup.IsTemplateActive("lane-defense-2d")` 及模块启用判断。覆盖所属模板、合法派生、无关模板、缺失身份、消费部署身份。非所属模板隐藏；已打开窗口在身份变化后停止写入/试跑并保留草稿。只写 MenuItem validate 返回 false 不能算入口隐藏。

正式 UI 通过 EUI 开发中心制作：BattleHUD、CardItem、PausePopup、ResultPopup；业务逻辑写用户文件，Binding、Prefab 骨架与注册由中心生成。沿用 base 设置、Loading 和通用弹窗。默认 UI 至少展示资源、基地生命、波次、卡费用/冷却/不可用原因、开始/重开/返回。

模板正式文档维护于 `Assets/Game/Documentation/lane-defense-2d/`，包含 README、glossary、RuntimeContracts、Authoring、ExtensionGuide 和验证边界。本文只是仓库实施记录，不让消费端依赖开发机器绝对路径。首版不强制新增专属 AI Skill；确需技能时再按模板 schema v2 及所有权规则分发。

## 8 分阶段执行清单

每阶段完成后留下“实际改动、源码/资产位置、相关验证、待办、下一阶段入口”，不以整份方案读完代替进度记录。

### F0 保护现场与确认父基线

1. 读仓库规则、术语、编码规范/API 速查、Unity 验证规范与本方案；确认项目是 embedded 开发环境。
2. 记录当前正式模板身份、未提交文件、未保存场景、base 实时/封存差异和包实际版本。
3. 保留当前 topdown 草稿，不执行 reset/clean、不保存到错误模板、不重写现有快照。
4. 通过项目中心确认可用父基线和创建新模板的正式流程；切换前说明目标与可能弹窗，按公共规则由用户处理确认。
5. 中心不可用或父基线不明确时停在此关口，保留方案及现场，不能用复制 Templates~ 创建替代品。

产物：F0 基线记录、可使用的 base 内容身份、当前草稿恢复入口。退出条件：新模板开发现场与旧草稿已隔离且可恢复。

### F1 冻结最小规则与接口

1. 固定行列坐标、攻击方向、放置阶段、移除原因、波次结束、同帧终局和时间归属。
2. 定义配置/运行态、命令/结果 DTO、实体与会话 ID。
3. 明确默认投射物和产品替换的唯一执行者，写一份不含胆小鱼概念的扩展示例说明。
4. 列出 F2～F6 相关用例；只对高风险规则做有意义测试，不为简单访问器铺测试。

产物：接口契约与配置 schema。退出条件：消费项目可以开始设计产品数据，无需猜模板生命周期。

### F2 正式启动与棋盘放置

实现 Module/SceneParticipant、配置准备、正交棋盘、拾取、预览、资源与占用事务。完成 EUI 最小 HUD 和卡牌。验证棋盘外、UI 遮挡、快速重复点击、取消、实例化失败和重开清理。

产物：可以进入、放置、拆除和返回的白盒。退出条件：没有扣费/占用不一致，退出不触发奖励。

### F3 基础分路战斗

加入普通敌人、阻挡攻击、射手索敌、直线投射物、命中去重、基地扣血和对象回收。验证相邻行隔离、高速命中、目标死亡、重复碰撞和旧回调。需要池时优先复用已确认可用机制，不为首版新增公共池框架。

产物：单路闭环与多路并行白盒。退出条件：基础战斗不依赖 UI 对象或旧项目 Tag。

### F4 波次与完整结算

实现配置波次、等待清场、波间状态、胜败、暂停、重开及返回；若做倍速，所有战斗计时统一接线。加入至少两套不同棋盘/波次配置，证明没有写死 5×9 或固定四波。

产物：可从主菜单完整游玩的中性示例。退出条件：最后生成敌人先死不会提前过关，终局只执行一次。

### F5 扩展验证与制作工具

用中性测试策略验证替换攻击、拦截命中和自定义放置拒绝；测试夹具不成为正式产品玩法。完成工作台、配置校验、输入与制作文档，确认窗口失效保护。跨行弹道接入只验证接口能表达，不实现装置组合。

产物：可供消费项目接入的模板候选。退出条件：产品不需要引用兄弟模板或改私有字段才能扩展。

### F6 Unity 增量验证与消费样例部署

执行第 9 节相关测试及人工画面验收。通过正式部署在独立消费工程验证；若该工程不存在，记录未完成并在消费 C1 补验，不能宣称已验证。开发端通过和消费端通过分别记账。

产物：编译/测试/试跑证据与缺陷清单。退出条件：必测失败全部解决；未测设备或平台单独列出。

### F7 保存、封存与发布交接

1. 内容先维护于 Assets，通过项目中心正式保存；核对 diff、模板清单和父基线。
2. 在获得对应授权后，通过中心 Bump，核对实时与封存 hash 关系，不手改 metadata。
3. 如需要发布，使用 `ember-release-framework` 流程，协调包版本、变更说明、检查、提交和 tag。保存、Bump、提交与发布授权分别判断。
4. 输出第 6 节交接清单和消费部署说明。没有发布授权时交付已完成阶段与待发布事项，不自行发布。

模板候选、模板已保存、模板已 Bump、包已发布、消费端已验收是五种不同状态，必须分开报告。

## 9 验收矩阵

| 编号 | 范围 | 必须验证的结果 |
| --- | --- | --- |
| T01 | 棋盘与投影 | 行列和屏幕坐标往返；边界外拒绝；非方形格子、不同分辨率不错格 |
| T02 | 放置事务 | 冷却/资源/上限/地形/占用拒绝；双击一次提交；失败与取消零副作用 |
| T03 | 移除 | 拆除、死亡、重开和退出的返还规则分离，不重复归还 |
| T04 | 分路战斗 | 同路最近合法目标；相邻行大 Sprite 不串路；阻挡死亡后继续移动 |
| T05 | 投射物 | 高速扫掠、一次伤害、一次回收、TTL、池重置和会话代次 |
| T06 | 波次 | 空波、多波、延迟生成、重复开始、末个生成者先死、漏怪和生成失败 |
| T07 | 终局 | 基地生命低于零仍失败；同帧胜败优先级；退出不胜利；结果只发布一次 |
| T08 | 时间 | 暂停恢复、可选倍速、失焦输入、转场阻断；UI/Loading 不被战斗暂停锁死 |
| T09 | 所有权 | 准备失败、取消、重复重开、退出后迟到回调，无残留实体/订阅/租约 |
| T10 | 扩展 | 替换攻击/投射物不双执行；拦截命中不双扣血；关闭扩展仍运行默认示例 |
| T11 | 工具隔离 | 正式活动/派生/无关/无效身份、模块禁用、旧窗口及消费部署身份 |
| T12 | 独立部署 | 解析包、部署身份、场景入口、UI 绑定、资源引用与扩展文档均可用 |

每批代码/程序集变更后，必须通过 Unity MCP 主动请求编译，确认本轮编译和域重载完成，再读取 Console。Refresh 成功或空 Console 不能单独证明完成。场景资源变化同样通过 MCP 刷新并检查。

默认仅运行本次新增及直接相关用例，执行前列明过滤范围。全量或预计长时测试另行获得授权。MCP 断连按公共规范：先检查待编译改动并尝试请求，无法送达立即提醒手动编译；结果不明不重复提交，30 秒间隔最多 10 次重连。不能用 dotnet、BatchMode 或轮询日志代替。

画面至少在 16:9 与一种较窄比例下检查格子拾取、卡牌栏、基地边界与弹窗；实际目标设备在消费项目另验。性能先记录示例和约定压力场景的实体/弹丸数与 Profiler 结果，再确定预算，不预先声称达到某帧率。

## 10 风险与回退

- 当前父模板有未封存差异：F0 必须先确认父基线，不能顺手修复 hash 或覆盖当前草稿。
- 扩展过度：只交付基础和必要接口；特殊装置即使容易写，也留给消费项目。
- 默认同路规则封死产品：将同路约束放在攻击策略；投射物接管接口保留逻辑二维位置和明确命中所有权。
- 模板保存失败：保留 Assets 及阶段记录，报告未保存；不得复制到快照目录补救。
- 回退：以正式中心记录恢复原编辑现场，保留当前草稿；消费方回到已验证包/模板基线。回退依赖状态与文件备份，不能单独把 metadata 版本改小。
