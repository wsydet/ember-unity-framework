# Ember Framework 0.12.9 发布说明

日期：2026-09-14。Tag：`v0.12.9`。归属：**框架升级**。

## 快速打开场景

此前刷新后，窗口通过 `EmberSceneField.HasValue/SceneName` 判断可打开状态并按名称查找场景。
映射 SO 保存了 SceneAsset 引用，但场景名缓存未序列化，只有选中 SO 后触发序列化回调才恢复，
导致已经配置场景的窗口显示未设置或无法打开。

本版增加仅编辑器可用的 `EmberSceneField.EditorScenePath`，窗口按已绑定场景资产的真实路径
显示、检查和打开，避免依赖 Inspector。纯名称构造的引用仍支持查找，但同名时要求明确绑定资产。
刷新按状态身份保留主场景及叠加场景选择，列表缩减时调整索引，配置不存在时清空旧列表并保留刷新入口。
刷新后终止本轮 GUI 绘制，下一次 Layout 重建控件。

打开前检查框架场景、主场景及已选叠加场景，提前解析并去重路径；无效选择不能开始切换。
仍通过 Unity 的保存提示处理未保存场景，运行或准备进入运行模式时禁用打开。

## 发布范围与验证

- 修改场景打开器、增加编辑器路径属性及 API 文档。
- 新增 4 个 EditMode 回归：无名称缓存直接打开资格、重命名/同名解析、刷新后选择与空配置、无效叠加场景阻断。测试只复制临时资产，不打开或替换用户正在编辑的场景。
- 模板保持 `base 0.6.3`、`source3d-2p5d 0.3.5`，父快照、Hash、0.12.0 兼容声明及 GuideModule.Enabled=false 不变。无需重新保存或部署模板。
- 完整依赖清单仍为 56 项，仅更新 com.ember 至 v0.12.9；第三方继续使用 ember-v0.11.1，共享字体保持 0.12.8 已发布内容。
- 字体动态缓存、生成的 slnx、Table 状态和本地模板交接记录不进入本次提交。

静态检查覆盖发布版本/依赖一致性、模板未变、编辑器程序集引用、Git 空白，以及共享字体配置、二进制完整性与两种 autocrlf 的干净检出。

本次 Unity MCP 不可用，Unity 编译、4 个新增 EditMode 测试和实际窗口交互尚未验证。此前用户对 0.12.8 的编译确认不作为本次修复的验证结果。

已有项目通过 **Ember/UPM Manager** 升级到 0.12.9；不直接修改消费端 manifest/lock 或 PackageCache。
升级后验证“打开工具 → 刷新 → 选择主场景/叠加场景 → 打开场景”，全过程无需选中 SO。

当前 Unity MCP 不可用，本次未完成 Unity 编译验证。请在 Unity 中手动触发编译；如果仍有报错，请将首条编译错误及其完整堆栈发回当前对话。
