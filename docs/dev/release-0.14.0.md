# Ember Framework 0.14.0 发布说明

2026-09-22。发布标签 `v0.14.0`。用户已授权提交和发布；Call Me Heartless 由用户手动更新验收。

## 已封存

- `visual-novel 0.7.0 / preview`，父模板 `base 0.6.4`。
- 正式调用 `SaveTemplate` 保存 810 个文件，再调用 `BumpTemplateVersion(..., 1)`；未直接修改模板快照或 hash。
- `contentHash = versionedContentHash = 43fb51b0679d7ca4c82e4d6f1b5a22ce`。正式 API 重算一致，模板图检查 0 个问题，编辑记录已更新为 0.7.0。
- 父基线 hash 保持 `2257aea46640e1f91735ba006522507d`。本次没有父同步或修改 ParentSnapshot。
- 与 0.6.0 业务快照相比仅新增四项 Skill、说明文档及剧情编辑身份修复和六个测试用例，没有修改剧情、美术或配表内容。

## 本版交付范围

框架提供原有九项通用 Skill 的随包首次安装，以及模板 Skill 的固定版本分发、继承、预览、归属记录、切换、备份和异常回滚。旧 schema v1 通用目录/记录继续兼容；混合记录使用 v2，旧更新器不能继续管理 v2。包升级不静默覆盖既有模板技能，模板内容仍须显式部署。

视觉小说包含四项 Skill：图片导入与配表、飞书指定范围剧情导入、不改变剧情的演出优化、向指定飞书表格新建页回写实际流程。后两项飞书读写入口先检查 `lark-cli`；缺少时要求安装后继续，绝不覆盖原飞书页。

剧情编辑器改用 Core 的正式编辑/活动部署记录，根据 embedded 模式选择唯一来源；消费端残留编辑记录不能冒充当前身份。支持 visual-novel 及其已登记派生谱系；保留 NarrativeModule 启用、Play Mode 与 Assets 写入限制。新增 `Ember.Core.Editor` 业务编辑器依赖，方向仍是业务 → 框架。

技能最低框架版本为 **0.14.0**、最低模板版本为 **0.7.0**。模板 metadata 的 frameworkVersion 仍沿用父模板声明 0.13.0，不手改父谱系；技能目录会单独阻止旧框架启用。旧 0.13.2 包没有本地新增的技能系统，不能用它部署这版快照。

`package.json`、`Dependencies~/release-0.14.0.json`、`manifest-0.14.0.json` 已准备。56 项完整依赖基线只推进 com.ember，其余第三方固定来源不变。框架通用 Skill 唯一源不变，bundle 校验为 9 项/24 文件。

## 实际验证与限制

- 发布暂存检查发现根目录 LFS 规则会将模板图片/音频转为指针；包内 `Templates~/**` 已禁用 filter/diff/merge，保持原始二进制随 Git/UPM 发布，未改变模板文件或封存 hash。发布检查逐文件核对暂存字节与封存快照一致。
- 四个 Skill 格式检查通过；正式技能预览在更新最低版本前确认四项无错误；封存 hash 与图检查通过。
- 更改 package.json 后，当前 Unity PackageInfo 尚报告旧版本，最终技能预览按最低 0.14.0 正确阻断四项。需要 Unity 重新解析包版本（必要时重启编辑器），不降低最低版本绕过。消费端安装真正的 0.14.0 后应再次核对。
- 本次 Unity MCP 编译刷新等待 60 秒超时，按 CLAUDE.md 停止自动编译/测试验证；之后只调用既有正式保存、封存与只读 hash/图检查 API。封存成功不等于编译通过。
- 六个身份选择测试及此前 AI Skill 隔离/事务测试源码已包含，但本次没有执行测试结果或 XML，不声称全项目通过。
- 当前未找到飞书 CLI，没有读取原在线表格、真实导入或远端写入；截图仅作为五列表头与语义的格式依据。

后续用户明确反馈：手动编译无报错。此反馈记为人工编译验证，不等同于新增测试通过；未取得新的自动测试 XML。

## 发布与 Call Me Heartless 验收顺序

1. 用户已确认手动编译无报错；自动回归和技能中心在实际 0.14.0 包上的预览仍应继续验收。保存实际测试结果，不用历史批次总数替代。
2. 发布提交纳入完整框架实现、模板快照、开发源、bundle、测试和文档；仅 BOM/换行改动、运行时字体图集、个人调试配置和生成解决方案留在本地。依赖基线不变；发布清单标为 released-consumer-validation-pending。
3. Call Me Heartless 先备份现有业务目录与配置，通过 **Ember/UPM Manager** 升级到实际发布的 0.14.0，等待解析并编译。不要直接覆盖项目 manifest，不自动装齐可选依赖。
4. 项目中心完整预览并部署 visual-novel 0.7.0，处理本地修改与冲突。只升级框架不会升级 Assets。四项模板 Skill 应随部署进入项目 `.agents/skills/`，记录有效模板身份；不安装到个人全局目录。
5. 重开 AI 会话发现技能。先试图片导入；安装/配置飞书 CLI 后试少量指定行剧情导入，再优化演出，再回写**新页**。检查重复操作、取消、冲突、台词保真、分支不变及备份恢复；逐项验收见模板文档。

发布操作不访问或修改 Call Me Heartless。已加载到会话的旧技能不能即时撤回；每次执行仍须身份前置检查。
