# 视觉小说接入公共存档模块：待实施契约

本页承接平台临时方案原 §14 的独有消费需求，属于开发仓库的跨模板迁移计划，**未实施、未发布、未升级消费项目**。它不是平台玩家 Skill 或公共存储模块的运行依赖。正式小说操作说明须在用户加载 visual-novel 后落到其模板文档维护源；不能直接修改模板快照或消费项目 PackageCache。

当时 NovelCheckpoint 为 Schema 9，含随机状态、调用栈、剩余等待与演出数据。NovelSaveStore 使用 `VisualNovelSaves/index.json`（Schema 1）、6 个手动槽 0—5、快速槽 6、自动槽 7、4 MiB 上限及 SHA-256 校验；新负载先写、索引最后 File.Replace 并留 .bak，旧负载保留，不自动回退备份。账户已读/偏好走独立 account.json 队列，语言走 PlayerPrefs。以上是接入前需重新核实的基线，不应固化成公共模块规则。

## 所有权和接线

| 既有职责 | 目标所有者及限制 |
| --- | --- |
| 槽位、读写队列、索引和文件事务 | 启用新的 PlayerDataModule，配置独立目录、稳定 DataTypeId 与槽位；不硬编码章节或剧情类型 |
| 完整进度类型 | 保留 NovelCheckpoint；提供普通对象 codec，调用时显式传入，不反射注册、不改成等级/金币示例 |
| 采集、Track、AutoSaveRevision、稳定点自动保存队列 | 小说协调层；沿用触发算法，提交完整独立快照，不引入公共定时保存 |
| 语义、剧情指纹、资源准备与演出恢复 | 现有 NovelSession/NarrativeRunner；codec 只承担编码、基础版本识别及适合它的纯数据转换 |
| account.json 已读和偏好 | 独立账户服务，保留产品格式和有序写入；新增可等待 Flush，不随普通槽位恢复回退 |
| 语言 | 继续现有 NovelLanguageSettings/EmberLocalization 持久化，不强塞进槽位或账户 |
| UI、主菜单、快捷键、退出 | 调用小说协调入口并等待每请求最终结果；不以接受 bool 或全局 Message 判断保存/恢复成功 |
| 旧 NovelSaveModule | 完成迁移后退役，或短期作为没有独立存储生命周期的转发门面；不得再独立装配为第二个写入者 |

依赖为小说协调/codec 适配层 → PlayerData 存储及 Narrative；公共存储不反向引用 Narrative。一个配置服务一个完整文档族，不增加模板组合分区、任意 object 或多业务拼装。账户文件不属于进度槽位。

## 准备、恢复与提交

1. 等待当前服务世代的 WhenReady，检查结果；TryGetModule 只证明已登记，OnInit 返回不证明异步就绪。同 Phase 没有依赖排序，不靠发现顺序。
2. 读指定槽位并等待本请求 Completion。Loaded 只表示文件完整性与 codec 解码成功，尚未恢复小说会话。
3. 用独立候选沿用既有语义校验、旧版本处理与资源准备。不能承诺所有旧 Schema 都能无条件升级；负载版本与封装声明须一致。
4. 失败/取消释放候选、保留旧会话及会话来源槽位；检查请求与会话世代，迟到回调不得启动旧会话。
5. 成功后在现有业务提交边界交接。旧会话 Dispose 已开始即不可逆，之后的失败必须报告 CommitFailed，不能宣称自动回滚。

主菜单进入可通过 NovelPreparedGameRequest 交接，在场景中恢复沿用 CommitCandidate；不要求把所有恢复强塞进 PrepareEnterAsync。候选应由 Global 协调对象或独立操作持有，经参数在 Gameplay Reset/OnInit 后交接，不能提前写入会被重入清空的 NarrativeModule.Session。旧 I/O 未释放目录所有权前不得建立新写入者。

保存须重新采集运行数据；在接受前同步编码并冻结负载与摘要，后台只处理纯字节。显式槽位读写，不维护隐式当前槽位；读取不改变最近成功保存槽位。会话来源槽位由业务在恢复提交成功后更新，新游戏可以为空。

## B 路径：旧档只读导入

- 保持旧 VisualNovelSaves 根目录只读，公共新格式使用独立根。先核实旧索引、相对路径、大小、SHA-256 与业务版本；损坏原文件不改写。
- 每槽构造独立完整候选与摘要，执行必要兼容检查，再调用新模块正常保存。可以复用候选语义/资源准备，但不为导入启动正式会话。
- 默认不覆盖新库已有槽位；出现冲突时由用户明确选择。记录旧槽 ID、摘要、来源校验与原保存时间，区分导入提交时间。
- 识别相同来源的重复导入。多槽分别报告，失败不撤销其他成功项，也不删除旧档或伪装整体成功。
- 按旧保存顺序提交，原 Latest 若有效且导入成功则最后提交；缺失/失败明确报告差异，不伪造最近成功项。
- 切换前核对新库，正式只装配新存储模块，不双写。回退旧程序仍能读保留的旧目录，但导入后新增进度不会自动回流。

## 正常退出与失败责任

先停止产生新保存请求，将小说仍持有的自动快照提交或明确报告放弃，再 BeginDrain 关闭入口并记录固定水位。等待进度 Drain 和账户 Flush 的各自结果，失败可重试、取消退出或明确放弃，之后才释放会话/退出。

队列清空不等于全部成功，历史未确认失败仍须由业务处理。取消等待不撤销正在提交的写入；恢复入口须验证服务世代，重试是新请求。OnDestroy 不承担可等待采集/保存职责，强制杀进程不能保证最后一次写入完成。

## 实施与验收清单

1. 用户加载小说模板后，核对上述历史基线、全部入口和真实程序集，保护现有草稿及真实存档；先补独立 codec/协调层，再改 UI/退出与旧模块测试夹具。
2. 验证冻结后修改、同槽/跨槽串行、取消提交边界、索引失败保原档、重启后最近成功槽位、损坏/未知版本和备份负载保留。
3. 验证 Loaded 后语义/资源失败仍保原会话、Reset 不清候选、陈旧请求隔离、账户/语言不被回档、自动队列与历史失败不因退出被吞掉。
4. 验证导入重复、冲突、部分失败、Latest 与旧目录保持，确认只有新模块管理正式进度库。使用隔离数据，不以源码阅读代替真实恢复验收。
5. 模板普通保存、Bump、发布与消费升级分别授权；消费框架经 UPM Manager，Assets 按实际差异迁入，包升级不等于模板已部署。

跨平台文件后端、断电恢复、云同步、并行/合并队列、通用迁移注册框架、孤儿自动回收、自动备份恢复 UI 与性能优化可后置；不能因此后置可靠提交、显式兼容入口和正常退出刷新。本轮未实施小说存储接线或读取真实档案。
