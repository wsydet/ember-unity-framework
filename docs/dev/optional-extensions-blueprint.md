# 可选扩展的蓝图可视化后续方向

记录日期：2026-10-29。

状态：用户确认的后续需求，仅记录设计方向；扩展蓝图可视化尚未实施。本记录不增加当前扩展机制开发的交付门槛，也不表示已有扩展 API、菜单或消费项目迁移已经完成。

## 目标与组合关系

将可选扩展及其依赖关系纳入 Ember 的蓝图可视化，让开发者能够像拼图一样查看项目由哪些能力组成、为何需要某个扩展，以及改变组合会影响哪些功能。玩法模板继续独立维护；复用扩展不要求它们继承一个新的共同玩法父模板。

候选能力包括通用 FSM、FSM 蓝图工具、关卡制作与正式试玩、房间／地图编排。具体扩展 ID、拆分和依赖由实现确定，不能把本页的功能名称当作已存在的 API。依赖应表达实际需要：例如 FSM 蓝图工具依赖 FSM；地图编排通过关卡制作能力接入试玩时声明相应依赖，不因二者都有节点画布而强制依赖 FSM。

## 未来可视化范围

- **项目组合视图**：以扩展为节点、依赖为有向连线，展示项目启用选择、依赖所需状态、不可用原因及兼容诊断，并区分模板默认组合与项目当前配置。
- **影响追踪**：选中扩展后查看依赖链和使用方；启用或关闭前展示受影响能力，定位缺失依赖、循环依赖与不兼容条件。
- **业务导航**：从扩展定位其提供的工具、业务适配器，以及已登记的 FSM 图或地图编排资产。具体对象仍使用所属工具编辑，不把房间连接解释为状态转换。
- **可选的图上装配**：后续若支持在画布调整组合，应先生成变更预览，再调用与项目中心相同的校验和应用入口；移动节点或整理布局本身不改变启用配置。

扩展依赖图、FSM 状态图和房间编排图具有不同含义。可以统一导航与交互习惯，但不共用状态转换语义、不要求所有扩展实现运行时 FSM，也不由可视化窗口额外驱动业务 Update。编辑器扩展不因可启用而自动变成常驻 Manager 或业务 Module。

## 与扩展机制开发的衔接

扩展登记及项目配置是唯一事实来源，未来蓝图读取同一份依赖、启用和诊断结果，不另建一份图资产来复制扩展清单。开发扩展机制时保留稳定标识、明确依赖和可读取的诊断信息即可，不要求为了本记录提前实现通用图编辑平台或虚构尚未确定的公共接口。

当前 [FSM 蓝图登记与模板隔离](../../Packages/com.ember/Documentation~/manual/fsm-blueprint-access.md)仍描述现有行为；只有新扩展机制实际实现、验证并更新正式契约后，才能改变其接入规则。通用扩展入口服从正式启用状态，业务专属入口继续遵守所属模板和模块条件。身份或启用状态变化后，旧窗口必须停止有效操作并保留草稿。

Windward 的地图组合窗口可作为后续通用能力的来源案例。抽取时保留产品资产、稳定身份及接线适配，区分图上排版与实际世界坐标；产品挑战、评级、存档及加载策略不因可视化整合而进入公共扩展。框架开发与消费项目恢复通过明确的迁移说明衔接，不能用旧项目目录整体覆盖新实现。

## 后续验收与本次边界

真正实施可视化时，至少验证：图与项目中心配置一致；依赖链和错误定位准确；变更预览与正式应用结果一致；布局操作不改变业务配置；无效身份、扩展关闭、域重载及旧窗口不能绕过校验；原有 FSM 与地图编辑、试玩行为保持。

本次仅新增需求记录及文档索引，未修改代码、资源、模板快照或 Windward，未执行扩展启用、模板保存、Bump、发布或消费升级。文档检查不代表上述未来能力已通过 Unity 验收。
