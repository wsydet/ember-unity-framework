# Ember Framework 0.14.5 发布说明

2026-09-23。本次归类为框架升级：为模板补丁提供消费端三方增量部署与可复制冲突日志。
三个模板内容及兼容声明保持不变：base 0.6.4、source3d-2p5d 0.3.7、visual-novel 0.7.2，
均声明框架 0.14.1，与 0.14.5 的 major.minor 相同。本次没有修改模板快照、第三方依赖或消费工程。

## 行为

- 同一活动模板 major.minor 相同且 patch 递增时，项目中心提供“预览补丁增量更新”，支持跨多个 patch。
  前两位变化时，先保护本地改动，再完整部署并恢复。框架版本与模板内容版本独立。
- 持久保存部署原稿至 ProjectSettings/EmberTemplateBaseline~/，与部署记录一起提交版本控制。
  旧版原稿、新版模板和本地项目三方比较：新版单方变化自动应用，本地独有文件与本地单方变化保留，
  双方不同修改需要逐项选择；资源及其 .meta 成对处理。
- “复制冲突日志”提供项目/模板身份、版本、三方路径与指纹、GUID、冲突类型和待提交选择，
  供后续本地改动恢复 Skill 协助合并。日志不含文件正文；合并后重新预览，核对结果再应用。
  本版不交付该恢复 Skill，不执行自动文本 diff3 或场景语义合并。
- 逐文件及目录事务同时提交业务差异、技能发现副本、部署记录和新基线；冲突未解决、预览过期、
  资源配对错误或 GUID 碰撞时拒绝写入。目录仍有本地内容时，不允许删除其 .meta。
  场景注册和映射刷新沿用部署后流程，不属于文件事务。
- “补齐缺失”只允许相同模板版本/hash 修复缺失，不再冒充升级或推进部署记录。

## 消费项目如何使用

1. 在 Ember/UPM Manager 升级框架至 v0.14.5。此次框架升级没有改变模板内容，无需重新部署模板。
2. 今后模板仅末位递增时，在项目中心“预览补丁增量更新”检查差异。
3. 旧项目没有部署原稿基线时，选择“从旧模板恢复部署基线”，导入历史框架包里对应旧版本模板的
   Assets 目录。hash 必须匹配旧部署记录；恢复基线不修改业务内容，不要求完整部署。
4. 有冲突时复制日志给负责合并的 Skill/开发者，只修改本地项目文件，再重新预览。
   合并后的冲突文件核对无误后选择保留本地；所有冲突解决后应用更新。
5. 新基线必须保存模板原稿，不能用合并后的业务文件替代。旧记录曾被补缺错误推进或缺少 hash 时，
   需先核实真实历史原稿与记录，不能自动猜测。

patch 发布必须保持业务扩展点、GUID、序列化和目录结构兼容；需要重建或重写业务的变更应提升
minor/major。版本号本身不代表可以无条件覆盖项目文件。
