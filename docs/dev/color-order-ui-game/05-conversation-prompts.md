# 给其他对话的启动指令

以下三段按执行地点和进度使用。用户将对应提示词发送到目标工程对话即可，不需要再次口头解释三份策划优先级。相对路径基于目标仓库根目录；如果文档包移动过，替换开头的文档目录。

提示词授权的是各自明确范围。部署目标、发布 tag、模板 hash 等真实信息由执行者读取或填写，不从本文猜测。

## A. 框架仓库：创建通用 UI 游戏模板

```text
请在当前 Ember 框架开发仓库实施 docs/dev/color-order-ui-game/README.md 与 02-framework-template.md 的阶段一方案，并阅读 01 的职责边界和 04 的验收要求。

目标：通过项目中心从 base 正式派生 ui-game 通用 UI 游戏模板，提供中性点按 Demo 的主页、玩法、暂停/设置、结果、重试闭环，以及消费项目如何替换 Demo 的正式说明。颜色排序、九宫格、双目标、奖励星、定格、评分及九关均留给消费项目，不写入模板或 base。不预设需要新增框架公共 API。

请先重新核对正式编辑身份、实际包/父模板版本、Git 状态、内存草稿与已有任务成果。保护并验证当前工作区和 .meta 备份，记录可恢复位置；不清空现有修改。若已存在 ui-game，先判断是否可继续，不重建覆盖。此指令授权完成必要保护后，经项目中心创建并加载 ui-game；不要为同一切换再次要求确认。不要把当前 platformer 编辑副本“另存为”UI 模板。

按方案分批实现。正式 Page/Popup/Item、Prefab、Binding 和注册走 ember-eui-build / EUI 开发中心；代码只改项目 Assets，不能直接改 Templates~ 或 ParentSnapshot~。保留纯 UI 场景合法 Scope，明确业务暂停与旧会话取消，不让两个玩法入口重复启动。

执行相关 Unity MCP 编译/域重载、Console、增量测试和 Play 验证。测试范围仅新增或直接相关部分；预计较长或全量测试遵守公共规则。真实操作结果与未验证项分别报告。

此指令授权项目中心普通保存及与实际新增结构匹配的一次模板 Bump，并记录真实版本/hash/父链结果。Git 提交、推送和框架发布不在此条范围；先完成可审阅的发布准备和交接单，不编造安装 tag。中心不可用时保留 Assets 并报告未完成，不绕过保存。

最终交付实际修改、模板正式文档入口、Demo 替换方式、验证证据、保存/Bump 状态、原工作区保护状态和 04 的框架交接单。需要新框架发布才能让新项目安装时，明确剩余具体动作。正式模板说明维护在 Assets/Game/Documentation/ui-game/，不能让消费端依赖本机路径。
```

该提示词把保护、创建、加载、实现、普通保存和模板 Bump 一并授权，减少执行过程中重复确认。框架发布仍是独立动作，使用下一段衔接。

## A2. 框架仓库：交付可安装版本

在阶段一完成并审阅交接结果后使用：

```text
请继续本对话已完成的 ui-game 模板交付，读取本轮实施记录和 docs/dev/color-order-ui-game/04-acceptance-handoff.md。使用 ember-release-framework 技能检查并发布包含该模板的新 Ember 版本。

这次授权完成相关发布准备、必要的版本与依赖声明更新、项目中心要求的正式模板操作、只包含本次发布范围的提交、推送和不可变版本 tag 发布。先读取当前发布规则及实际已有版本，由真实变化确定合法的新版本，不复用旧 tag，不提交其他任务的无关改动，不为已明确授权的步骤重复询问。

核对实际内容、父模板兼容、hash、已完成验证与待验证项。若需要全量或长时间测试，按公共规则单独说明具体范围。发布后核对远端 tag 对应的 commit 和包内容确实包含 ui-game，提供新项目可用的安装来源、模板版本/hash、正式说明入口和交接单。没有执行过消费项目部署时明确标为待验证，不拿开发工程通过代替。
```

先把本目录整体放到新工程 `Docs/ColorOrder/Planning/`，附上阶段一的真实交接单。使用此段前在新工程目录建立对话；若工程未创建，先给出目标路径与项目名。

```text
请在当前新 Unity 项目实现《有趣的色彩顺序》。阅读 Docs/ColorOrder/Planning/README.md、01-product-rules.md、03-consumer-project.md、04-acceptance-handoff.md，以及附上的框架模板交接单。

玩法基线已经确定为 V2：错误保留进度、单/双目标、固定格位奖励星、一次定格、按步骤计分；V1.1 只继承未被覆盖的基础约束。先完成 B0 三个短关，九关、巡游、广告、排行与平台 SDK 不包含在本次实现范围。

核对当前目录确为目标新项目和 Unity MCP 实例。按交接单安装实际包含 ui-game 的框架版本，通过项目中心直接部署该派生模板并先跑中性 Demo；此指令授权目标新项目的首次安装和部署。若工程已有内容，先保护并检查覆盖差异。不要先部署 base，不改 PackageCache，不拿旧 0.21.4 当作新模板的交付版本。缺少真实交付信息时先从已附记录查找，确实缺失再说明阻塞项。

按 03 的 B0 批次实现 ColorOrder 模块、纯规则模型、配置和校验、三个给定原型夹具、正式 EUI 页面与 Item、暂停与返回、幂等计分、本地进度和恢复练习。所有正式 UI 使用 ember-eui-build / EUI 开发中心，并以实际生成 Binding 编写用户逻辑；替换或关闭模板 Demo，不能两套玩法并行抢输入。

落实 01 的补充约定，尤其双目标合法块数量、点击前格位收星、定格跳过仍推进效果槽、末步不执行机关、全关共享一次定格仍能全星通关、失败/练习不解锁、强退恢复仅练习。若源码接口与方案不一致，核对实际已安装 API，修改设计记录后继续，不自行编造调用。

通过当前项目 Unity MCP 主动请求本轮编译并核对域重载，再运行新增/相关用例和 Play 验证。交付三短关可玩的入口、真实结果与未覆盖设备、04 的产品交接单，以及给人工试玩的最短操作说明。真人体验尚未发生时直接标待试玩，不虚构反馈。暂不提交、推送或发布项目，除非本对话另有授权。
```
