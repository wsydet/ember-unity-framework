## 两部分如何划分

| 归属 | 本次计划内容 | 不包含的产品内容 |
| --- | --- | --- |
| 框架公共包 `com.ember` | 优先复用已有 EUI、模块生命周期、SceneFlow、输入、音频、存储等；仅在真实公共缺口出现时增加通用能力 | 色彩关卡、评分公式、星星格、墨团等具体玩法 |
| 新玩法模板 `ui-game`，正式父模板 `base` | UI 游戏公共接线、最小可运行示例、扩展说明；作为模板随包交付 | 九宫格规则、九关配置、美术主题、巡游、广告和排行 |
| 新消费项目，工作代号 `ColorOrder` | `ColorOrder` 业务模块、EUI 页面与 Item、规则及机关、关卡配置、正式成绩与恢复策略 | 对 PackageCache 的临时修补、私自改模板快照 |

`ui-game` 和 `ColorOrder` 是本包建议的技术名称，开工时检查重名后确定。模板是可部署的 Assets 装配，不是新 UPM 包，也不是单个 UI Prefab。

## 文件的长期归属

本目录保存决策与实施交接。阶段一形成的正式模板使用说明，必须维护在活动模板的 `Assets/Game/Documentation/ui-game/`，经项目中心保存分发。阶段二将产品规则、配置说明、验证记录放在新项目自有 `Docs/ColorOrder/` 或项目既有产品文档目录；不要放入框架包、base 或通用 UI 模板。

新项目可以把本目录整体复制到自己的 `Docs/ColorOrder/Planning/`。执行阶段二只需本包、已部署模板说明和实际安装包的公共规则；不依赖本机桌面路径。仓库源码链接仅供阶段一核对，消费端按实际解析位置查同名 API。
