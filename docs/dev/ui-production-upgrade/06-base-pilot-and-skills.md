# 阶段 S6 完成 base 换肤试点与 AI 工作流

目标是使用 base 现有基础 UI，完整完成一次占位功能到美术 UI 的替换，并将经过验证的工具组合成其他项目可调用的 AI 工作流。前置为 S0 至 S5 的必要能力已可用。

本阶段既验资源制作，也验原有功能保持。真实 PSD 缺失、Photoshop 未导出或 Unity 未运行时，各自保持待验证，不能用静态检查补填通过。

## 试点范围

| 对象 | 需要保留的功能 | 本轮验证内容 |
| --- | --- | --- |
| EUIMainPage | 开始游戏、打开设置，以及实际基线存在的其他行为 | 公共按钮、文本、页面区域、组件实例复用 |
| EUISettingPage | 按来源显示上下文、关闭返回、遮罩/输入行为 | Popup 骨架、状态、文字和适配 |
| EUIOptionRowItem 与其示例宿主 | 显示当前数据、刷新、清空、事件和释放 | 动态 Item、列表语义与实例回收 |
| Gameplay、Loading、GM | 原有流程 | 受影响回归，不默认重做美术或生命周期 |

资产路径采用 S1 完成的规范名，旧 Panel 来源通过[迁移表](contracts/ui-naming.md)定位，行为以 S0 现场基线为准。实际 UI 没有的音量、语言切换等功能不得凭“设置页通常都有”自动添加。

## 完整执行顺序

1. 固定本次工程、模板、工具版本、原 Prefab、绑定与行为基线。记录正在使用的确切 PSD 和导出规则。
2. 从 S2 的初版默认 UI 导出 EUI 契约，与美术资料一并形成交付包。使用外部美术稿，或按 S4 制作的真实分层试点稿，均需有默认与必要状态。
3. Rename 比较 PSD 与旧契约，列出结构变化、组件复用、状态和接口差异，保存工作 PSD。
4. UXP 导出真实 BUI 与 PNG，核对完整 Target 和资源清单。
5. Maker 分析并预览，依据页面范围选择原位更新或结构重建，保存正式资源并重新生成绑定。
6. 对照生成差异完成用户逻辑接线；原行为的实现方式有变化时记录原因与新入口。
7. 通过 MCP 编译、域重载与 Console，再执行有限的结构、视觉、交互、布局和生命周期验证。
8. 使用同一输入续跑一次，验证没有重复生成、覆盖用户代码或修改公共源；再做一次小美术修改验证增量路径。
9. 保存 base 维护源、正式使用说明和工具配置，经中心普通保存。记录未封存内容和派生影响，发布按 S7 处理。

不要为了演示流程，从已经有效的 BUI 强制重做全部上游。工作流应支持从 PSD、工作 PSD、BUI 或现有 Prefab 的适用阶段进入，但每个入口都核对本次实际输入。

## 验证方式

视觉对照使用相同画面尺寸、相同状态和固定示例数据。截图应来自已保存 Prefab 的实际渲染，不能只看制作窗口的临时对象。明显的裁切、漏层、错位、状态错误和文字不可读必须解决；字体渲染等合理差异记录接受范围，不虚构统一像素阈值。

动态验证至少包含长文本、禁用/选中状态、滚动和 Item 重用；适配覆盖两种实际比例和安全区。行为验证包含正式启动、主界面进入设置、关闭回到正确来源、进入玩法、从玩法进入设置后恢复。

反复打开关闭三次，核对事件与实例数，测试被遮挡页面不接收点击。对未覆盖的真机输入或构建单独记录，不把编辑器结果扩展为全部平台通过。

另外验证一次项目级皮肤替换：在独立的项目副本或测试资产上，将默认浅色风格的颜色、背景、图标或字体样式换成另一组明确视觉，保留规范名、Binding、状态和点击行为。默认库源保持不变，不为换肤增加一套专用逻辑。这个用例验证未来具体项目接入路径，不要求本轮先实现完整产品。

## AI 技能如何组织

先确认现有技能维护与发布清单，复用 ember-eui-build 的正式制作职责。只在新职责需要时增设技能，候选名称在实现时确定。

| 工作流职责 | 技能应做什么 | 工具负责什么 |
| --- | --- | --- |
| UI 资料准备 | 选择目标、读取行为和生成契约 | 真实资产导出、引用与差异检查 |
| PSD Rename | 解释设计、确定语义和复用关系、处理未决项 | PSD 工作副本操作、命名验证和保存 |
| UXP 导出 | 选择准确输入和支持能力，续接结果 | 原生切图、BUI 输出、资源清单 |
| EUI 制作 | 分析差异、调用正式工具、组织验证 | Prefab 创建、绑定、生成、预览和报告 |
| 业务接入 | 按旧功能与需求修改用户逻辑 | 现有生成器和运行框架提供接口 |

不要把完整业务写入 Maker，也不要把工具实现代码塞进长提示词。技能应要求读取当前工程、实际包和配置，不能硬编码开发机绝对路径或 Burner 的产品目录。

每个技能写明：支持的起点、必需输入、实际工具/API、产物、完成判定、断点续接、已知限制。公共技能按现有框架 AI Skill 机制分发；玩法专属技能留在模板维护源，不能混入公共清单。

创建或修改技能时使用技能创建规范，并按实际目录所有权维护源与发现副本。缺少某个自动化工具时提供明确的人工步骤和未完成状态，不能模拟回执。

## 必须留下的试点证据

记录源与工作 PSD、BUI/PNG、原/新 EUI 契约、制作计划和应用结果、生成差异、同状态截图、交互操作、编译及相关测试、base 保存结果。以实际路径引用大文件，不为文档复制多份重复 PSD。

行为清单逐项写通过、失败或未验证，关联实际操作。剩余问题区分工具缺口、素材问题、功能选择和环境限制，下一对话能直接接续。

## 进入 S7 的条件

F01 至 F07 通过；公共库能从正式配置恢复；主界面、设置和动态 Item 的换肤链路真实执行；原行为保持；AI 工作流与项目皮肤替换有实际调用证据。

未完成时保留已经有效的框架和资源成果，并明确 S7 依赖的剩余项。不要仅因技能文档写完就宣布换肤生产流程已完成。
