# 初版 UI 组件库默认视觉与素材制作

用户已选择以 macOS 界面风格作为初版方向，并允许在实施阶段生成图片供组件库使用。S2 应交付有统一视觉、状态完整、可实际操作的第一版 UI 库，供 base 和 ui-game 默认使用；具体游戏随后通过同一替换流程形成自己的版本。

采用 macOS 风格中的清晰层级、充足留白、圆角、细边线和克制配色。首版是适用于 Unity 游戏的中性浅色界面，设计值由本项目定义，不声称是 Apple 官方尺寸或系统组件。复杂实时背景模糊不作为首版前置条件，可用不透明表面和独立轻阴影表达层次。

## 默认皮肤与逻辑边界

默认视觉标识建议为 EmberDefaultLight，名称在 S2 查重后确定。Page、Item 和绑定名称保持功能语义，皮肤名仅用于素材和样式配置。组件不能因为从蓝色改成绿色就改变对外类型或事件。

颜色、字体槽位、圆角、间距、图像和状态样式作为可替换数据，优先使用已有字体皮肤、组件字段和 Editor 配置。首版不需要另建全局主题 Manager 或运行时任意换肤引擎。

## 建议视觉基线

以下是首版默认设计参数，可在实际截图对照后小幅修正并记录。单位为 1 倍设计尺度；按 S0 确认的 Canvas 参考分辨率统一换算，不能把值无条件当成所有屏幕的物理像素。

| 维度 | 首版建议 |
| --- | --- |
| 画布背景 | 浅灰白 #F5F5F7；可搭配轻微冷色渐变 |
| 卡片与弹窗表面 | #FFFFFF，次级表面 #ECEEF2 |
| 主文字与次级文字 | #1D1D1F 与 #62666D；用真实 TMP 文本 |
| 分隔与边线 | #D5D8DE，低对比且清楚，不用粗重描边 |
| 强调色 | 蓝色 #0A64E8，集中用于主动作、选中和焦点 |
| 间距 | 4 为基本单位，主要使用 8、12、16、24、32 |
| 圆角 | 控件 8，卡片 12，弹窗 16，按组件尺寸协调 |
| 字号层级 | 辅助 12、正文 14/16、区域标题 20、页面标题 28 |
| 控件高度 | 桌面紧凑项约 36，主要按钮与触摸交互区约 44 起，按目标平台核对 |
| 阴影 | 一套轻阴影，独立于内容和点击区；缩放后不模糊污染边缘 |

这些色值和尺寸是项目起点。必须在实际文字、禁用、焦点、不同分辨率与输入设备下检查可读性和可操作性，不能用填了参数表代替验收。

字体优先复用项目已有且可分发的字体与 TMP 字体皮肤。没有必要为视觉相似强行引入某个系统专用字体。桌面悬停可以补充反馈，触摸用户必须只靠默认/按下/选中状态也能操作。

## 首版组件和状态

| 组件 | 至少交付 |
| --- | --- |
| 标准 Page | 背景、标题、内容区域与留白示例 |
| 标准 Popup Page | 卡片、标题、关闭按钮、遮罩与内容区域 |
| ActionButton | 主/次按钮，默认、按下、禁用、必要键盘焦点 |
| ChoiceToggle 与页签 | 未选中、选中、禁用，图形状态不只依赖颜色 |
| Progress | 底槽、填充、可选数值，0 和满值表现 |
| Scroll/列表 | 背景、分隔、实际滚动区和中性 OptionRowItem |
| Item 与空态 | 图标、标题、选中/禁用样式，以及一份空列表展示 |

功能控件与状态由 Unity 组件实现。不要把整张界面图当作按钮或列表，也不要生成一张含文字的整页图片冒充可编辑 UI。

## 哪些素材生成 哪些保留参数化

| 素材 | 默认制作方式 | 原因与验收 |
| --- | --- | --- |
| 圆角按钮、卡片、分隔、填充 | 原生几何、现有可伸缩组件或准确九宫格素材 | 边界、尺寸和状态可控，支持多语言和缩放 |
| 简单箭头、关闭、勾选等图标 | 复用可分发资源或确定性的统一图形；缺合适资源时可生成 | 同一线宽、视觉尺寸和对齐，不引入混杂图标风格 |
| 默认背景图 | 使用 imagegen 生成一份低干扰的浅色抽象背景 | 正式可用图片，检查安全内容区与裁切 |
| 空状态插画 | 使用 imagegen 生成一份中性的小插画 | 透明背景，独立文本，作为空列表或示例素材 |
| 特殊纹理或装饰 | 确有用途时按同一风格生成 | 不影响动态内容、可伸缩边框和点击区 |

首版默认至少制作一张实际背景图和一张空态插画，完成检查与项目导入，不能只留下生成提示词或几何占位。已有完全适用资源可明确复用并记录；工具暂不可用时保留必要待办，不因此阻止独立的 Prefab 和状态制作。

生成的图标/九宫格底图若边缘不精确，继续调整或改用确定性资产，不把漂移的圆角、阴影或线宽固定进全库。图片生成擅长提供外观素材；精确布局和行为仍由编辑器制作。

## S2 素材制作步骤

1. 先制作一个小型风格板，展示 Page 表面、Popup、主次按钮、Toggle、文字、列表与状态；输出为参考图或可操作预览，不作为运行时整图。
2. 固定上述视觉基线、字体和图片清单。用户已经选定 macOS 风格，常规素材制作可直接推进；不增加每张图都要先确认的流程。
3. 真正生成图片时使用 imagegen 技能与内置图片工具。新建图像和编辑已有图像分别处理；编辑本地图先查看原图。需要透明背景时明确请求真实 alpha，不能用棋盘格冒充透明。
4. 检查每张结果的构图、边缘、透明度、图标风格与是否意外包含文字。必要时针对单一问题迭代，并保留最终采用的提示词和版本。
5. 将最终资产复制到项目受管资源目录。普通公共 Sprite 可放 Common/Atlas/DefaultLight；大背景按实际加载方案放 Common 下对应图片类别，不能因为都是 PNG 就全入同一图集。
6. 正确设置 Sprite/Texture、尺寸、Pixels Per Unit、过滤、压缩、九宫格 border 和图集归属。具体参数依据实际输出像素与项目平台验证，不声称生成工具保证准确像素或天然满足九宫格。
7. 通过 EUI 中心搭建组件并连接实际图片、字体、slots 和状态，展示在组件库预览中。不得让正式资源仅引用个人生成图片缓存或本机绝对路径。
8. 保存素材来源清单与可编辑结构，经项目中心普通保存进入 base。S2 交付截图与可运行预览，S3 再完成动态容器行为。

## 可直接使用的生成提示词

背景图提示词示例，实际输出尺寸应在生成后检查与导入：

~~~text
用途：Unity 通用 UI 组件库的默认背景素材。
生成 macOS 风格启发的中性浅色抽象背景，以灰白和很淡的冷蓝色为主，少量柔和层次，中心区域安静、低对比，适合叠放原生 UI 卡片和动态文字。
只生成背景，不要按钮、窗口截图、界面文字、品牌标识或设备边框。正视平面构图，无透视。背景不透明，四周裁切后仍协调。
~~~

空态插画提示词示例：

~~~text
用途：Unity 浅色默认 UI 的空列表插画，作为独立 Sprite。
画一个小型、居中的抽象卡片与收纳托盘组合，圆角几何、克制的灰白色和少量蓝色，清楚的外轮廓，风格与轻量 macOS 风格界面协调。
不包含任何文字、数字、按钮、品牌标识或背景面板。四周留出透明边距，主体不被裁切。需要真实透明背景，不要把棋盘格画进图像。
~~~

## 素材记录与初版 PSD

每张正式图片记录资源 ID、生成/复用来源、提示词、实际尺寸、alpha、导入设置、归属、使用组件和槽位。稳定资源 ID 与业务绑定分离，换一张图不应改变事件接口。

S2 可以先用生成图片和原生控件完成初版，不需要等待外部美术 PSD。S4 若没有外部设计稿，默认在 Photoshop 使用这些素材、EUI 契约和可编辑文本制作一份真实分层试点 PSD，作为 Rename/UXP 的输入。图片生成结果不是分层 PSD，不能通过改扩展名或把整页压成一个图层代替。

试点 PSD 可以由现有初版布局出发，改变一组明确的样式和局部布局，验证替换有效；它是流程测试素材，不是对外部美术已交稿的声明。

## 具体项目如何替换

消费项目继承一份能用的默认 UI。替换时保留 Page/Item 的规范名、语义 ID、绑定、事件、状态与公开槽位，在项目自己的素材和皮肤范围更新颜色、字体、图标、背景与允许的布局。

项目通常已拥有部署到 Assets 的副本，可在正式替换流程中修改自己的副本或创建适合本项目的 Variant；不得改框架 PackageCache 或其他项目的共享源。真正的接口变化交由映射与逻辑迁移处理。

验收至少证明一个样例可以从默认浅色风格换为另一组项目视觉，并保持相同绑定和交互。重新部署能得到默认库，已经换肤的项目通过升级合并保留自己的修改，不能默认被框架升级覆盖。
