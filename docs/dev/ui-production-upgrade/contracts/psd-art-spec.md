# Ember UI 美术 PSD 交付规范

本规范面向为现有 UI 提供美术设计的美术和 TA。程序侧会提供页面截图、交互与状态清单、组件参考和画布要求；美术按这些信息设计，交付后由 Rename 和 UXP 工具生成制作输入。

适用于 base 练习和后续游戏项目。游戏项目可以补充风格要求，不能省略组件、状态与动态内容的结构信息。美术无需填写 C# 类名、Unity GUID 或工具内部请求字段。

初版 base 按[默认视觉与素材规范](default-skin.md)提供 macOS 风格浅色组件。游戏项目可提供自己的视觉，继续沿用同一语义、状态和绑定契约。页面正式资产统一使用 Page；PSD 的 Popup 标签描述设计目标类型，不要求把程序页面改名为 Popup。

## 开始设计前接收的资料

- 页面用途、打开和关闭方式，以及需要保留的按钮和状态。
- 当前 UI 的默认截图，以及选中、禁用、空列表、长文本等必要补充状态。
- 画布宽高、设计参考分辨率、屏幕方向和目标比例范围；这些值按项目明确填写，不统一写死为 1080×1920。
- 可复用组件的预览和使用说明，包括按钮、页签、进度条、Item 等。
- 动态文字、图标、数值和列表的范围；需要保留的文案键或变量由程序侧提供。
- 本次允许改动的范围：仅外观、局部布局或整页重设计。

未说明的功能变化在交付说明中单列。例如新增领取按钮或删除返回入口，不应只体现在图片中。

每次给美术的页面资料可直接使用下面的清单，由程序或 TA 从当前工程填写：

~~~text
项目与模块：
页面名称与用途：
参考画布宽高、屏幕方向、目标比例：
安全内容区、背景铺满要求、弹窗或子页宿主区域：
必须保留的入口与关闭返回方式：
允许变化的功能与布局范围：
可复用组件及预览：
各组件必须提供的状态：
动态文本、本地化文本、最长样例：
动态图片与 Item 数据范围：
九宫格和特殊切图要求：
字体与文字效果：
源 PSD、预览和交付说明的目录：
本次版本、负责人和未决项：
~~~

## 文件和画布

1. 保留可编辑源 PSD，文件名表达项目、模块、页面和设计版本。交付目录包含 PSD、预览图及说明。
2. 每次交付保留可辨认版本，不用“最终最终版”覆盖唯一历史。至少写明日期、页面和本次变化。
3. 页面按已约定画布设计。弹窗应保留弹窗在页面中的位置和遮罩说明；子页需说明其在宿主页面中的位置与大小。
4. 透明像素可保留，但不要靠不可见的大面积图层暗中决定控件尺寸。控件设计框与实际可见图像边界可以不同，应有明确来源。
5. 外链智能对象、链接图片和字体需一并提供可用来源，或在副本中完成可重现的处理；不要让切图依赖美术电脑上的独有路径。
6. 工作色彩空间、透明度和导出策略保持一致，试点以实际 Photoshop 与 Unity 对照结果确定，不通过猜测色值补偿处理明显差异。

## 图层组织

页面、弹窗、独立子页、可复用组件和重复 Item 应有清楚的组边界。背景与内容分组，固定顶部/底部与可滚动内容分组；隐藏状态不能混进无用途的杂项组。

下面是美术可读结构示例，不是要求艺术家手写最终导出命令：

~~~text
主界面
  背景
  顶部
    标题
  主体
    开始按钮
      普通状态
        背景
        标题文字
      禁用状态
        背景
        标题文字
    示例列表
      选项行模板
        图标
        名称
        状态标识
  底部
    设置按钮

设置弹窗
  背景遮罩参考
  弹窗内容
    标题
    关闭按钮
    选项区域
~~~

同一组件实例内部的槽位名称和结构应保持一致。相同按钮换了文案或颜色仍可属于同一组件；布局和行为明显不同的控件应在交付说明中区分。

## 标准化命名由工具完成

美术原稿允许使用清楚的中文语义名称。Rename 根据已导出的 EUI 契约和组件库，将工作副本转为当前导出器支持的命名。

目标组可沿用已验证的类别约定，例如 @Page_UIBase_Main、@Popup_UIBase_Settings、@Component_UIBase_ActionButton、@ListItem_UIBase_OptionRow。这里的 Base 是示例模块标识，实际项目按自己的模块填写。

正式标签语法以 S4 选定版本的命名规则文件为准。@PrefabRef、布局区、资源复用或九宫格的参数不得凭示例猜写；工具必须验证当前导出器确实支持。若决定改变语法，命名规则、UXP 解析器、BUI 消费器和本规范一起更新。

程序绑定名称通过映射保持稳定，美术文案不直接成为代码字段名。Rename 保留源 PSD，使用明确的工作副本，不能静默覆盖原稿。

旧页面名称中出现 Panel 时，通过[迁移表](ui-naming.md)对应到 S1 的 Page 名称；PSD 与引用说明采用规范名或明确旧名映射，不重新引入第二套有效页面身份。

## 按钮和状态

| 控件 | 至少交代的信息 |
| --- | --- |
| 普通按钮 | 背景、标题、可选图标，普通与禁用外观；按下反馈采用图片还是程序效果 |
| Toggle 或页签 | 未选中、选中、禁用；选中标识的独立图层 |
| 进度条 | 底槽、填充、边框；填充方向，数值是否动态 |
| 弹窗 | 内容框、标题、关闭入口、遮罩样式；点击遮罩是否关闭由功能说明决定 |
| 列表 Item | 单项结构、选中/不可用状态、图标和文字槽位、可变尺寸范围 |

状态可以放在隐藏组中，但必须标注用途。默认隐藏不等于无用图层，导出流程需要能够发现它。未提供的状态可明确沿用程序 Tint 或缩放等现有反馈，不能在制作时擅自猜一套行为。

“禁用外观”与“禁止点击”分别由视觉与交互规则保证，不能仅靠变灰代表已经禁止交互。

## 文本规范

- 动态文本、本地化文本和需要换文案的按钮标题保留为文本层，避免合并进背景。
- 提供字体名称、字重、字号、行距、字距、描边/阴影和对齐方式；字体文件的实际使用条件由项目确认。
- 标出固定宽高、自动换行、缩放、截断或滚动要求。对长文本给出示例，不能只设计最短标题。
- 数值、计时和数量使用有代表性的样本，例如 0、9999 和最长预计格式，真实数据由程序提供。
- 同一文本的普通/禁用/选中外观要清楚区分，但内容与本地化键保持同一含义。
- 纯装饰字可以按图像处理，但需明确标为装饰，不再承担可变内容。

PSD 的文字像素效果不一定等于 TMP 的直接表现。无法准确还原的效果需要明确选择可接受的文本样式或装饰图像，不能把所有文字直接切成图解决。

## 切图与九宫格

| 内容 | 处理要求 |
| --- | --- |
| 单独图标 | 独立、透明背景，保留必要边缘与阴影 |
| 可伸缩背景/边框 | 标明固定角和可拉伸区域，九宫格边界以最终导出的像素确认 |
| 多层形成一个视觉元素 | 明确合成边界，合成不得跨越独立点击区、动态文本或状态切换边界 |
| 大背景 | 明确填充/裁切/保持比例策略，不能仅按控件类型自动放入图集 |
| 动态图像 | 说明内容变化来源，例如头像或商品图；不是所有切换状态的 Sprite 都算动态纹理 |
| 公共素材 | 指明复用意图，由工具核对项目真实资源；同名或看起来相似不等于同一资产 |

固定图素、公共图集、组件私有图片与动态加载图片分别归类。组件内部私图默认随组件复用，不能擅自提升为所有页面共享资源。实际打包上限、压缩、过滤和导入设置按项目平台配置，不照搬 Burner 的固定阈值。

九宫格信息须能回到真实 Sprite border。注明单位和方向；导出缩放后重新核验。阴影、发光超出设计框时，导出器必须保留正确图像偏移，不能用裁切后的 PNG 大小覆盖原控件设计框。

## 列表与子页

重复内容明确给出一份 Item 模板及若干数据样例，不把十个长得相同的 Item 做成一张整图。指出排列方向、间距、滚动区域、固定元素和内容增减后的期望。

嵌入页面的子页应标记宿主区域；隐藏页签也属于交付内容。局部滚动和裁切由程序组件实现，PSD 中超出 viewport 的部分要能被正确识别，而不是直接丢掉。

## 交付清单

- [ ] 源 PSD 可打开，外部依赖和字体信息完整。
- [ ] 默认与必要状态的预览图齐全，注明尺寸和页面。
- [ ] 页面、弹窗、组件和 Item 分组清晰。
- [ ] 动态文本和图标未被错误合成。
- [ ] 长文本、空列表、禁用等状态有设计或明确沿用说明。
- [ ] 九宫格、合成边界、复用素材和大背景策略已标明。
- [ ] 新增、删除或改变含义的交互独立列出。
- [ ] 本次版本与变化清单明确。

程序与工具验收还会检查 Binding、资源身份和运行行为，不要求美术手工填写这些工程字段。

## 工作副本与导出结果

尚无外部美术稿时，S4 可在 Photoshop 用 S2 已生成并检查的图片、组件布局和真实文本制作分层试点 PSD。至少保留独立页面组、组件/Item 组、动态文本和状态图层；单张整页效果图或仅改扩展名的 PNG 不符合本规范。

Rename 完成后交付工作 PSD、命名映射和未解决项；UXP 完成后交付实际 BUI、所有被引用 PNG、设计预览及导出结果。源 PSD、工作 PSD、BUI 和 PNG 的版本关系应可确认。

不能以“已生成 BUI”代表切图完整，也不能以“图像相似”代表功能保持。两者分别进入[换肤试点验收](../06-base-pilot-and-skills.md)。
