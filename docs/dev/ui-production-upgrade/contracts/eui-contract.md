# EUI 信息与交换契约

本规范定义 AI 制作和替换 UI 所需的工程信息。S1 先实现读取、验证和差异输出，S2 补公共库描述，S5 据此执行制作。字段模型属于实施目标，最终类型名和序列化形式需记录在交接中。

这里的 EUI 文件包括 Prefab、EUIBinding、生成绑定、用户逻辑、页面注册和库配置，不预设项目已存在独立的 .eui 文件格式。建议工具从这些真实来源导出 .eui.contract.json，供 AI、Rename 和 Maker 读取；它是生成的描述文件，运行时仍使用现有 EUI。

正式命名遵循[Page 命名与迁移规范](ui-naming.md)：S1 将现有页面 Panel 名称迁移为 Page。契约保存规范名、稳定身份和必要旧名映射；文件名变化不能被误判为删除一个功能再新增一个功能。

## 信息的唯一来源

| 信息 | 权威来源 | 导出规则 |
| --- | --- | --- |
| 组件、层级、RectTransform、序列化引用 | 已保存 Prefab 与真实嵌套关系 | 导出实际状态，不把设计稿猜测写成工程事实 |
| 绑定名、类型、Page/Item、生成模式 | EUIBinding 和公开编辑器 API | 保留已有框架标记与继承关系 |
| 实际生成字段 | 当前生成文件和 ControlMap | 与 Binding 核对，不手工修改生成文件补差异 |
| 公共组件类别、槽位、允许覆盖范围 | S2 的库配置资产 | 配置引用真实 Unity 对象，导出目录由工具生成 |
| 点击后做什么、变量从哪里来 | 用户逻辑、接入代码和人工确认的行为说明 | 静态可确认、实测、待确认分开记录；未知不能填默认行为 |
| 字体、图片、材质、动画来源 | 实际资源引用及字体/资源配置 | 缺失、动态加载和无法解析的引用显式报出 |
| 新旧对象映射 | 本次分析产生并核对的映射表 | 保存输入版本；资产变化后重新校验 |

不要让用户手工同时维护 Prefab、Binding 和一份完整结构 JSON。必要的语义补充只登记一次，例如组件家族、槽位含义和行为说明；工具组合它们与资产事实生成最终描述。

## 描述文件最低信息

| 分组 | 必填信息 | 用途 |
| --- | --- | --- |
| 格式和输入版本 | schemaVersion、导出工具版本、源资产摘要、生成时间 | 确认消费者可读、计划仍匹配当前输入 |
| 页面身份 | 工程相对路径、Prefab GUID、逻辑类、PageName、PageType、Page/Item 角色、代码模式 | 确认编辑的准确对象和生成边界 |
| 继承和嵌套 | Prefab Variant 来源、Binding 基类 GUID、嵌套实例来源与覆盖 | 分别校验资源继承和代码绑定继承 |
| 设计环境 | 参考分辨率、Canvas 模式、缩放策略、安全区和承载区域 | 解释 PSD 坐标及运行适配 |
| 控件接口 | 稳定语义 ID、绑定名、组件类型、所属组件、当前对象定位 | 保护程序可见接口 |
| 公共库信息 | family、库条目 ID、Prefab 引用、槽位定义、允许覆盖属性 | 驱动准确复用 |
| 当前皮肤 | 样式/皮肤标识、真实图片和字体来源、颜色与尺寸配置、允许替换属性 | 支持初版默认库被项目视觉替换，不改变逻辑身份 |
| 状态 | 默认、选中、禁用等状态及其真实控制方式 | 防止只迁移默认画面 |
| 文本 | 静态/本地化/动态、键或提供方说明、字体槽位、字号、布局边界 | 避免把程序文本烘焙成图片 |
| 资源 | GUID/子资产身份、类型、所属模块、图集/静态/动态用途、九宫格、材质 | 资源导入和复用 |
| 行为 | 事件、导航目标、数据输入、显示关闭条件、生命周期所有者 | 提供旧功能迁移依据 |
| 检查结果 | 缺绑定、重复 ID、空槽、未识别类型、待确认行为 | 明确哪些阻止应用、哪些允许继续 |

工具只应对当前实际使用的语义要求必填。一个无交互装饰 Image 不需要虚构点击行为；一个未使用本地化的项目不需要虚构文本键。

## 稳定身份与对象定位

稳定语义 ID 表示职责，例如 main.start、settings.close、option.title；绑定名保持既有生成约定，例如 Btn_Start。二者可以不同，映射必须明确。不要因美术把“开始”改成“出发”就自动改逻辑绑定名。

定位信息包含实际资产 GUID 与可用的对象标识，层级路径作为诊断和回退提示。节点重排可能改变路径；重建 Prefab 可能改变 GUID 或 local file ID。工具必须对新对象重新解析并保存明确映射，不能把旧路径字符串当作永远有效的身份。

同一个公共组件的多个实例共享组件定义，但实例身份不同。例如 main.start 和 main.settings 都可使用 ActionButton；组件内部 title 槽位一致，页面实例 ID 不同。

实例被复制时应生成新的实例身份。重复 ID 为阻断项。删除再建立的节点不能仅凭同名自动继承旧对象身份。

## Page 和 Item 的所有权

| 用法 | 创建和生命周期 | 父级绑定方式 |
| --- | --- | --- |
| 主页面与弹窗 | 按现有 EUIManager、状态流程和 PageType 管理 | 页面正式注册 |
| 固定嵌套组件 | 父逻辑通过嵌套 Binding 创建和持有子逻辑 | UILogic，由生成器与 Bridge 处理 |
| 动态或池化 Item | 宿主实例化，EUIItemFactory 包装，宿主管理回收/销毁 | 绑定宿主或 Extension/RectTransform，避免重复创建子逻辑 |
| 局部子页 | 先明确按已有 SubPage 还是宿主持有 Item 实现 | 依据生命周期决定，不按 PSD 名称直接决定 |

同一个嵌套对象只允许一种逻辑创建路径。禁止父级 UILogic 自动构造后，又调用 EUIItemFactory 再构造一份。

已有 EUIItem 的 BeginUse、Show、Hide、ResetForPool、Dispose 应分别保留含义。Dispose 不销毁 GameObject；宿主负责实例归还或销毁。对象池和容器必须记录自己拥有的资源与回调。

## 槽位与可修改范围

每个可复用组件声明其公开槽位，建议包含以下内容：槽位 ID、语义、目标组件引用、必要性、状态、支持的属性修改、尺寸约束。例：title 接受 TMP 文本样式；icon 接受 Sprite；background 接受九宫格 Sprite。

应分开处理：

- 内容覆盖：文本、图标、颜色等本实例数据。
- 外观覆盖：允许的字体、背景、边框与状态图。
- 布局覆盖：根尺寸、位置、可配置内边距和插入区域。
- 结构变化：增加/删除内部节点、改变接口或事件源，需要重新分析契约。

普通页面换肤只修改嵌套实例允许的覆盖，不 Apply 到公共源。公共组件升级是独立范围，需要列出所有受影响实例并执行相关回归。

默认库采用[初版皮肤规范](default-skin.md)。更换背景、图标或主题色通常属于允许的外观差异；新增事件、删除状态、变更组件类型仍属于接口变化。皮肤标识不拼进绑定名和 Page/Item 类名。

## 状态和布局信息

状态声明需说明驱动源，例如 Toggle.isOn、Selectable.interactable、业务数据或页面生命周期。艺术图层可提供 Normal、Selected、Disabled 外观，但不能自行改变驱动逻辑。

区域声明至少覆盖背景、安全内容、顶部、主体、底部、弹窗内容和滚动 viewport；实际项目只使用需要的区域。保留 Ember SafeArea 的实际节点体系，导入器负责语义映射，不强制改成 Burner 的固定层级。

弹窗和子页应记录承载矩形。子页按宿主分配区域适配，不能把整个屏幕安全区重复套入。PNG 透明裁切边界只表示像素内容，不能替代控件设计尺寸。

文字样本至少包含默认、长文本和运行变量形式。字号、描边等外观可以替换；本地化键、变量占位符和数据显示责任需要保留。

## 差异分类和处理

| 差异 | 默认处理 |
| --- | --- |
| Sprite、颜色、字体样式改变 | 在允许槽位中更新并视觉验证 |
| 节点重排，绑定名与类型不变 | 明确重绑定目标，检查布局、动画路径和序列化引用 |
| 新增纯装饰节点 | 允许，不自动生成业务绑定 |
| 新增交互控件 | 生成接口差异和待接入事件，不能编造业务 |
| 删除或改名已有绑定 | 阻止自动替换，提出映射/兼容或明确删除方案 |
| Button 改成 Toggle 等类型变化 | 视为接口变化，需要代码接入和相关行为验收 |
| 更换 Prefab 身份 | 列出静态与动态消费者，完成引用迁移 |
| 未找到精确公共组件 | 保持未解析，或按明确选择创建局部组件，不静默使用相似项 |

分析后输入 Prefab、PSD、BUI、PNG 或配置发生变化时，应用必须重新核对受影响计划。不能以旧的成功分析报告覆盖新内容。

## 建议导出示例

以下仅说明信息关系，不是当前存在的 C# 类型或工具请求；路径示例采用 S1 迁移后的 Page 名称，旧名通过迁移表定位。实现时优先复用现有模型，避免把路径、引用与文本事实复制成多套权威数据。

~~~json
{
  "schemaVersion": 1,
  "source": {
    "prefabPath": "Assets/GameResource/Resources/UI/Common/Prefabs/EUIMainPage.prefab",
    "prefabGuid": "由真实资产读取",
    "assetDigest": "由导出器计算"
  },
  "role": "Page",
  "pageType": "MainPage",
  "bindings": [
    {
      "semanticId": "main.start",
      "bindingName": "Btn_Start",
      "componentType": "从真实 Binding 读取",
      "owner": "main",
      "behavior": {
        "event": "click",
        "meaning": "经已有状态流程进入玩法",
        "evidence": "对应用户逻辑或生成模板的实际位置"
      }
    }
  ],
  "unresolved": []
}
~~~

真实文件禁止保留“由真实资产读取”等占位值。缺失值进入 unresolved 并说明影响，不伪造 GUID 或摘要。

## 编码和版本约定

交换文件使用 UTF-8，保留中文；资产路径使用项目相对路径与正斜杠。Unity GUID 与大整数 local file ID 按字符串保存，避免 JSON 数值精度损失。绝对工作目录只作为本次任务定位，不进入运行资源加载路径。

读取方识别 schemaVersion 和所需能力，不支持的关键语义明确拒绝。扩展字段可以保留，但不得忽略关系型字段后继续生成貌似成功的页面。

生成契约不修改资产；验证和预览阶段不产生制作副作用。应用记录保存输入身份、操作列表、实际写入资产、生成结果、验证状态和部分失败，供新对话准确续接。

## 验收

两个不同执行对话读取同一已保存 Prefab 应获得相同的核心结构与绑定信息；生成时间等非业务字段可不同。修改文字外观只产生外观差异，删除绑定必须产生接口差异。已存在框架标记、嵌套所有权和代码模式不得在导出/重新生成中丢失。
