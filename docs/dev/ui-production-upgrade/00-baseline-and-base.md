# 阶段 S0 核对现状并切换 base

本阶段在 Ember 框架开发仓库执行。结束时应已保护原编辑内容，通过项目中心加载 base，并确定后续练习页面和真实行为。用户已明确允许这次切换；不因原来活动模板为 platformer-2d 而重复申请同一选择。

## 输入和读取顺序

先读[总览](README.md)、[统一验收](08-acceptance.md)、[交接记录](10-progress.md)与仓库公共规则。编写 C# 前还需完整阅读编码规范和 API 速查；操作 Unity 前读取 Unity MCP 技能及实际测试规范。

读取项目版本、实际包来源、Git 状态、项目中心正式编辑身份及模板列表。检查是否已有本任务工作，若已经在 base，先核对加载结果并补齐缺少的 S0 证据，不为重做清单重复加载覆盖。完整记录由实际执行者补充。

## 先保护当前编辑内容

1. 保存完整 Git 状态，分清任务前已有修改和本任务修改；未跟踪文件也进入保护清单。
2. 查看 Unity 当前场景、Prefab 编辑状态、未保存草稿及相关窗口状态。需保留的内存内容先保存到其正确归属；不把不明内容自动保存成新模板版本。
3. 记录五个受管根：Assets/Game、Assets/Resources、Assets/Ember/Editor、Assets/Settings、Assets/GameResource。它们会受模板加载影响。
4. 使用项目中心已有草稿保护能力；若不能覆盖当前所有差异，另做可恢复文件备份，包含 .meta、删除清单、未跟踪文件及必要编辑身份信息。备份位置应在五个受管根之外，记录实际绝对路径、内容清单和恢复方法。
5. 原模板已经存在的未保存修改保留为原模板草稿，不能误收进 base。框架 Package 中的字体等修改也不能因切模板被重置或被算成本阶段成果。
6. 不用 git reset、clean、未经核对的 stash 或整目录覆盖作为保护办法。备份须检查实际可读内容；记录文件不能代替备份本身。

编制时 Git 已有四个字体 SDF 资产和 slnx 的修改。执行时以新状态为准，不把这个列表当固定白名单。

## 正式加载 base

1. 确认当前是 embedded 框架开发工程，Unity MCP 指向同一工程。
2. 打开 Ember 项目中心的模板开发入口，选择 base，执行正式加载操作。使用工具支持的实际接口或窗口，不伪造编辑身份文件。
3. 读取正式编辑记录，确认 templateId 为 base。选择模板树节点和磁盘存在 base 目录均不等于已加载。
4. 等待导入完成。加载若产生脚本改动，主动通过 MCP 请求编译并确认本轮域重载和 Console；按公共规范处理断连。
5. 运行正式启动入口，记录主界面、进入玩法、打开设置、关闭设置、返回的现状。原有缺陷分别记录，避免以后把旧问题误认为新改动引入。
6. 若加载失败，保存中心诊断与已发生的影响。通过正式恢复入口或已核验的备份恢复，不能直接改快照/hash 让工具显示正常。

本阶段只读取 base 快照作为比对。之后正式编辑的目标是加载到项目中的 Assets。

## 优先使用的练习页面

以下文件在编制时的 base 快照中存在；加载后重新核对实际路径、Binding、页面类型和行为。

表中 Panel 名称是迁移前事实。按[命名规范](contracts/ui-naming.md)建立旧名到 Page 新名的映射，S0 负责盘点，S1 完成实际迁移；S2 以后使用迁移后的名称。已有页面类型和行为不因改名而改变。

| 目标 | 编制时信息 | 用途 |
| --- | --- | --- |
| EUIMainPanel.prefab | Common/Prefabs；EUIMainPage；MainPage | 提取标准按钮、标题和页面区域；保留开始与设置入口 |
| EUISettingPanel.prefab | Common/Prefabs；EUISettingPage；FullScreenPopup | 弹窗骨架、关闭、背景遮罩、文字和可选设置 Item |
| EUIGamePlayPanel.prefab | Common/Prefabs；EUIGamePlayPage；MainPage | 受影响的回归对象，后期衔接模板玩法页 |
| EUILoadingPanel.prefab | Common/Prefabs；TopMost | 回归对象；本轮默认不重构加载遮幕协议 |
| EUISafeArea.prefab | 公共安全区结构 | 复用其实际定位能力，避免与 Burner 固定层级发生冲突 |
| GMPanel.prefab | FreePage，固定排序层 | 回归检查，默认不纳入首次换肤 |

设置页面目前通过 SettingsState 进入，关闭按钮调用游戏状态机 Pop；主界面通过状态机进入 Gameplay 或 Settings。该信息来自编制时源码，正式迁移必须再次读取，不能仅把关闭按钮接成隐藏 GameObject。

首次试点优先采用主界面和设置页。若没有现成可重复 Item，可在独立 UiFoundation 示例中提供中性选项行或展示列表，避免为展示容器而改变正式设置页的含义。

## 生成五份现场清单

在本目录的 evidence/S0 下记录实际产物，文件只在执行时创建，不预填通过状态。

| 清单 | 最低内容 |
| --- | --- |
| 工程和保护记录 | 工程路径、Unity/包/模板版本、Git 差异、备份路径、加载结果 |
| 能力盘点 | 有效源码、注释参考代码、可用 API、编辑器入口、相关测试、待验证项 |

| 行为基线 | 点击入口、状态机导航、可见/隐藏状态、关闭/返回、变量文本、运行更新和释放 |
| 组件提取候选 | 当前节点、重复范围、建议 family/slot、归属、预计影响、提取顺序 |

页面资产清单补充规范名、旧名、GUID、字符串加载路径、生成配置/模板和所有受影响引用。新建默认值也要检查，避免只改现有文件后再次生成 Panel。初版视觉按[默认皮肤规范](contracts/default-skin.md)准备字体、现有素材和待生成图片清单。

图片和基线截图需带页面、状态、实际分辨率和来源。不得只截图默认静态画面而遗漏禁用、遮罩、关闭等行为。

## 确认本轮默认技术选择

- 保留 Ember 的 EUI、EUILogic、EUIItem 和代码生成链，新增能力在原入口扩展。
- 公共库第一版采用显式组件引用与槽位映射；模糊匹配不自动写入。
- 配置默认值可随 base 部署；本地工具工作目录独立于运行资源。
- 页面和弹窗先建立骨架；SubPage 与轻量 Item 的生命周期在 S1 明确，不能从美术分组直接推导 PageType。
- 旧页面首次替换默认保留现有 Prefab 身份与行为；结构重建模式单独试验，按实际差异决定。
- 初版采用 macOS 风格的中性浅色视觉，S2 可生成背景、空态等图片并完成可运行组件；不等外部 PSD 到位才制作初版。
- 外部 PSD 尚未指定时，S4 默认使用 S2 素材与契约制作真实分层试点 PSD；记录实际制作工具和来源，不能将整张生成图当成 PSD。

上述为实施默认值，有现场证据表明不适用时调整并记录理由。普通内部实现选择无需逐项询问用户；目标页面、交互含义或输出范围变更才需要明确决定。
