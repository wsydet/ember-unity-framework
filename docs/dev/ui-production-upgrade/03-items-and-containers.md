# 阶段 S3 完善动态 Item 与容器

目标是让重复 UI 成为独立 Prefab，并在列表增减、刷新、关闭、回收和异步更新时保持正确。前置是 S1 的所有权契约与 S2 的公共 Item 资产。

先用 base 中性的 EUIOptionRowItem 示例验证，family 可记为 OptionRow，实际命名遵循 S1 规范。只有正式页面确有同类功能才接入基础页，避免给设置页增加没有实际意义的业务。

## 复用已有能力

EUIItemFactory 为已有 GameObject 建立 Item，不负责 Instantiate、Destroy 或资源句柄。EUIItem 已有 BeginUse、Show、Hide、ResetForPool 和 Dispose。新增容器组合这些能力，不另造第二套 Item 生命周期。

当前注释掉的 Burner UIContainer 与 GameUIContainer 是参考材料，不能直接整文件取消注释。它们的框架类型、资源加载、更新循环和引擎版本依赖均需逐项核对。

## 首版能力边界

| 必须完成 | 按试点需要增加 | 留给后续 |
| --- | --- | --- |
| 单一 Item 模板、数据刷新、增减、清空、销毁 | 小规模池化、多模板、页签切换 | 大规模虚拟列表、复杂异形布局 |
| 确定的事件解绑与异步代次保护 | 必要预加载和延迟创建 | 通用页面预加载体系重构 |
| 原生 ScrollRect 和 LayoutGroup 的正确接线 | 对外统一选择状态 | 所有 Burner 包装组件的逐一移植 |

如果原生组件加现有 Item 足以满足试点，先交付轻量容器。是否增加池化、虚拟化以实际列表规模和生命周期需求决定，不为三行列表强加复杂基础设施。

## 所有权与调用顺序

| 对象 | 责任方 |
| --- | --- |
| 资源加载句柄 | 容器或明确资源提供者，记录释放时机 |
| 实例 GameObject | 容器或对象池，单一持有者 |
| EUIItem 与子逻辑 | 持有该实例的容器，按现有 API 创建一次 |
| 每次使用的数据订阅、回调和取消源 | 当前 Item 使用周期 |
| 列表数据与业务规则 | 页面或业务模块，通用容器不理解产品数据 |

借用顺序为：取得实例与 Item → BeginUse → 写入本次数据和状态 → Show。Show 会在未 BeginUse 时补开一次使用，数据若提前写入可能被重置，必须核对调用顺序。

回收使用 ResetForPool；最终退出用 Dispose 后由拥有者销毁或释放实例。Hide 仅临时隐藏，不代表释放本次使用。容器销毁时不能只销毁节点而遗漏逻辑、事件和资源句柄。

## 实施步骤

1. 定义最小数据适配方式：模板提供、更新显示、绑定事件、结束使用。优先用现有泛型/接口与生命周期，候选 API 命名在实现时确定并记录。
2. 规定稳定数据 key 与显示 index 的差别。数据重排后点击应命中当前数据，不闭包捕获旧 index；重复 key 的行为明确拒绝或由业务显式处理。
3. 实现初始化、刷新、追加/删除或整体替换、清空和销毁。第一版允许明确的整表重建策略，但要记录成本和实例计数，不宣称已实现增量差分。
4. 如果加入池化，恢复文本、选中、禁用、进度、图片和事件状态。回收后的旧异步图片结果不得写入新的数据行，使用已有取消/代次机制或最小等效实现。
5. 通过 EUI 中心建立 EUIOptionRowItem Prefab 与用户逻辑，容器根绑定 Extension/实际类型。动态 Item 不同时走父级 UILogic 创建，并继承 S2 默认皮肤和完整状态。
6. 接入 ScrollRect、viewport、mask、content 和 LayoutGroup，测试长文本与动态高度。循环布局依赖和 ContentSizeFitter 冲突必须有具体诊断。
7. 页签确有需要时，明确首次创建、缓存、隐藏、释放策略及宿主矩形。每次切换只激活一个目标，隐藏子页不会继续接收不应处理的输入。
8. 将容器模板、Item 和数据绑定方式纳入 EUI 契约，使 S4/S5 能识别 List 与 PrefabRef，而不是把列表导入成一组静态图片。

## 最小验证数据

用同一容器执行 0、1、3、20 行的增减与清空；设置一条长文本、一条禁用项和不同图标。20 行仅为本试点操作规模，不是性能上限或性能承诺。

连续三次打开关闭页面；选择一行后重新排序；复用刚回收的行；模拟旧图片结果在回收后到达。记录当前实例数、逻辑创建数、点击回调次数和资源句柄的归还情况。

只运行当前新增或受影响用例。需要性能压力测试时先给出规模与预计耗时，按公共测试规范处理。

## 交付与验收

执行 D01 至 D05。提交真实容器 API、所有权表、Item Prefab、示例入口、相关测试与 Unity 结果。若池化或页签没有实现，说明是否因本试点无需使用，而不是标记为整体遗漏。

模板资产通过中心普通保存；记录 S4 所需的列表语义和 S5 所需的正式创建方式。高级控件候选留在后续清单，不影响已经达到范围的本阶段交付。
