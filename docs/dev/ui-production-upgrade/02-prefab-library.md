# 阶段 S2 建立公共 UI 预制体库

目标是在 base 中提供可编辑的中性基础 UI 库，并让 EUI 开发中心依据该库创建、嵌套和检查正式 UI。前置为 S1 的绑定边界与契约可用。

本阶段采用显式引用和可验证槽位，按[命名规范](contracts/ui-naming.md)使用 S1 已迁移的 Page 名称。必须交付一套能直接使用的 macOS 风格浅色默认组件库，视觉与素材步骤见[默认皮肤规范](contracts/default-skin.md)。消费项目可继续通过替换流程形成自己的主题。

## 第一批资产

下列名称是候选名称，实施前查重并根据现有命名统一。已有同职责资产优先扩展，不平行建立第二套。

| 类别 | 目标 | 最低职责 |
| --- | --- | --- |
| 页面骨架 | 通用 Page | 根布局、安全区、内容插入区域、过渡接线 |
| 弹窗骨架 | 通用 Popup | 内容区域、关闭入口、遮罩与输入阻断策略 |
| 局部容器骨架 | SubPage 或宿主 Item | 使用宿主矩形；运行角色按 S1 决定 |
| 按钮组件 | ActionButton | 背景、标题、可选图标和已声明状态 |
| 选择组件 | ChoiceToggle | 文本、选中标识、禁用外观 |
| 进度组件 | Progress | 背景、填充和可选数值 |
| 列表行 | EUIOptionRowItem，family 为 OptionRow | 中性图标/标题/状态；供 S3 持有 |

表中 Popup 表示页面类型，正式骨架资产仍以 Page 结尾；动态行等宿主持有的轻量单元以 Item 结尾。组件名称保持职责语义，不命名为某个颜色或皮肤专属类型。

Page/Popup 骨架只保留结构与通用行为，不携带 base 主界面的具体开始游戏业务。已有 base 页面可以逐步采用这些结构，原逻辑与行为仍由原页面维护。

## 配置与目录设计

每个库条目包含稳定 ID、Prefab 对象引用、类别、family、别名、是否允许自动匹配、参考尺寸、允许覆盖范围、必要角色和 slots。slots 指向真实组件引用，包含状态及修改权限。

库配置资产是编辑维护源；供 AI 读取的目录是生成输出。配置修改、生成目录和验证分别有实际结果，目录过期时工具不能继续自动匹配。编制时 Ember 的 EUIPrefabCatalogService 仅提供现有页面健康检查，新增语义能力可与它组合，但应保留各自职责。

配置默认值放入模板可管理的 Assets/Ember/Editor 范围。若有 ProjectSettings 偏好，只保存本机目录或窗口配置；工程部署所必需的库引用和默认值不能只存在本机。

## 实施步骤

### 1 从 base 页面识别可复用结构

对照 S0 资产与行为清单，提取按钮、标题、背景、内容容器等重复模式。先记录原对象引用、动画路径、绑定和消费者，避免提取后隐式丢失。

现有基础页可能带 Framework 模式和删除保护。保留这些规则；库源不应误注册成可打开的业务页。确需新的可复用 Item 由中心按 Item 角色创建。

### 2 扩展正式创建服务

在 EUICreationService 的计划/创建流程中支持明确的源骨架和插入区域，并同步中心 UI、预检、错误报告和编译续接。原有调用方式继续有效，不能让未选择模板的已有工具全部失效。

Page/Popup 从基础 Prefab 建立真实 Variant；普通复合组件通过嵌套 Prefab 复用。验证保存后真实关系，复制节点或把完整模板嵌进普通根均不能代替 Variant。

参考分辨率、缩放、安全区和弹窗内容区域来自配置，不沿用当前代码中写死的横屏值作为全部项目标准。

### 3 建立绑定继承策略

独立验证 Prefab Variant 来源和 Binding 基类关系。基础骨架的哪些字段继承、哪些由子页面声明、哪些不得重复生成，需要形成明确规则。

继承控件被移动时重新解析目标，缺失时报出具体字段。源骨架只提供结构时，可使用现有不生成业务代码的方式，但不能造成运行阶段查找不存在的逻辑类。

### 4 制作组件并登记槽位

先按默认皮肤规范制作小型风格板，固定颜色、文字、圆角、间距与状态。生成并导入一份可用背景图和一份空态插画，必要图标统一制作；精确的圆角按钮、卡片和分隔优先使用可伸缩结构或九宫格。执行图片生成时使用 imagegen，保存正式产物到项目并记录来源。

通过中心创建/绑定组件，连接真实字体、图片和状态，不能只留下空骨架或一张整页效果图。公开标题、图标、填充等槽位；内部装饰不暴露为页面绑定。首版限制可覆盖属性，遇到结构变化转为组件定义升级或独立局部组件。

同一按钮创建两个实例，分别设置标题和外观，确认实例覆盖不会写回源。为有私有图片的组件检查资源归属，避免拷贝成多份 Common 图像。

增加一个实际组件库预览，展示主次按钮、选中/禁用状态、文本长度、进度边界和空列表。S2 不等待 PSD 管线完成；它的素材、布局和契约还将用于 S4 制作真实分层试点稿。

### 5 生成并验证语义目录

目录至少能按稳定 ID/准确 Prefab 引用查询，显示其槽位、状态、引用是否失效和调用方。自动匹配默认关闭；开启时必须满足 family 和必要角色，多个候选保持待选择。

加入重复 ID、无效 slot、类型不兼容、越过组件边界、依赖循环等检查。目录不可用时仍可允许已经核验的精确 Prefab 引用，不能静默退化成相似组件猜测。

### 6 改造一个现有页面验证

先在主界面的有限范围替换按钮或标题组件；保存、重新生成后运行开始和设置入口。保持原 Prefab GUID 的路径优先使用正式 Unity 资源编辑流程；如需另建 Variant 再迁移，列出所有引用并按 S5 的身份变更规则处理。

不要直接转换全部 base 页。设置页和完整美术替换留给后续试点，减少一次性迁移范围。

### 7 保存并准备继承传播

确认活动模板仍为 base，通过项目中心预览差异并普通保存。记录受影响派生模板和预计冲突；此时只准备传播清单，不批量覆盖 platformer、视觉小说等模板。

## 完成标准

执行 L01 至 L09。必须展示：新页真实 Variant、两个组件实例独立覆盖、库源保持不变、无效槽位能阻止写入、完整生成与 base 原有导航通过，以及默认皮肤、正式图片和各状态真实可用。

交接记录列出库配置路径、源骨架 GUID、库条目 ID、默认皮肤与素材清单、生成提示词、实际导入设置、组件预览、实际创建方法、已保存 base 状态和待 Bump 状态。未来对话应根据这些真实资产继续，不能按候选名称重新创建一套。
