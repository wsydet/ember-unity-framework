# Ember Framework 0.14.15

发布 visual-novel 0.14.1，封存 hash 为 `b6762e121f2c01184089672ff99b98ca`。修复节点试播提交名字后无法继续的问题。

## 原因与修复

开场段落持有玩家推进锁并启用自动阅读，试播窗口却每帧使用自己的“自动对白”偏好覆盖会话模式。点击画面还会将该偏好切换为手动，于是自动播放停止，而手动推进仍被开场锁阻止。

窗口现在尊重剧情推进锁：锁定时保持剧情控制的阅读模式，禁用手动推进与自动对白切换，并显示状态提示。名字仍正常写入剧情变量；开场结束解锁后恢复窗口控制。

## 验证

修复轮次中两个 Unity 项目编译无错误，4 项专项 EditMode 测试通过，覆盖自动对白开/关、名字提交、锁定时点击画面，以及实际名字/空白默认名。当前消费项目教室节点已复现旧问题，并验证修复后能提交、继续开场、解锁和手动推进。正式 SaveTemplate → Bump、模板谱系及技能同步通过。

发布阶段执行差异、版本声明、共享二进制和字体配置静态检查；不重复没有代码变化的 Unity 测试。未重跑完整测试、完整 Play Mode 或新包升级。

## 更新方式

通过 Ember/UPM Manager 升级到 v0.14.15，再在项目中心预览 visual-novel 0.14.0 → 0.14.1 补丁增量，保留本地业务修改并处理冲突。仅升级框架包不会自动更新已部署的业务 Assets。更早的模板版本按项目实际部署基线选择迁移方式。

框架 API、base、source3d-2p5d 和第三方依赖不变。
