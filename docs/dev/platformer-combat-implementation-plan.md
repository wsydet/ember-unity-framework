- **建议实现**：本文示意的类名、资产拆分、协调对象和编辑界面布局。可以采用满足相同行为和验收标准的等价实现，不要求逐字照造新系统；阶段内部可调整任务拆分，但第 14 节的依赖顺序和退出标准仍须遵守。
- **示例与待调参数**：0.15/0.20 秒缓冲、0.30/1.30 秒窗口及正式示例的具体数值均不是用户最终定值。不得把示例变成硬编码限制，也不得把可选表现缺省误判为玩法缺失。

本期已确认机制要全部交付，但不由“最大化自定义”推导出蓄力、远程、格挡、任意武器系统等未经讨论的新功能。扩展接口用于允许项目替换规则，不代表本期必须实现所有可能玩法。

## 1. 目标、首版范围与不包含内容

### 1.1 目标

提供可组合、可关闭、可配置的攻击和生命机制。用户应能用模板制作不同风格的平台动作游戏，不被绑定为 Project_F 的招式表、属性或元素系统。复用现有 PlayerScheme、手感方案、Powers、FSM、Entity、动画、恢复及开发工具流程。

### 1.2 首版必须交付

| 类别 | 必须支持 |
| --- | --- |
| 攻击 | 每段独立图节点、复用状态实现；起手/攻击/后摇；独立攻击接续节点；按段配置站桩或移动攻击 |
| 输入 | 攻击/冲刺/跳跃短预输入；可执行候选优先级；跨自然阶段保留、跨动作清理；按实际进入读取方向 |
| 收刀 | 始终存在逻辑阶段；普通/特殊收刀；无动画回退 Idle；独立逻辑计时；移动时保留或断连按段配置 |
| 停顿派生 | 普通窗口后进入特殊窗口；Ability 开启决定是否选择特殊收刀；窗口内 CanEAttack 可用提示 |
| 冲刺 | 配置独立冲刺攻击或携带普通下一段；冲刺攻击开放节点；自然收尾续接；移动保留；地空回退 |
| 空冲收尾 | 恢复正常重力、保留水平惯性并减速；正常落地保留剩余收尾时间；重落地/翻滚断连 |
| 命中 | 多窗口、多形状、简单形状与异形 Polygon、离散形状关键帧、按 Entity 去重、拒绝后重试策略 |
| 效果 | 每窗口配置伤害、击退、击飞、硬直与反应优先级；同批命中换血；立即生效的无敌判定 |
| 生命 | 血量、血条、受击反应、死亡处理分别可选；受击无敌；自定义处理接口；默认死亡确认恢复 |
| 工具 | 完整配置复制/冻结/比较/恢复；图与连招单一来源；原生形状编辑与预览；诊断；新增攻击 Skill |
| 示例 | 正式三连击、不会主动移动但可被击退击飞的沙袋、沙袋重置、陷阱、简单刀光序列帧 |
| 验证 | 其他机制用隔离测试配置验证，可复用正式动画，不要求每种机制另做完整美术 |

### 1.3 不自动扩大范围

- 元素切换不在本期。停顿派生不等于命中顿帧；本期不新增完整 hit-stop / 镜头震动系统。
- 不要求复刻鬼泣、黑神话或旧项目的完整出招表，不要求敌人 AI、通用武器系统、复杂世界回滚。
- 不实现任意拓扑 Polygon 顶点插值、任意高速旋转变形的精确连续碰撞算法。
- 不保存攻击进度、Animator 进度、运行状态实例、临时检测器或动作持有的效果句柄。
- 不默认扩大 Ability 为另一套 Skill；当前 Ability 有开启/次数，冷却由现有 Skill 承担。
- 不因添加 Skill 执行模板发布；正式模板保存、Bump、提交、发布、部署分别按授权处理。

## 2. 最终术语与不可变规则

| 术语 | 定义 |
| --- | --- |
| 攻击本体 | 一段攻击从进入到起手、有效攻击、后摇完成的全过程；不是仅指造成伤害的区间 |
| 后摇 | 攻击本体内部阶段，可以依配置先后开放冲刺、跳跃、下一段攻击和移动 |
| 收刀 | 攻击本体自然结束后的独立逻辑阶段，可播放收刀、Idle 或移动表现；独立计时 |
| 普通收刀 | 不满足特殊收刀选择条件时使用；允许普通下一段或按规则重新起手 |
| 特殊收刀 | 有启用的停顿派生且对应 Ability 已开启时选择；从进入起使用特殊收刀身份和动画 |
| 冲刺收尾 | 冲刺自然结束后的续接宽限与运动阶段；不等同于攻击收刀 |
| 接续记录 | 运行时明确保存的普通下一段目标及来源信息；不是从历史状态猜测招式 |
| 命中窗口 | 一段攻击内独立的检测和去重单元；多个形状、多个关键帧可共用同一窗口 |
| 开启 | 能力已装配、方案 Enabled，运行 IsOpen；不等于次数足够或当前环境可执行 |
| 冻结 A | 开始会话时捕获的完整配置；修改源方案不追溯影响运行角色及该会话的恢复候选 |

必须同时成立：

1. 动画负责表现；动作时间、命中、取消、收刀结束由逻辑时钟驱动。
2. 每次实际攻击进入时读取最新方向；该段攻击本体方向固定。
3. 攻击、收刀及冲刺接续上下文中，当前可执行主动动作按 **冲刺 > 跳跃 > 攻击 > 移动** 排序；未来才开放的高优先级动作不阻塞现在可执行的低优先级动作。此处不要求重排普通移动场景原有的全部转换顺序。
4. 上述排序只用于主动动作仲裁，不覆盖死亡、已接受的强制受击和约定的重落地/翻滚。
5. 条件查询不消费；最终提交只消费一次；拒绝不消费资源。已提交后发生异常遵循现有 FSM 故障清理，不擅自返还资源。
6. 不在共享 SO、静态字段、共享 Definition 中保存计时、输入、命中记录、方向或角色引用。
7. 只有实际接管动作的受击反应才中断攻击；仅扣血且反应被保护阻止时可以继续攻击；死亡始终接管。
8. 关闭攻击模块不关闭玩家受击、血量或死亡。血条关闭也不等于生命关闭。

## 3. 配置结构、数据归属与默认值

### 3.1 方案结构

以下为逻辑组织，不要求逐项创建独立 SO。优先嵌入现有资产工作流，确实需要独立复用时才拆资产。

```text
PlayerScheme
├─ Feel : PlayerFeelProfile
│  ├─ Movement                 现有移动及冲刺运动参数
│  ├─ Jump                     现有跳跃/空中参数
│  ├─ Input                    输入有效期与场景缓存策略的唯一来源
│  └─ Attack                   新攻击分组，含模块总开关
│     ├─ Segments[]            每段攻击的时间、运动、打断、命中窗口
│     ├─ RecoveryProfiles[]    普通/特殊收刀逻辑时间
│     └─ DashFollowup          冲刺出招模式、开放节点、收尾续接规则
├─ Powers                     Ability/Skill 装配、开启、次数等的唯一来源
├─ Combo                      起手入口与普通/停顿/冲刺目标连接的唯一来源
├─ Graph                      由对应配置维护战斗子图；既有自定义内容保留
├─ Animation                  本体、普通/特殊收刀、移动变体和特效表现映射
├─ ActionEffects              动作效果接线，包括派生提示；不在两处重复配置效果
└─ Life / Reactions / Recovery 血量、受击、无敌、死亡和恢复的独立配置
```

- 攻击总开关与攻击手感归 Feel。技能次数、开启状态继续归 Powers，不复制到 Attack 中形成第二份权威值。
- 伤害数值/反应参数由每个命中窗口引用的 Payload 所有；玩家生命配置负责如何接收，不重复维护每一刀的伤害。
- 普通/特殊收刀的时间属于攻击配置；Clip、视觉状态和变体属于 Animation。
- 冲刺运动参数留在现有移动分组；出招模式及开放/收尾时间归 Attack.DashFollowup；具体起手、普通下一段、停顿目标和指定冲刺攻击目标只归 Combo。面板可汇总显示，但不能复制数据。
- 站桩/移动及对应收刀是否因移动断连，由本段运动配置决定；RecoveryProfile 只提供收刀时间，不再保存一份可能冲突的移动许可。动画变体不拥有移动许可或连招规则。
- 一个属性只有一个当前有效来源。不实现“全局默认→武器→攻击段”静默多重覆盖。默认值在创建时填入；显式共享资产要展示引用与影响范围。
- 攻击总开关应有明确值；关闭时可不装配攻击专属详细数据和输入。若保留含攻击节点的图，结构与动画映射仍须合法，不能靠关闭开关跳过整个图校验。旧方案的新增字段通过显式默认/迁移处理，不因缺引用自动开启攻击。

### 3.2 建议字段契约

| 数据 | 至少包含 | 约束 |
| --- | --- | --- |
| AttackProfile | Enabled、段集合、收刀配置引用、冲刺接续配置引用 | 关闭后不可经任何入口进入攻击；不影响生命 |
| AttackSegment | 稳定 SegmentId、Enabled、AbilityId、环境限制、动作时长/速度、阶段边界、各取消节点、运动配置、命中窗口集合 | ID 不依赖显示名、数组序号或 Clip 名称 |
| CancelGates | Dash、Jump、Attack、Move 的启用及开放时间 | 分别配置；不能把下一段固定到收刀；时间必须在本体内 |
| MotionSpec | 站桩/移动、运动参数引用、进入速度保留/缩放/指定、地空变化处理 | 每段配置；本体朝向锁定；不得沿用上一动作继续写速度 |
| RecoveryProfile | 普通时长；特殊 NormalDuration/TotalDuration | 特殊 0 <= NormalDuration <= TotalDuration；移动规则取本段配置，表现取 Animation |
| ComboConnections | 地面/空中起手、每段普通目标/停顿目标及启用、冲刺专用目标 | 稳定 ID 引用；只保存连接，冲刺模式取 DashFollowup；允许派生后继续连招 |
| DashFollowupSpec | 模式、攻击开放时间、收尾时长、空冲水平惯性与减速配置引用 | 原连招模式只携带普通下一段；收尾不刷新计时 |
| InputPolicy | 按动作的有效期、适用场景、边沿语义 | 每种请求最多一份；长按不刷新；新按刷新 |
| HitWindow | WindowId、起止时间/单次采样模式、形状关键帧、Payload、过滤、去重及拒绝重试策略 | 同窗口换形状不清命中账本；多形状取并集 |
| HitPayload | 伤害类别/数值、击退方向与初速/刹车、击飞初速、硬直秒数、反应优先级 | 结算时复制为不可变数据，不再回读活动状态 |
| LifeConfig | Enabled、最大/初始血量、伤害接收模式及修正、致死规则 | 有致死规则必须有死亡处理方；不以 HUD 为依赖 |
| ReactionConfig | 默认反应启用、动画、替换优先级、无敌触发/时长/类别/反应保护/表现 | 受击与死亡不要求 Ability |
| RecoveryConfig | 默认/自定义处理、位置策略、回血策略、资源与效果恢复策略 | 普通读档与死亡恢复区分；候选准备成功才交接 |

### 3.3 数值状态

已确认的是规则与默认策略，不是具体平衡数值。以下仅供建立测试夹具，不得标为用户最终选定：攻击缓冲约 0.20 秒、跳跃/战斗取消用冲刺缓冲约 0.15 秒；特殊收刀普通区间 0.30 秒、总时长 1.30 秒。正式血量、每刀伤害、硬直、无敌、收刀与冲刺收尾时长、关键帧、运动值由实现阶段结合素材填写并记录实测。

为了便于正式三连击试跑，建议示例将普通攻击 Ability 开启且不限次；这是示例装配建议，不是用户锁定的能力规则，更不是所有攻击必须不限次。次数限制另用隔离方案验证。不要为平衡数值再阻塞基础开发，但必须在交付中列出最终示例值、单位、来源和调参入口。

### 3.4 完整方案工作流

- 复制：深复制所有可变配置及嵌套数组/形状数据，明确共享 Clip/Texture 的范围；改结构时另复制图和 Controller。
- 冻结：运行捕获必须包含全部攻击、拓扑、形状、伤害、生命和效果参数；浅克隆 SO 不足以证明隔离。
- 比较/恢复：展示攻击与生命差异；参数恢复只处理结构兼容的方案，结构恢复是独立明确操作，不因恢复手感删除用户节点。
- 编辑：支持 Undo/Redo、保存重载、缺失引用定位；不能在预览时消费资源或改运行方案。
- 不把运行时 IsOpen 修改等同于编辑源 SO；配置热切换不作为首版默认能力。

### 3.5 Ability 绑定与缺省校验

- 各攻击段和相关入口可单独启用/关闭，所有攻击入口都检查总开关、段开关和目标 Ability；不能只在普通起手检查，而在连招、停顿或冲刺入口绕过限制。
- 多段可以引用同一个 Ability，也可以逐段引用不同 Ability。绑定关系可配置，不强制每个节点新增独占 Ability。资源仍由 Powers 管理，不由 FSM 节点数量决定装配数量。
- 区分“损坏配置”和“合法但不可执行”：悬空 SegmentId、空的必需 AbilityId、损坏的资产引用属于配置错误；合法 AbilityId 在当前装配中未安装、未启用、未开启或次数不足，属于明确的不可执行状态。
- 特殊 Ability 未装配时必须能按第 6 节进入普通收刀，不能先被全局校验拦住整个角色。其他入口按不可执行拒绝且不消费，不自动换招。
- 必需攻击动画/Controller 目标损坏需报错；可选收刀 Clip 缺省且已有 Idle 回退是合法装配，不能用“缺任何动画就失败”的泛化检查拒绝它。

## 4. FSM 图、连招配置与收刀复用

### 4.1 一段一个节点，共用实现

每段攻击是独立 `EmberFsmNode`，绑定稳定 SegmentId；多个节点复用一个攻击状态实现。普通收刀与特殊收刀使用可复用的收刀状态实现和不同模式/配置，保留明确可观察的节点身份。普通移动与收刀可以复用运动服务，不通过继承 Idle 获取一整套不受控制的转换。

推荐每段配置自己的普通收刀节点，有停顿派生时再配特殊收刀节点。它们可以引用同一只读 RecoveryProfile 或 Clip，但运行计时、来源段、接续目标与效果句柄均为每宿主独立数据。首版不做一个接收任意历史目标的全局共享收刀节点，以免图中出边与来源含混。

```text
Attack_1 ──本体攻击接续节点──> Attack_2 ──本体接续──> Attack_3
   │本体自然结束                 │自然结束              │自然结束
   ▼                             ├─派生能力未开启──> Recovery_2_Normal
Recovery_1_Normal                └─派生能力已开启──> Recovery_2_Delayed
   │普通接续                                          │
   └──────────────> Attack_2           普通窗口 ───────> Attack_3
                                      特殊窗口 ───────> Attack_Special
Attack_3 ──自然结束──> Recovery_3_Normal ──新按攻击──> 环境起手
```

该图说明机制，不表示正式示例必须装配特殊刀；特殊分支放在测试配置。Attack_Special 仍是普通的数据驱动攻击节点，可继续连接后续攻击。

### 4.2 连接唯一来源与生成边界

1. Combo 配置保存目标关系；编辑工具据此生成/更新战斗节点的目标绑定、动画目标及必要取消出边。
2. 使用现有稳定 transition ID、目标 slot、`EmberFsmTargetBinding`、请求位置和预检协议；同一个状态实现可在不同节点把同名 slot 绑定到不同目标。
3. Definition 的转换声明只能声明结构，不能读取当前输入或运行计时。节点绑定 SegmentId 的实际方式在 P1 用真实 API 证明；若 Definition 携带配置标识或参数，必须纳入冻结捕获。
4. 普通/特殊收刀、冲刺指定攻击、冲刺续接目标都必须是图可验证的目标。动态接续须通过合法目标绑定/重定向实现，不能绕过 FSM 直接调用另一个状态的 Enter。
5. 编辑图中的战斗连接时应回写同一个 Combo 来源，或明确设为只读生成区；不能同时手改两份运行拓扑。检测不一致时报告差异，不静默选一份运行。
6. 生成器只拥有声明归属的战斗节点与绑定；保留移动、自定义节点、稳定 ID 和用户布局。只给新增节点排位置。
7. 有意的连招环可以存在；校验应阻止无时间/无输入的自动死循环，而不是拒绝所有图环。

### 4.3 图和 Controller 所有权

需要修改结构时，为当前方案建立独立图和 Controller，保留原有 ID、目标和布局。只改参数不重复复制。可继续共享美术 Clip，但每个覆盖目标需满足实际动画系统的独立 Key 约束。

当前 `PlayerSchemeWorkflow` 将图/Definition 排除出普通可变配置复制，且参考恢复要求相同图引用，不能直接沿用来承诺攻击方案独立。新增结构编辑事务需先预检所有引用，成功后统一提交，失败不留下半套图、Combo、Controller 和动画映射。

### 4.4 与父状态仲裁

现有父级移动、落地、空中转换先于子节点执行，子状态后还有竖直、墙面与挂边后处理。接入后需要明确运动和转换控制权，至少覆盖：攻击锁向、站桩、移动攻击、收刀、冲刺收尾、受击和死亡。

不能让父节点先执行普通跳跃而绕过攻击的跳跃开放点，也不能让墙滑/挂边自动切走未允许取消的攻击。攻击期间这些既有自动行为必须经过当前动作限制；合法退出后交回既有系统。环境切换、重落地、受击、死亡的规则见后文，不用无限增长的“当前状态类型黑名单”代替职责清晰的控制权。

## 5. 动作时钟、输入、取消与朝向

### 5.1 时间契约

- 攻击本体用统一动作进度驱动起手/命中/后摇、形状关键帧和取消节点；攻速变化同时缩放这些内容和对应表现。
- 收刀普通/总时长、冲刺收尾和输入有效期使用独立游戏秒，不随攻速缩放。
- 暂停停止逻辑时间和表现；沿用现有暂停清输入，恢复不补发按键。
- 编辑器可用“帧号/参考帧率”编辑，运行捕获转成统一时间；帧号属于设计时间轴，不等于 Unity 渲染帧计数。
- 表现不能靠 AnimationEvent 开关命中或决定状态退出。现有动画禁止事件的边界继续保留。
- 逻辑步跨过节点时按区间检查处理，不能要求某一帧恰好等于配置时间。跨过完整短命中窗口也要按约定采样/扫掠，不能整窗漏掉。
- 边界统一：窗口使用左闭右开区间；普通 `[0, normalEnd)`，特殊 `[normalEnd, totalEnd)`，到 totalEnd 已失效。容差集中处理，不在各状态随意增加一帧宽限。

### 5.2 请求与缓存

建议每种按钮请求保存：按键版本、按下时间、到期时间、所属动作/接续机会标识、意图类别（普通接续/停顿派生/环境起手/冲刺后攻击）。方向不在按下时锁定，实际攻击进入读取最新方向。

- 每种请求最多一个，新按刷新本类请求；按住攻击不自动刷新或逐段连发。移动使用当前连续输入，不当成排队的攻击按键。
- 攻击本体内，下一段节点未开放时可缓存普通接续；开放时且请求仍有效才能提交。
- 普通/特殊意图由按下时所在阶段决定；普通请求不等待到特殊窗口再变成特殊攻击。
- 请求可在短有效期内等执行条件恢复，但同时受对应接续机会截止约束；机会先结束就丢弃。缓存不延长连招窗口。
- 在上述战斗上下文中，对当前有效候选按冲刺、跳跃、攻击、移动比较。最终拒绝不消费资源；按既有 FSM continuation 继续评估适用候选，不用“最高优先级有输入”直接吞掉其他动作。
- 同一次请求成功执行后只消费一次；其他属于旧动作的请求清理，防止在新动作中补发。
- 当前冲刺没有独立持续缓存；必须新增战斗取消等场景的冲刺缓存策略，普通移动场景保持既有即时请求行为，除非用户另行调整。

### 5.3 跨阶段清理表

| 转换 | 输入 | 连招/机会 |
| --- | --- | --- |
| 本体自然进入收刀 | 保留仍有效且仍适用的请求，不刷新 | 保留本段接续语义；选择本次收刀类型 |
| 本段进入下一段 | 消费本次攻击请求，清理旧动作请求 | 新段建立新机会 |
| 攻击被冲刺取消 | 清理旧攻击缓存，新按键才是冲刺内输入 | 指定攻击模式清旧链；续接模式只携带普通下一段 |
| 冲刺自然进入收尾 | 保留仍有效请求，不刷新 | 保留已有普通续接记录或指定攻击路线 |
| 冲刺收尾普通落地 | 保留仍有效且适用请求 | 转移剩余时间，不重置 |
| 攻击中成功跳跃；冲刺收尾成功跳跃或再次冲刺；约定的重落地/翻滚 | 清理旧机会请求 | 断连；收尾再次冲刺不继承前次记录；攻击首次取消到续接冲刺按上方专门规则处理 |
| 实际受击接管/死亡 | 清理旧输入与提示 | 断连、关检测，按结算批次规则保留已成立候选 |
| 暂停 | 清空未消费输入 | 逻辑计时冻结，不延长游戏时间意义的窗口 |
| 停止/恢复替换/销毁 | 全部释放 | 不持久化连招和临时效果 |

### 5.4 移动与方向

- 按段配置站桩/移动攻击；每一刀 Enter 时读取最新水平输入，无输入沿用当前朝向；本体朝向固定。
- 本体可以水平移动不代表允许途中翻转攻击判定。形状镜像依据本段方向，视觉与判定一致。
- 站桩攻击达到移动取消节点后，移动取消并断连。移动攻击则按本段运动规则移动，不因输入方向而断连。
- 移动攻击收刀允许移动并保留连招；站桩攻击收刀移动取消仍断连。收刀允许移动时恢复移动表现与正常转向，下一刀再锁方向。
- 收刀阶段可被合法攻击、跳跃和冲刺直接接管，不重复等待攻击本体的取消节点；移动则遵循上条的站桩/移动区别。
- 每段配置入场速度：保留、按比例缩放或指定。之后由该攻击的运动规则负责，不能继续叠加旧冲刺尾速控制。

### 5.5 攻击中地空变化

按段配置环境策略，首版默认：地面专用段失去地面时结束并断连，回正常空中；空中专用段落地时结束并断连，交给落地规则。明确配置地空通用的段可继续，仍受重落地/翻滚的强制退出规则约束。

保留以后“落地转指定攻击”的策略扩展接口，但首版不要求实现完整落地派生招式。环境仅在进入时检查、全程不管变化，不是默认行为。

## 6. 普通收刀、特殊收刀与停顿派生

### 6.1 选择与时间

攻击本体自然结束总是进入逻辑收刀，缺动画用 Idle。下一段可在本体后摇提前接续，不必等到收刀。

选择特殊收刀需要同时满足：本段存在启用的停顿连接、目标攻击启用、目标 Ability 已装配且 Enabled 且 IsOpen。否则进入普通收刀，使用普通收刀自己的时长；不能留下没有派生目标的特殊等待阶段。

特殊收刀**从进入起**使用特殊收刀身份与动画，不在普通窗口结束时才切入特殊收刀。窗口例子（非正式平衡值）：本体结束为 t=0，`[0,0.3)` 可普通第三刀，`[0.3,1.3)` 可特殊刀，t>=1.3 断连。时间由收刀配置决定，动画不是第二套计时。

### 6.2 Ability 与提示生命周期

| 变化 | 处理 |
| --- | --- |
| 未安装/禁用/未开启 | 不选特殊收刀，普通收刀仍可接普通下一段 |
| 已开启但次数不足 | 可选特殊收刀；不提示当前可执行；请求只在有效窗口内等待 |
| 普通收刀中解锁特殊能力 | 本次仍普通，下次收刀重新选择 |
| 特殊收刀中关闭能力 | 移除提示和执行资格，不换普通收刀、不延长时间 |
| 特殊收刀中恢复资格 | 若还在特殊窗口，可以恢复提示及执行资格 |
| 离开特殊窗口或收刀 | 移除本次持有的提示句柄；不得移除别的来源效果 |

CanEAttack 复用现有 Entity 效果体系表达，不要求旧 Buff 枚举继续存在。其条件是特殊窗口开放且目标满足当前能力/资源/环境/临时限制，**不要求已经按下攻击键**。它只做表现，不作为攻击资格的权威数据。效果容器关闭却配置依赖该容器的提示/无敌时要显式报告依赖错误或使用用户明确选择的替代策略，不能静默开启容器。

目标暂时不能执行时，不自动降级普通刀、不重新起手，不消费资源、不刷新收刀；请求和对应机会任一到期就失效。

### 6.3 最后一刀和重新起手

- 本体内只尝试明确配置的下一段，没有目标不能自动回第一刀。
- 收刀时若本段不存在对应接续目标，新的攻击按键可以尝试当前环境起手，建立新连招。
- 有目标但它暂时不可用，与“没有目标”不同；不得静默回第一刀。
- 本体里为下一段缓存的请求不能改成收刀重新起手；重新起手需要进入收刀后的新按键。
- 请求只对应其阶段的路线，普通请求不能借特殊路线延寿；收刀总时长结束后回普通移动，新按攻击按常规起手处理。特殊收刀的普通窗口结束只切换接续资格，不提前退出整个收刀。

### 6.4 收刀表现复用

同一逻辑收刀中支持收刀 Clip、Idle、移动表现切换；允许配置专用移动收刀 Clip，缺少时用普通移动表现。动画播完而时间未到可回 Idle。切换表现不退出逻辑收刀、不刷新时间、不重复发提示。

复用的是状态实现、配置和 Clip；不是复用同一个运行计时实例。普通与特殊收刀有各自的视觉选择，不因为使用同一 Idle 回退就混淆其逻辑身份。

## 7. 冲刺攻击、续接与空中惯性

### 7.1 两种出招模式

| 模式 | 冲刺内攻击节点开放后的目标 | 原连招 |
| --- | --- | --- |
| 指定攻击 | 配置的冲刺攻击；可以再接它自己的连招 | 开始该冲刺时清除旧连招 |
| 续接普通下一段 | 进入冲刺时携带的明确普通下一段目标 | 保留普通下一段，不保留停顿资格 |

冲刺中开放节点前按攻击可短缓存，节点开放时有效才执行。攻击取消进入冲刺时清掉之前的攻击缓存，必须在冲刺期间新按攻击，防止原本连续输入自动触发冲刺攻击。

普通下一段记录包含稳定目标 ID、来源/机会代次和有效生命周期，不依赖上一个状态类名。无有效记录时按配置的当前环境起手规则处理，不编造一段连招。攻击本体进入续接冲刺时，按已确认规则把普通下一段转交给冲刺机会；这是显式交接，不是延长原收刀计时或保留停顿资格。

冲刺内节点与冲刺收尾使用同一目标解析规则：优先原普通下一段；它不符合当前地空条件时放弃旧链并尝试环境起手。此规则不能只实现于收尾而遗漏冲刺中的攻击节点。冲刺收尾中新按攻击也可执行，不要求必须在冲刺本体里提前按下。

### 7.2 冲刺收尾特殊规则

- 自然冲刺结束进入独立收尾，时间配置独立于动画；没有收尾动画也必须可执行。
- 收尾开始即可尝试攻击，保留冲刺末尾仍有效输入，不刷新。
- 移动和转向不清记录、不重置时间；成功跳跃、再次冲刺、重落地或翻滚断连；受击/死亡按全局规则清理。
- 普通落地保留剩余收尾时间，不能重新给完整地面时长。重落地/翻滚仍断连。
- 记录的普通下一段不满足当前地空条件时，放弃旧链，尝试当前环境配置的起手。若没有合法起手则保持运动，不消费资源。
- 只有地空不符触发上述回退；目标次数不足/未开启不等于地空不符，不借机自动换招。
- 时间耗尽清续接机会，但不能强行把水平速度置零；运动平滑交还常规控制。
- 墙碰撞、主动打断等非自然结束不能误用自然收尾；接墙不能持续向墙推进惯性。依据现有冲刺结束原因实现明确分支。

### 7.3 空中冲刺收尾运动

进入时恢复正常重力，保留配置比例的水平速度。无输入向 0 减速；同向输入向正常空中移动速度收敛；反向先制动再反转。复用 Motor，并保证墙面/竖直修正不会再次覆盖该规则。

当前冲刺结束有速度钳制和清竖速逻辑，需要改为按结束原因交接。新攻击、跳跃、受击等接管后立即停止旧收尾的速度写入。正常落地后使用适当的地面运动处理，但续接剩余时间不变。即使普通移动配置为立即设速度，也要避免收尾结束当帧将残余惯性突兀截断；运动交接与接续资格截止分别处理。

## 8. 命中范围、关键帧与编辑体验

### 8.1 运行检测

- 不为每一招永久挂一个碰撞器。使用当前动作需要的检测器/形状数据和可复用池；身体碰撞、受击范围、攻击范围职责分离。
- 已确认支持简单形状和异形 Polygon。简单形状实现可优先选用 Box/Circle/Capsule 等 Unity 原生工具方便编辑的类型，不把列举的所有原生类型擅自扩成额外首版承诺。每个命中窗口可包含多个形状，以 Entity 为单位取并集。
- 活跃窗口内持续查询，默认同实体每窗口最多结算一次；支持明确的单次采样窗口。新窗口/新段重新建立账本，同窗口换关键帧不重置。
- 排除自身、所属无效对象、友方或不接受该类攻击的对象；不依赖旧具体敌人类型。多个 Hurtbox 解析到同 Entity 后去重。
- 窗口实例 ID + 攻击实例 ID + 接收实体身份共同确定去重范围；对象池复用不得继承上一轮命中记录。
- 平移高速运动使用与形状匹配的扫掠/区间采样方案，验证实际物理姿态与查询顺序。不得宣称任意旋转/变形连续碰撞已经精确解决。
- 时钟跨过完整短窗口时仍执行有效采样；形状切换按关键帧取值，不用 AnimationEvent 临时开关 collider。

### 8.2 拒绝重试策略（逐窗口配置）

默认普通挥砍：合法目标第一次进入受击结算即记为已尝试，即使被无敌拒绝也不重试。可选择“仅成功接受效果后记账”，用于无敌结束仍希望被持续范围命中的攻击。

自身、友方、错误层等在合法性过滤时被排除，不占账本。未安装生命但接受了击退/硬直，也属于成功效果。是否被接受由统一接收结果明确表达，不能只用“扣血大于 0”推断；本文不额外规定零伤害、格挡等自定义接收结果必定成功或失败。

陷阱的周期伤害使用独立间隔/接触机会，不把“受击拒绝重试”当成任意无限连击开关。每步仍需限制同一窗口对同实体最多一次尝试。

### 8.3 编辑工具

在玩家开发工具中增加攻击时间轴/命中编辑区：

1. 选攻击段与窗口，拖动时间轴、上一帧/下一帧，预览真实角色对应姿态。
2. 创建临时编辑对象承载原生 Collider2D，使用 Unity 原生形状/Polygon 点编辑工具。
3. 把形状参数保存进当前窗口关键帧，支持复制上一关键帧；运行角色不永久保留这些编辑对象。
4. 离散关键帧保持到下一帧，不在首版做任意拓扑插值；不同关键帧可改变点数。
5. 左右镜像、局部偏移、缩放与脚底基准必须与运行检测一致；预览时显示当前窗口、方向和有效轮廓。
6. 编辑不要求进入 Play，不造成伤害、不扣次数、不写当前会话；Undo/Redo、取消、关闭、域重载释放预览对象。
7. 保存前校验非法点集、非有限值、零面积、无效尺寸、越界关键帧；报错定位攻击段/窗口/关键帧。

## 9. Entity 伤害、生命与受击反应

### 9.1 职责拆分

Entity2D 保持身份根和所属关系。生命、受击接收、反应运动为可选能力，不能强制所有 Entity 都装血量或玩家 FSM。

建议的角色服务（名称非现成 API）：Health 保存运行血量；HitReceiver 做合法性、保护及伤害修正；ReactionDriver 接管击退/击飞/硬直；HitResolver 协调本步候选与结果。由既有会话驱动者明确推进，不另加全局 CombatManager 或在每个脚本自行 Update 造成顺序分裂。

玩家、沙袋、陷阱走同一命中数据与受击协议。击退/击飞通过 EntityMotor2D 或宿主的等价运动适配，不写根 Transform、不同时 Rigidbody.AddForce 和 Motor 覆盖。

### 9.2 结算流程

```text
检测形状 → 合法目标过滤 → 每窗口账本检查 → 收集不可变命中候选
→ 稳定排序 → 每条命中读取处理前的伤害/反应保护，确定本次可接受内容
→ 修正伤害并更新生命 → 根据本次已确定的许可决定死亡/受击反应
→ 若实际扣血且存活，在处理下一条命中前建立受击无敌
→ 发布明确结算结果 → 表现、音效、刀光命中特效消费结果
```

- 结果至少区分拒绝、仅伤害、仅反应、伤害与反应、致死，包含实际扣血和被接受的反应，必要时附拒绝原因。检测到重叠不等于造成伤害。
- 在同一物理步先收集已成立候选，再按稳定规则结算。稳定顺序不得由 MonoBehaviour 更新先后或哈希容器迭代偶然决定；采用稳定实体/攻击/窗口序号等显式键。
- 允许换血：来源角色在结算中受击/死亡不撤销本批已成立候选。接收目标已经死亡时不重复伤害、反应或死亡事件。
- 立即新增无敌影响本批之后的命中，不把整批预先全部判为“无敌前可伤害”。
- 新增的受击无敌不能反过来否决触发它的这一击已经接受的硬直/击退/击飞。单条命中的保护判断和结果提交要保持一致，不能在增加新保护后重新查询本次反应资格。
- 队列在停止、恢复替换、场景退出时有明确失效边界，旧会话候选不得打到新恢复实例。
- 同步回调不直接嵌套执行另一轮 FSM 转换；通过统一提交阶段或动作接管请求处理，避免可重入状态清理。

### 9.3 血量与伤害模式

- 血量与血条分别启用。无血量实体仍可接受击退/击飞/硬直，也可用自定义接收器处理命中。
- 支持按输入伤害及接收方倍率/减免结算，和接收方固定每次有效命中扣血两种配置；正式示例默认输入伤害模式。
- 最大血量、初始血量、修正、伤害类别可配置。UI 只订阅生命变化，不负责判死或扣血。
- 禁用默认反应不等于禁用扣血；禁用受击动画不等于禁用硬直和位移。
- 有致死规则必须指定默认或自定义死亡处理；没有默认死亡处理时需明确选择非致死生命规则或自定义处理方，不产生“0 血仍正常操作但无人负责”的隐式行为。

### 9.4 击退、击飞、硬直

- 每个命中窗口指定伤害、击退方向/初速度/刹车、击飞初速度、硬直时间及反应优先级。
- 反应保护默认阻止硬直、击退和击飞，但不自动免伤；伤害保护另行按类别处理。
- 高优先级反应替换低优先级；同优先级使用最新位移参数，剩余硬直取 max(原剩余, 新时长)；低优先级仍可扣血但不覆盖更强反应。不累计冲量。
- 反应接管清旧输入/连招/提示、关后续攻击检测；已收集候选按换血规则保留。
- 默认硬直期间不能主动移动、跳跃、冲刺、攻击取消。期间新按键只按短缓存保留，硬直结束仍有效才执行；不默认提供受击脱身技能。
- 硬直由逻辑时间结束，不由受击 Clip 长度决定。结束按当前地空条件恢复控制。
- 击飞落地先处理碰撞和竖直运动，剩余硬直继续，不因落地解除，也不额外叠加普通落地停顿/翻滚；硬直结束但仍在空中则回空中控制。

### 9.5 受击无敌

默认在实际 HP 减少且未死亡后立即获得，拒绝命中不刷新。时长、触发策略、伤害类别、反应保护、闪烁表现可配置，允许关闭或替换策略。

受击无敌通过接收方保护查询实现，不关闭身体物理碰撞。无血量或只反应角色默认不触发“扣血后无敌”，可通过自定义触发策略提供其他行为。无敌效果与反应计时都使用游戏时间并在暂停时冻结。

### 9.6 效果作用对象隔离

现有玩家效果绑定收集所属 Collider2D/SpriteRenderer，新增攻击后必须细化目标集合：身体碰撞体用于身体穿透；受击范围用于受击检测；攻击范围由攻击查询负责；角色 Sprite 用于身体闪烁；刀光与派生提示默认独立，允许显式选择跟随。

不能让身体穿透层掩码误改攻击查询，也不能无差别给所有子 Sprite 写 alpha。动态创建的检测器/表现要有正确注册或独立所有权；释放后恢复各自原值，不覆盖其他系统。CanEAttack 句柄和受击无敌句柄不能互相误删。

## 10. 死亡、恢复与存档兼容

### 10.1 默认死亡流程

生命达到致死条件 → 标记终止生命状态 → 关闭后续攻击/受击反应入口并清临时动作资源 → 默认死亡表现 → 等待确认 → 使用当前会话恢复点创建恢复候选 → 候选成功后交接 → 恢复位置并按默认策略回满血。

死亡只触发一次。停用普通操作输入之后仍必须有可用的恢复确认入口，不能把确认也随 Gameplay 攻击输入一起屏蔽。没有死亡 Clip 可使用明确回退表现，不阻断逻辑死亡/确认恢复。

### 10.2 恢复策略

- 首版默认只恢复玩家，不重载/重置整个场景；沙袋通过独立重置功能恢复。
- 位置可来自当前会话恢复点，保留出生点/自定义来源接口；血量默认全满，保留固定值、比例、保存值策略位置。
- 能力资源与可恢复效果默认沿用恢复快照；动作、连招、预输入、临时派生提示清空。特殊“满次数复活”不是隐式行为。
- 普通读档恢复保存的 HP；死亡恢复对候选施加明确回血策略，不能混成“所有读档都回满”。
- 使用现有 PlayerModule/场景流程的恢复候选事务，准备失败保持原会话安全状态，不在旧玩家身上先传送再尝试装配。
- 默认世界不回滚，但提供自定义恢复策略接口；本期不实现完整世界存档。若项目需要重载场景，由替换策略明确负责。

### 10.3 快照扩展

当前 PlatformerSnapshot 为 v2，仅含场景、位置、速度、方向、能力和效果，没有 HP。新增带明确“生命是否装配”语义的生命记录及版本；先核对执行时版本，不能覆盖其他任务新增字段。

旧档默认明确拒绝并给出重新开始/迁移提示；提供迁移接口，由业务项目选择转换，不静默补满血。迁移契约同时覆盖数据版本变化和能力装配集合变化；当前能力恢复要求集合严格匹配，新增攻击 Ability 后不能只修改快照版本就声称兼容。

本期不保存精确动作进度。工程上沿用现有快照的可恢复性约束：攻击本体、有效收刀/冲刺接续机会、受击、死亡等新增临时状态，若不能由本期快照正确还原，应在捕获入口明确拒绝并返回原因，不能只隐藏 UI 保存按钮，也不能静默丢弃连招却宣称完整恢复。

准确的允许/拒绝阶段清单在 P7 对照实际快照能力落实；这不是新增“只要播放收刀外观就禁止存档”的玩法规则。逻辑机会已结束、只是还在播放一个视觉片段时，不凭动画名拒绝保存。恢复点来自合法稳定快照，不能把当前死亡位置自动保存为恢复点。Owned 动作效果不能伪装成可恢复 Timed 效果。

## 11. 动画、刀光、示例与调试

### 11.1 动画与逻辑同步

现有 AnimationSession 根据叶节点 ID 和 activation generation 切换固定动画；同一节点内改表现不会自动生效。需要增加显式视觉变体/播放请求，支持同一收刀逻辑节点中的收刀、Idle 和移动表现，以及攻击动作速度与时间同步。

- FSM 仍是动作权威。Animator 不新增自动转换、行为回调或 AnimationEvent 来偷渡玩法状态。
- 保持现有图节点映射完整，新增变体是对映射协议的显式扩展；不能简单把“一节点一槽”校验删掉而失去缺失目标检查。
- 每个动画播放目标保持合法独立覆盖 Key；同一个实际 Clip 可被多个目标复用。不同方案增加目标时不得修改共享 Controller。
- 攻击动作的视觉进度与命中进度使用一致的速度来源；不能只设置 Animator.speed，而逻辑窗口仍按旧时长运行。
- 同节点由移动变回静止，不应重播完整攻击或重置收刀时间。视觉切换的归一化时间/从头播放策略应明确，但不改变逻辑窗口。
- 保留 Visual/Animation/Sprite 的职责和朝向、脚底基准；角色位移由 Motor，动画仅局部视觉曲线。

### 11.2 正式示例

只制作一套三连击，使用明确配置的 Attack_1/2/3、普通收刀、命中窗口与 Payload。正式体验应包含可观察的伤害、击退/击飞/硬直、受击无敌、死亡确认恢复。不得为了测试停顿或冲刺派生而把正式默认图塞满额外演示攻击。

沙袋：不主动移动、不追踪玩家；有合法地面/重力运动，可受击退和击飞；重置恢复位置、速度、血量、反应、效果和命中生命周期，旧排队命中不得打到重置后的新生命周期。重置入口可以使用已有开发工具/调试入口，不要求为它额外制作正式复杂 UI。

陷阱：通过相同 HitPayload/Receiver 流程造成伤害；接触重复伤害有独立间隔；暂停与重置行为明确。用于验证掉血、无敌拒绝、致死和恢复，不直接修改玩家 HP 绕过结算。

刀光：实现阶段生成简单透明背景序列帧，按实际角色尺寸、攻击方向和帧率校准；可以复用一套资源配不同偏移/时序。生成后检查透明度、帧间稳定性、枢轴和镜像，在 Unity 实播验证。刀光不承担命中判定，移除刀光也不能改变战斗结果。本次文档任务不生成图片。

正式血条若启用，必须通过 EUI 开发中心创建、绑定、生成，用户代码依据真实 Binding；不能手工拼造正式 UI。生命与 HUD 可分别关闭的行为必须实测。

### 11.3 测试配置而非新增美术需求

建立隔离测试配置覆盖普通/停顿连招、特殊能力未开启/次数不足、指定冲刺攻击、冲刺续接、空冲惯性、移动攻击、空中攻击、地空通用攻击、多窗口、多形状、无生命受击、禁用默认反应、自定义死亡恢复。允许借用三连击 Clip/Idle，不把占位美术测试描述为最终独立招式资产已完成。

### 11.4 可观察性

白盒/开发工具应显示或记录：方案与冻结会话标识、叶节点与 SegmentId、动作时间、开放节点、请求意图/剩余有效期/拒绝原因、收刀类型/剩余时间、冲刺续接目标、Ability 状态、命中窗口/形状/账本、实际结算结果、HP/无敌/硬直、当前运动控制者。

记录通过现有诊断入口按需开启，避免每物理帧常态刷日志。提供复现输入、固定步长、配置值与结果；实际蓝图/画面/位置曲线是体验证据，不能用浏览器模拟或孤立状态实例替代正式运行。

## 12. 新增攻击 Skill 与现有 Skill 协作

### 12.2 工作流

1. **发现环境**：读取项目规则；Unity 连接核对 Application.dataPath；调用模板技能前置检查，确认实际模板体系、模块、版本兼容和 API，而非只看有同名脚本。
2. **确定目标方案**：区分当前编辑、下次白盒、项目默认、冻结运行方案；保护草稿和布局；只读内置方案先复制。
3. **收集缺少的设计**：确认普通/停顿/冲刺指定/冲刺续接/地空/移动攻击等类型、段数与连接、Ability、接续/取消节点、收刀、伤害反应。继承用户已确认事项，不逐字段重新问。
4. **推荐素材**：先查现有可用序列帧，再按需要推荐外部素材或 AI 生成；给出动作覆盖、帧数/帧率、尺寸/枢轴/朝向、使用许可及缺失动作。外部许可需查真实来源，AI 生成不冒充现成授权素材。
5. **用户选定素材与关键参数**：在用户已授权范围内推进；缺素材选择时可先完成可复用配置设计，不擅自把未选素材定为正式资产。不要用逐文件确认替代合理执行。
6. **实施**：调用正式编辑 API 创建段配置、Ability 绑定、Combo、图节点、收刀、动画和命中关键帧；结构变化独立图/Controller；保留用户自定义节点。
7. **验证**：静态完整性、正常主流程/白盒实播、伤害与取消、关闭/资源拒绝、左右方向、素材脚底、暂停/清理、复制冻结和保存重载。
8. **交付**：列出资产路径、配置与图差异、素材来源、最终参数、实际通过项和未执行项；保存/试跑/设默认分别报告。必需攻击表现、检测或实际验证缺失不能声称新增攻击完成；可选收刀动画缺省且合法回退 Idle 不属于缺项。

### 13.2 同步与生命周期实施约束

同批换血需要一个覆盖参与角色的明确“收集完再结算”边界，可用 Gameplay 拥有的普通战斗会话协调对象，禁止升格为所有模板必备 Manager。玩家、沙袋及陷阱不能各自边查询边立即结算而声称支持同批公平换血。

P0/P1 需验证现有 Unity 自动物理模拟与 FixedTick 的姿态可见时点，写明一次逻辑步使用哪个已同步姿态进行查询，以及 Motor 指令、攻击形状更新和结算顺序。优先适配现有模拟流程，不为此默认改成全局手动 Physics2D.Simulate。时间跨窗与同批候选测试必须覆盖多个渲染/物理步比率。

停止、准备失败、图故障、恢复替换、对象销毁、沙袋重置时，按所属对象释放：输入/机会、命中账本、待结算记录、效果句柄、形状池租约、运动控制权、动画覆盖、订阅与临时预览。清理幂等；已提交的资源异常不自动回滚；新会话不接受旧会话残留数据。

动作受击/死亡退出与会话替换不是同一种清理：前者关闭未来检测，但本批已成立候选按第 9 节保留；后者隔离旧会话数据。不能在通用 Exit 清理中把本批换血候选一并删掉。

## 14. 分阶段实施步骤

依赖主线：`P0 → P1 → P2 → P3 → P4 → P5 → P6 → P7 → P8 → P9`。以各阶段的工作、产出和退出标准为准；正文明确留到后续阶段的集成验证，在前一阶段记录为待后续验证，不提前宣称通过，也不倒置依赖。

阶段内部可调整任务拆分、做独立验证或提前创建测试配置，但不得跳过前置所有权/时间契约去直接制作大量招式。发生阻塞可完成不依赖该阻塞的工作；未满足退出标准的阶段仍标为未完成，不能放行依赖该缺失结果的后续工作。阶段推进不需要重复授权，超出用户范围的操作仍按授权边界处理。

### P0：基线与接口验证

**工作**：读取实际规则、源码、模板身份与 Git 状态；核对 Unity 项目和工具可用性；记录当前默认方案、图/Controller 引用关系、输入动作、恢复链和原移动测试入口。用最小原型/现有测试证明共享状态多节点绑定、父子转换顺序、真实物理查询时点与同批结算接入位置。

**产出**：精确改动清单、配置所有权图、现有行为基线、测试入口和已知限制。声明主要模板升级；确需框架 API 改造时列出最小通用契约。

**退出标准**：能解释一个攻击请求怎样通过真实 FSM 提交、一个角色何时写速度、何时检测命中；没有把不存在的 API 当作已有能力。原项目/草稿未被切模板覆盖。

### P1：数据契约、方案所有权与静态校验

**工作**：实现 Attack/Combo/Recovery/Hit/Life 等必要配置及捕获值；总开关、段启用和 Ability 引用；扩展方案复制/冻结/比较/恢复/保存。实现结构编辑时图与 Controller 独立化和带归属的节点生成基础。

**产出**：可创建、复制、保存重载的纯移动与战斗方案；完整校验错误定位；图/Combo 一致性验证。对外接口名称和所有权在此阶段定稿。

**退出标准**：两个方案改参数/拓扑不会互相污染；修改源配置不改变冻结会话；关闭战斗可运行纯移动；损坏目标、必需动画或能力标识显式报错；可选 Ability 未装配、可选收刀动画缺省按约定拒绝/回退，不全局报错。校验无运行副作用。

### P2：输入、动作时钟与控制权

**工作**：攻击输入、战斗场景冲刺缓冲、请求版本/意图/截止、动作时间轴；主动优先级与实际提交消费；父级水平、朝向、空中转换及后处理的控制权。

**产出**：可观察的输入/节点时间诊断，使用测试段验证节点先后，不必等待正式美术。

**退出标准**：战斗上下文中冲刺/跳跃/攻击/移动同时输入按当前资格排序；高优先级未开放不阻塞；拒绝零消费；缓存不跨机会、不因长按刷新；原移动和跳跃缓冲行为无无意回归。

### P3：攻击本体、普通收刀与三连击闭环

**工作**：一个复用攻击状态、每段独立节点；各取消节点；站桩/移动与方向锁定；地空变化策略；普通收刀、重新起手、缺动画回退；必要动画变体支持。

**产出**：三连击配置与运行链，暂可用占位动画，明确标记未完成伤害与美术。

**退出标准**：后摇可提前下一段；移动攻击能边走边连续转向下一刀；站桩移动取消断连；第三刀收刀新按可起手、本体旧缓存不会补第一刀；缺收刀动画仍完整。

### P4：特殊收刀与停顿派生

**工作**：特殊收刀选择、普通/特殊窗口分割、Ability 动态资格、CanEAttack 持有句柄与表现接线、派生后继续连招。

**产出**：隔离配置验证第二刀普通第三刀与停顿特殊刀；不要求正式示例新增特殊美术。

**退出标准**：不会压缩普通接续窗口；能力未开启走普通收刀；次数不足/开关变化/窗口边界遵守第 6 节；提示不提前、不残留、不替代资格判定。

### P5：冲刺续接与空冲惯性

**工作**：两种冲刺出招模式；冲刺节点与输入；普通下一段 token；自然收尾移动保留；普通落地剩余计时；重落地/翻滚/跳跃/再冲断连；环境回退；空冲结束原因与惯性控制。

**产出**：指定冲刺攻击、插入冲刺续连、地空回退和惯性测试方案/轨迹。

**退出标准**：旧攻击缓存不触发冲刺攻击；停顿资格不被携带；持续方向输入不误断连；普通落地不刷新时间；尾速不被父状态或收尾截止突兀归零；墙碰撞不继续推墙。

### P6：命中检测、原生编辑与伤害结算

**工作**：形状/关键帧数据和检测池，编辑预览；多窗口账本与两种拒绝策略；共享结算批次；Entity 可选 Health/Receiver，Payload/Result；效果目标隔离。

**产出**：可在非 Play 编辑异形范围，运行和预览一致；沙袋基础伤害接收及位移反应请求；通过受控接收器复现同批换血结算。完整击退/击飞运动和真实死亡状态的集成由 P7 补齐。
