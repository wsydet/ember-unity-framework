# base 与六个子模板玻璃 UI 迁移：需求 R1

日期：2026-11-17，Asia/Shanghai。任务 ID：20261117-base-soft-glass-migration。

## 用户确认和来源

用户在主对话要求：“给我们的框架的base的主界面和设置界面等都使用我们的新的玻璃UI优化一下，包括几个子模版”，并调用 ember-solution-design。
用户随后明确选择“完整模式：由本主对话创建方案、实施、独立验收对话，并向它们派发本任务后续工作和返工，统一收取结果”和“全部六个子模板”。
用户补充：“切换模板的时候可能会有弹窗需要我处理，子对话直接叫我就行了”。这允许执行阶段直接提醒用户处理真实弹窗；不授权代理绕过、自动点击或静默丢弃草稿。此前用户明确要求暂不发布框架版本，该限制继续有效。

## 方案需具体化的页面范围

只读初查：七模板均包含 EUIMainPage、EUISettingPage、EUILoadingPage、公共 Alert/Confirm 和设置行 Item。ui-game 有自身结果页；lane-defense 有暂停/结果 Popup；visual-novel 有阅读菜单、存档/槽位等专属页面。该列表是候选清单，不穷尽正式页面。

方案须逐模板列出现有正式页面、公共/专属归属、复用或适配策略，以及明确不改的玩法内容。主菜单/设置/公共弹窗/加载及模板对应导航页面优先；其余 HUD、小说正文/角色表现等先说明是否需要视觉适配，不能借换肤重写玩法或剧情系统。没有用户给出的额外图片附件，不假定存在 PSD。
