# 增强缓冲进度条需求 R1

- 任务：20261117-buffered-progress-bar。
- 日期/时区：2026-11-17，Asia/Shanghai。
- 来源：入口当前对话。用户先提出类似 DNF Boss 血条的缓冲效果、可扩展现有进度条并提供进度文字，随后明确要求：“两种都做成可选模式吧，慢慢缓冲也可以单独开启或组合使用，支持进度文字，按我们框架规范把这个增强进度条做起来。”
- 用户已授权本功能实现、必要局部修复、相关增量验证和使用文档；无需重复请求同范围实施审批。
- 当前为需求基线；接口、算法、默认参数与实现方式尚未设计。本任务独立于已归档的 UI runtime extensions，不恢复或复用其旧临时目录。

## 有效需求

| ID | 内容 | 来源/性质 |
| --- | --- | --- |
| R01 | 提供通用增强进度条，保留真实进度层；进度下降时真实值立即更新，缓冲表现独立于真实数据，可用于血量、护盾或其他数值进度。 | 用户明确要求及已说明的交互模型 |

## 边界、提议与非目标

- 用户未要求多管血条、分段/分阶段 Boss 逻辑、伤害计算、飘字、Boss 名称/头像、音效或粒子；本次不将其加入范围。
- 白条的两种模式为二选一，可与独立慢速缓冲组合；未要求同一白条同时做收缩和淡出叠加模式。
- 回血时默认直接同步相关尾条可避免残留伤害，但这只是候选常规策略，由方案比较并记录，不冒充用户已确认的视觉取值。
- 缓冲默认延迟/时长/曲线、模式切换保留或复位、是否使用非缩放时间、文字精度及默认格式，均由方案在上述验收内决定；没有需要用户重复回答的关键产品缺口。
- 不强制所有 radial/任意旋转布局；方案先明确首版所支持的 fill 方向和布局，不能默默缩减对现有 Slider/Image 的兼容承诺。
- 不引入第三方运行时依赖，不自动改既有页面，不操作 Templates~/ParentSnapshot~、版本、发布或消费升级。
- 上个 UI 任务曾有共享动态字体写回，已由用户接受特定现状并归档；这不授权本任务新增写回。文字测试须使用独立 TTF 创建的 FontAsset/atlas/material；共享源/全局字体皮肤必须保护，避免重演该问题。
