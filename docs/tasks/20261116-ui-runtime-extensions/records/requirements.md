# UI 通用运行时能力补齐：需求基线

- 任务：20261116-ui-runtime-extensions
- 修订：R1；2026-11-16，Asia/Shanghai
- 阶段：入口需求澄清；尚未设计、实施或独立验收。
- 来源：当前入口对话，用户要求“先把滚动定位与吸附、文本跑马灯、图片异步加载封装这三项补齐，参考 burner 的实现，按我们框架的规范接入”，并补充询问 ImageEx 的圆角和多图索引切换。
- 已有授权：完成这些能力的框架接入、必要的局部修复、相关增量测试和使用文档。授权随阶段交接，不重复请求实施审批。未授权提交、发布、模板保存/Bump/部署、全量或长时间测试。

## 需求与范围

| ID | 内容 | 性质 |
| --- | --- | --- |
| R01 | 补齐滚动定位与吸附：覆盖滚到头尾、指定 RectTransform/Item 的定位、居中/边缘对齐及偏移、立即或平滑滚动、目标可见性判断、用户滚动结束后的邻近项吸附。API 和吸附触发/回调契约由方案阶段明确。 | 用户确认的能力；细节按 Burner 对照形成方案 |
| R02 | 补齐 TMP 文本跑马灯，支持框架 TMPEx；明确开关、速度、溢出条件和复位方式；正确响应文本、容器尺寸和字体变化，兼容现有裁剪及字体材质。 | 用户确认；具体滚动模式/停顿默认值为方案事项 |
| R03 | 补齐 Image/Sprite 与 RawImage/Texture 的资源地址异步加载封装，复用 Ember 资源后端，提供加载结果及失败处理，管理快速切换、取消、目标销毁、复用和资源所有权；可直接从正式 EUI Binding 使用。 | 用户确认的图片加载封装；覆盖类型来自前轮已接受的功能描述 |

| R05 | 按框架架构、命名、程序集和 UI 中心契约接入；通用能力属于 Packages/com.ember，不依赖任何具体游戏，不引入 Burner 包或其定制 Unity/TMP 依赖。参考源码的行为，不把旧框架整套拷入。 | 用户规范要求及仓库规则 |

## 非目标

- 长列表虚拟化、多模板/网格列表、Tab/Attachment 体系、通用 Tween 系统、MergedImage、镜像、节点截图/模糊/软遮罩。
- 图片圆角扩大到 Sliced/Tiled 的完整支持：用户尚未提出此要求，现有支持范围为 Simple。
- 从消费项目回迁、升级 Burner/Unity/TMP、发布新版本、修改模板快照。
- 不预设必须新增页面或 Prefab；确需正式示例页面时通过 EUI 开发中心生成，禁止手写 Binding。

## 已核对的事实与待方案决定事项

1. EUIImageEx 已有 SpriteArray/SpriteIndex 和自定义 Inspector，不需要另建多图切换组件。当前用 overrideSprite 显示选中项。
2. EUIRoundedImageModifier 是独立 BaseMeshEffect，仅对 Image.Type.Simple 生效；Burner 的圆角同样独立于 ImageEx。圆角运行/网格视觉验证尚未在本任务执行。
3. EmberAssetHandleSlot<T> 已有同槽位加载、去重、取消、重入与 Dispose 入口。EmberAssetHandle<T> 的 Cancel/Complete/Dispose 及 Provider 的释放行为必须核实；这是静态检查关注点，尚未验证缺陷结论。
4. UIExtension Runtime 当前 asmdef 未直接引用 Ember.Resource.Runtime。方案需确认实际程序集名及依赖，不能只因源码可见就直接调用。
5. 正式页面绑定主要返回 Unity/增强组件，不会自动实例化旧 EUIComponent 包装；新能力不能只落在内部无法初始化的封装层。
6. 跑马灯算法、材质或 Transform/网格方案、单行滚动模式、停顿默认值、吸附阈值和索引越界策略由方案阶段依据源码和既有契约决策，明确写出理由；这些不是用户已经确认的具体取值。

当前没有需要用户重复说明的关键需求缺口；上述细节可由方案阶段在已授权范围内确定。
