# AI 阶段交接模板

按[公共工作流规范](ai-workflow.md)使用。完整模式复制下方正文到项目现有临时任务目录；没有约定时使用 `.utmp/ember-workflow/<task-id>/handoff.md`。简化模式只保留适用字段，可在一份记录附需求、方案、实施和自检，不必生成阶段提示词或空表。完成并归档后才清理本任务临时材料，待消费端验收时保留。占位内容均须替换；无、未知、未验证和不适用明确说明，不预填通过。日期使用项目约定时区。

## 下一对话启动文本

```text
接续任务 <ID/名称>，本对话负责 <阶段>。
先读取项目 AGENTS.md / CLAUDE.md、实际 Ember 包内的公共工作流规范，以及 <项目交接记录相对路径>。
按该记录读取 <本阶段必要的需求/方案/实现文件>，核对当前工作区、正式模板身份和有效基线。
本轮完成 <具体任务与验收标准>，保留其他已有修改，按记录的授权范围执行。
沿用记录的执行模式和验收安排，不重新选择模式或接管下一阶段。
完成后更新本阶段成果、交接入口、证据和未完成项，返回任务 ID、阶段/轮次、有效修订、结果及文件索引，由主对话统一调度。
不直接创建下一阶段，不因收到“请汇报”就自行推定有反向发送授权。
若本轮是独立验收，直接核对有效需求和实际实现，逐项记录结果及复现问题。
```

## 适用提示词文件的阶段差异

完整模式需求交接时用上面的启动文本生成适用文件，填入实际路径、任务和回交信息；不预写下游成果。消费端验收可省略本地 04-acceptance.md，改用消费端交接；简化模式不要求这些文件。占位内容不可作为完整交接执行。

| 文件 | 本阶段输入与任务 | 阶段结束时 |
| --- | --- | --- |
| `prompts/02-design.md` | 读取有效需求；核对实际项目，形成接口、资产、步骤及验证方案 | 写入 design.md 和 handoff.md，回交主对话；提议不当作实施授权 |
| `prompts/03-implementation.md` | 读取有效需求和方案，核对授权及前置状态，执行实现、定向验证或指定问题修复 | 写入 implementation.md、证据和 handoff.md，回交主对话；消费端待验收如实保留 |
| `prompts/04-acceptance.md` | 需要独立验收时直接读取需求和实际实现，逐项检查或定向复验 | 写入 acceptance.md、问题和 handoff.md，回交主对话安排返工或收束 |

## 主对话返工派发文本

```text
接续任务 <ID> 的 <实施/方案/验收>，本轮 <轮次>，有效需求/方案修订为 <修订>。
先核对 <handoff.md> 与实际工作区；本轮处理 <问题 ID、受影响 AC>。
预期/实际、复现和证据见 <具体文件位置>，完成 <定向修复或复验>。
沿用已有授权和阶段边界，保留其他修改；不要降低 AC 或自行派发下一阶段。
更新本阶段记录、相关验证和交接后正常结束本轮，主对话将等待结果并继续调度。
```

## 中断或手动交接后的收束文本

```text
接续任务 <ID/名称> 的入口收束，任务目录为 <实际临时路径>。
先读取当前交接和适用的需求、方案、实施、验收或合并记录，沿用模式与验收安排，核对验收后工作区是否变化。
若必需事项均已完成，将有效成果、验收和必要证据收束到 <正式文档位置>，修复对临时文件的引用。
归档验证成功后标记任务完成，核对精确目录及所有权，仅清理本任务临时材料；保留其他任务与无承接内容。
若仍有失败、待验证或待消费端验收项，保持未完成，安排返工或交接，不删除临时证据。
```
