# 多语言中心

入口：`Ember/多语言中心`，所有模板可用。立绘管理是小说模块专属窗口，不属于多语言中心。

## 日常编辑

选择文案表，左侧搜索 Key 或正文，右侧编辑各语言。支持新增 Key、缺译筛选、待复核筛选、Undo 与可拖动的左右分栏。
点击“保存并更新预览”写回 CSV/TSV；绑定了 EmberTableDefinition 的源表同时通过现有配表管线校验、烘焙。
未保存草稿随窗口序列化保留，切表/刷新不会静默丢弃。外部文件变化时，保存拒绝覆盖；请先复制需要保留的草稿，再刷新合并。
源语言改变后条目标记待复核，“标记本条翻译已复核”先保存，再记录确认状态。

## 注册与运行

基础模板包含 `common_ui_text` 示例源表，默认简中、繁中、日文、英文。框架启动时装配通用解析器，无需小说模块。
其他模块通过 `EmberLocalizationSource` 注册 CSV/TSV、主键列、语言列、源语言、用途描述及可选的强类型表定义。
注册资产放 `Assets/Ember/Editor/Localization`；源表放 `Assets/GameResource/TableSources`；生成产物放
`Assets/GameResource/Resources/Config/Localization`。无注册的新项目可以在窗口初始化公共 UI 文案。

所有注册表共用全局 Key 空间，建议使用 `common.*`、`inventory.*` 等前缀。同表/跨表重复 Key 会阻止保存，运行解析器也拒绝重复，不再静默按表优先级遮蔽。
运行解析顺序为目标语言→该表源语言→由调用方回退原文。`EmberLocalization.SetLanguage(language)` 持久化偏好并广播 `LanguageChanged`。
`TMPEx` 继续通过 `ITextLocalizer` 工作。业务仍可以注入自己的解析器；小说用兼容适配器接入旧强类型表，保留既有 Key 和调用接口。

通用源表可以配置任意语言列。绑定强类型 Row 的既有小说表增加语言时，仍需同步 Row、语言清单及小说适配器，不能仅添加 CSV 列。
构建前从所有注册源表更新正式产物，校验失败会阻止构建，避免打包外部编辑后尚未更新的文案。

## 辅助翻译

展开“翻译到其他语言”，配置 Chat Completions 兼容服务的完整 URL、模型和 API Key。
密钥只在窗口内存中保留，关闭窗口/脚本重载后重新填写。使用 HTTPS，本地回环服务允许 HTTP。
接口格式参照 [Chat Completions API](https://developers.openai.com/api/reference/resources/chat)。

选择本次源语言和目标语言，可仅补齐空白，也可生成已有译文的新版本。请求发送当前文案、相邻文案、表用途与填写的术语上下文。
服务返回后展示新旧文本，可修改译文再应用到草稿。变量占位符、富文本标签和换行不一致时拒绝应用；请求后源条目变化时拒绝旧结果覆盖。
请求可取消，有超时，失败不修改表格。应用后仍需复核和保存。没有配置翻译服务时，全部本地编辑功能照常可用。

## 实现归属

框架：通用运行解析、语言偏好、源表草稿、多语言编辑器、翻译适配。
基础模板：公共文案源表、注册和生成数据。小说模板：小说表注册、旧接口适配、立绘管理。
模板只能通过项目中心的加载、保存、Bump 与父级同步流程更新。
