# 玩家运行、配置与持久化契约

本文描述 platformer-2d 当前实现；操作入口见[使用工作流](PlayerWorkflow.md)。代码位于 `Assets/Game/Module/Player`、`Entity`、`SceneFlow` 和 `PlayerCamera`。通用 FSM/转场归 Ember 包，具体玩家规则不进入 UPM/base。

## 所有权与生命周期

Entity2D 是归属根，Motor/Sensors/Facing/Powers/Effects 是可组合能力，不要求所有 Entity 同时具有刚体/FSM；不存在为本模板新增的全局 EntityManager。PlayerController 组合本角色 Context 与能力，PlayerModule 是唯一 Update/FixedUpdate 驱动。SceneScope/参与者负责准备和交接，不另 Tick 玩家。

Gameplay 准备先取得输入/存储服务与目标场景 Scope，按显式参与者顺序准备必要对象；全部必要内容就绪后才能显示完成并启动。交互输入在过渡完整消失后开放。候选与旧会话有独立所有权和世代，取消、过期结果或旧 Dispose 只能释放自己拥有的资源。

Update 推进游戏秒资源/效果并采样输入。FixedTick 更新物理检测与支撑机会、开始 Motor 指令步、父先子后执行 FSM、结算竖直运动并提交物理，再衰减输入窗口；实际顺序以 PlayerController 为准。观察窗口不能额外采样、Tick、求值 Guard 或消费输入。

暂停统一冻结 FSM、玩家刚体和游戏时间，关闭玩法输入，不全局暂停音频。嵌套句柄最后释放才恢复首次暂停前倍率和运动数据；停止会清理会话持有的全部句柄。Controller 局部暂停是内部协调，不是另一种供业务选择的暂停策略。

## 完整方案与冻结 A

PlayerConfig 拥有正式 Scheme 引用和 Scene/Spawn 环境字段。PlayerScheme 引用图、Feel、Powers、输入接线、动画、动作效果及规则配置；布局与存储根不属于方案。已绑定方案时不逐字段回退旧装配；旧版资产只在显式兼容路径中按完整旧装配运行。

Gameplay 初次准备通过 PlayerSchemeCapture 捕获方案 A，冻结图结构、有效手感、能力定义、方案动作效果、动画映射和有限规则计划。每宿主独立创建状态、资源、效果、输入和 AnimatorOverrideController。原位恢复保留本会话 A，仅恢复快照进度；编辑 B 后恢复不偷换成 B，新的 Gameplay 或开发重启才取得 B。

运动值分别由 Movement/Jump/Input 唯一持有，次数/CD与开放由 Powers 持有；动作效果从方案 ActionEffects 按节点捕获，旧 Definition 序列化效果不作为第二来源。PlayerSchemeWorkflow.Copy 复制可变配置闭包，基础图、无可变配置的 Definition、Controller/Clip/Sprite 保留共享引用。规则配置独占且指回所属 Scheme，复制、比较、恢复、校验、保存共用现有工作流。空白方案关闭可选机制/能力，规则附加条件重置恒真。

CaptureDefinition 当前仅特殊复制地空冲刺的捕获效果；其他 Definition 复用为纯声明对象。新增可变字段必须显式纳入捕获与配置所有权，不能假设自动冻结。美术资源仍为 Unity 对象引用：冻结映射不承诺运行中原地重写同一 Clip/Texture 的字节对旧会话不可见，换图优先新资源和新 Play。

编辑器观察来源标识只读且不序列化，不参与运行配置选择、资源提交或保存比较。内置只读保护覆盖其配置闭包；自定义方案仍需检查共享引用。配置编辑支持 Undo/Redo，绘制不保存/迁移/应用；保存方案、保存 PlayerConfig 默认引用、保存模板是不同写入目标。

## 输入与动作资源

输入通道和 Action 名由方案唯一配置。跳跃请求跨 Update/FixedUpdate 锁存一次，新的按下刷新缓冲，不排队；暂停/禁用清空旧请求。预检只查询，最终 Enter/Begin 才提交已有输入和资源，失败预检不消费。地面/土狼/缓冲普通起跳优先于空中扩展；只在有效普通起跳提交时补二段跳，单纯落地和恢复不凭空补它。

Entity 的 Ability 是启用/开放/次数资源，Skill 在相同基础上带 CD；启用、开放与当前可用不能混为一项。每宿主进度独立；玩家特有落地补充只补明确配置的次数，不清 CD。一般能力使用说明见[公共 Powers](../../Module/Entity/Powers/README.md)，玩家动作说明见[玩家 Powers](../../Module/Player/Powers/README.md)。

效果逐次拥有独立身份与句柄。Owned 随动作持有，正常冲刺结束释放后可创建独立 Timed 尾随，打断不产生尾随。保护类别和碰撞排除显式配置；外观按优先级及同级较低透明度组合，不因此取消其他保护规则。详见[Entity Effects](../../Module/Entity/Effects/README.md)。

## 完整快照与恢复

当前业务快照版本为 v2，保存 Scene、位置/速度/朝向、能力开放/剩余次数/CD、效果装配和可恢复 Timed 剩余时间/规则。同步接受请求时冻结，异步磁盘写入期间继续运动不会改变已接受内容。只在成功保存完成后更新会话恢复目标；失败、取消、迟到或其他会话结果不覆盖目标。

首次保存前的恢复目标为本次新游戏初始快照；从槽位进入使用实际读入快照。普通 Save 不暂停。保存退出先整体暂停，接受保存并 Drain 已接受写入后转 Main；失败保留会话并释放本次暂停，不自动丢弃失败。无新增保存退出也必须 Drain，OnDestroy 不能替代异步退出流程。

Recover/LoadCheckpoint 通过公共原位准备→启动→可交互链替换玩家，保留世界和 Gameplay 模块。候选准备不改变旧玩家；整体暂停的同步提交区内才绑定物理、效果、表现与状态。启动失败清理候选并恢复旧绑定；成功后旧所有者不能停止新会话，相机只在完整交接成功后收到通知。

不保存 FSM 对象/叶子身份、Animator 时间、输入缓冲、墙跳窗口、碰撞豁免或瞬时动作阶段。恢复按位置、速度和实际支撑重新选择合法状态：上升可走 Jump 的恢复路径，但不重复发射或消费；首次支撑只建立基线，不算新落地补资源。旧 v1、缺能力/效果定义、不匹配装配及非法值严格拒绝并保留原档，不隐式迁移、补资源或回退新游戏。

动作中拒绝保存：普通/重落地停顿、翻滚、冲刺、下穿未完全离开平台、挂边/翻越、踩头反弹上升阶段。无恢复适配的 Owned/OwnedThenTimed 效果也拒绝；不能静默漏存。独立 Timed 尾随按接受时剩余时间恢复，不续接冲刺。新状态若改变可恢复性，必须明确接入捕获拒绝或新增兼容协议，不能只在 UI 隐藏按钮。

## 物理与扩展限制

下穿只豁免本角色与目标单向平台的碰撞对，多拥有者租约保留原过滤并在停止/转场释放。挂边/翻越使用静止实体墙顶和扫掠路径，候选几何采用保守包围盒，单向/移动平台不在首版支持范围。踩头要求显式静止轴对齐 BoxCollider2D 头部 Trigger、下降从上方穿入与当步请求，不是通用敌人/伤害系统。翻滚由真实落地与水平输入触发，不增加单独按键、碰撞体缩小、自动保护或独立 Ability。

落地 ImpactSpeed 来自接触前最后一轮 Motor.ExecuteStep 后记录的向下速度，不是整个下落过程最大速度，也不承诺是物理引擎施加重力后的碰撞瞬间速度。首次支撑仅建立基线；普通落地与重落地阈值、翻滚优先关系须结合真实步序理解，不能用空中位置直接推导触发。

PlayerCamera 是独立适配模块，Player 不依赖 Cinemachine 类型。Editor/Odin、开发场景桥接和运动轨迹不进入运行程序集；发行构建是否真正排除开发资产需在实际 Build 验证，源码/依赖检查不能替代产物验收。
