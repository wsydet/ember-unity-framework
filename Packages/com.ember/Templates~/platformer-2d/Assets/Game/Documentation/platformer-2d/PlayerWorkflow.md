# 平台玩家使用与开发工作流

本文属于 platformer-2d 及合法派生模板。统一入口是 **Ember → Player → 玩家开发工具**，窗口保留“手感白盒／玩家配置”两页。无关模板隐藏入口；所属模板关闭 Player 模块时显示不可用原因并保留草稿。包内存在模板快照不表示项目已经部署该模板。

## 从部署到试跑

1. 消费项目通过项目中心选择部署策略，先保护业务修改；升级框架不会自动升级已部署业务模板。开发仓库通过正式加载取得编辑身份，当前工作区已加载时无需重复加载。
2. 打开玩家开发工具，在“玩家配置”选择完整 PlayerScheme。内置“空洞骑士风格／蔚蓝风格”只读，先“复制为自定义”；风格名称是调校方向，不是原作参数复刻。
3. 按动作/机制、运动、能力、效果、动画、Prefab 表现/碰撞定位本次参数。单位采用世界单位 u、u/s、u/s²及游戏秒；机制启用、默认开放和当前资源可用是三个不同条件。必要错误与依赖提示始终可见。
4. “手感白盒”选择下次 Gameplay 使用白盒，明确应用编辑方案与出生位置/速度，再播放。正常经过 Init → Main → 新游戏/继续 → Loading → Gameplay；不直接运行白盒场景绕过准备链。
5. 观察实际 Game 画面、状态图和运动曲线。修改后新会话或明确重启生效；重启会结束整个 Play 并新建开发存档库。停止播放后确认编辑草稿仍在。
6. “保存当前完整方案”只保存方案配置闭包。将方案设为项目默认是独立 Undo 操作，再显式保存 PlayerConfig；不因试跑或复制自动设默认。框架作者的普通模板保存、Bump、提交、发布与消费升级分别处理。

## 四种方案身份与写入目标

| 身份 | 含义 | 改动生效方式 |
| --- | --- | --- |
| 当前编辑方案 | 窗口中选择的实际资产及未保存编辑 | Undo/Redo 修改资产内存，显式保存才落盘 |
| 下次白盒方案 | 本机开发设置中已经应用的方案、出生位置/速度 | 下次 Play 捕获；不改项目默认 |
| 项目默认 | PlayerConfig.Scheme，正式新 Gameplay 的装配入口 | 显式设默认与保存；正式场景不使用白盒出生参数 |
| 运行冻结方案 A | 当前 Gameplay 首次准备捕获的完整配置 | 编辑不追溯改变；同会话恢复仍用 A，重启/新会话取得新配置 |

内置只读状态是资产所有权，不是运行状态。自定义方案可能仍共享图、Definition、美术；复制完整方案会复制可变配置，保留这些共享对象。改共享图或素材前查所有引用者。“恢复为参考”写回已有目标配置并支持 Undo，不等于还原模板快照；比较与绘制不会自动保存、迁移、应用或重启。

## 参数与已有机制

基础移动、普通跳跃和下落组成必要底座。Movement 管理地面/空中速度、加速/刹车/转向、冲刺、下穿、挂边、落地与翻滚；Jump 管理起跳/重力、短跳、二段跳、墙面和踩头；Input 管理缓冲与土狼。具体字段和依赖见[手感参数参考](../TemplateSkills/ember-platformer-tune-feel/references/parameters.md)，不要从历史状态 Definition 读取已迁出的运动参数。

- 地面可即时或加减速响应；空中可继承地面或独立设置。Accelerate/Decelerate 是真实叶子，表现切换不会额外执行水平运动。
- 普通跳跃支持输入缓冲、土狼和互斥短跳策略。顶点减重、下落倍率/限速、自然离地悬停及起跳早期水平响应分别配置；估算高度不等于真实物理轨迹。
- 二段跳、墙滑/踢墙、地空水平冲刺、下穿、挂边/翻越、落地停顿/重落地、自动落地翻滚、主动踩头均已有实现，先考虑选配。八方向冲刺、移动平台挂边和完整战斗不属于现有能力。
- Powers 管装配启用、开放、次数/CD；Feel 不维护第二份资源真值。ActionEffects 是方案级动作效果唯一来源。只读源码条件、动作提交及清理由原有状态拥有。

诊断、旧草稿、比较/恢复、素材副本及正式流程隔离验收位于高级区域。使用旧草稿需显式选择/应用，不能把保留的旧 Feel 草稿当成完整运行方案。

## 白盒、保存与暂停

白盒位于 `Assets/Game/Development/Scenes/PlayerFeelLab.unity`，使用正式 PlayerBlock Prefab 与同一 PlayerModule 驱动。默认不进入发行场景列表。每次 Play 在 `Library/PlayerFeelLab/<会话标识>` 建立独立存储，同次 Play 的 Main/Continue 使用该库；正式 GameplayScene 与真实存储不被白盒选择改写。

背景网格使用一个无光照 Quad 与 `GameResource/Player/Whitebox/PlayerLabGrid` 材质。世界原点周围覆盖 2048×2048 单位，1 单位细线、10 单位主线，交点附近显示 X/Y 世界坐标；数字表示坐标，不是本次移动距离。原点轴单独强调，线条宽度按屏幕像素计算，缩小时淡出过密细线与小字。网格及数字由 Shader 生成，无贴图、字体对象、碰撞体或逐帧更新脚本。该范围有限，需要更大场地时可显式调整背景面的尺寸；当前数字支持四位坐标。不要缩放关卡或玩家来改变标尺单位。减少渲染对象不等于已经证明所有设备上的 GPU 耗时改善，性能结论仍需目标设备实测。

普通保存接受完整快照后世界继续运行。设置、保存退出和恢复由模块协调整体暂停，音乐和非缩放 UI 继续；暂停句柄可嵌套，释放本句柄不解除其他暂停。恢复输入清除旧触发，持续方向可重新采样。保存成功更新会话恢复目标，首次保存前使用本次初始完整快照；读档失败不回退新游戏。详见[运行与持久化契约](PlayerArchitecture.md)。

“正式流程验收（新隔离存档库）”在高级区域，只替换本次测试存储，仍走正式场景流程。它不是发行入口，也不是替代真实消费部署或构建的证据。

## 相机与表现

白盒相机由独立 PlayerCamera 适配层使用 CameraManager/注册器管理，在玩家成功交接后绑定玩家根为 Follow/LookAt；失败候选不改变当前镜头。首次交接与恢复跳变清除旧相机状态，释放/退出清除引用。当前基线为 WorldSpace 偏移 (0,1,-10)、正交尺寸 8、位置阻尼 0、固定朝向；参数直接在已有 Cinemachine 组件上编辑。已配置而无效的白盒相机在准备阶段报错，未配置该适配的正式场景保持原行为。

Prefab 为物理根 → Visual 朝向层 → Animation → Sprite。动画只改 Sprite 子树视觉，禁止根运动、碰撞/Sensors、朝向外层和效果 alpha 曲线。换图保持现有物理尺寸；默认 BoxCollider2D 为 1×1.75，不能自动按图片轮廓拟合碰撞。PPU、轴心和视觉偏移必须在真实地面及左右朝向下检查。

## 蓝图、规则与扩展

从窗口“状态图”进入公共 FSM 蓝图，选择真实运行实例观察活动路径、逻辑时间和真实尝试记录；未评估/短路不等于条件为 false。源码/Definition/参数定位基于真实节点，画布引用不是新增状态。手动布局按本机图身份保存，自动布局必须显式触发，不因打开、刷新、切方案或 Play 重排用户坐标。

转换规则的目标、阶段、顺序和提交行为来自代码声明。有限规则编辑只开放 air 的 air-jump、wall-slide、ledge-hang 三个入口的**附加条件**，见[规则与扩展](PlayerRules.md)。旧方案保留旧版代码模式，显式等价迁移才创建恒真附加条件；配置模式丢资产、版本非法或规则错误必须报错。
