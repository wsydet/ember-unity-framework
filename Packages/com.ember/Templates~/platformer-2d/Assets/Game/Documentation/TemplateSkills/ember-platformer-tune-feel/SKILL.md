# 平台玩家手感调整

先读取项目 AGENTS.md、CLAUDE.md 及其适用规则。唯一运行配置仍来自实际 PlayerScheme；不要为调手感改图身份、存档或包版本。

## 开始与发现

1. 连接实际 Unity 项目，核对 `Application.dataPath`，调用 `Ember.Core.Editor.EmberProjectSetup.GetTemplateSkillExecutionBlockReason("ember-platformer-tune-feel")`。非空时停止业务写入，说明原因并通过项目中心修复；没有 Unity 连接时只做可证实的只读分析。
2. 按 [操作与验证](references/workflow.md) 核对正式模板身份、Player 模块开关及真实 API 能力。合法派生模板按有效身份判断，不强求模板 ID 等于来源标签。清单版本下限不能替代业务能力检查。
3. 区分窗口当前编辑方案、下次白盒方案、PlayerConfig 项目默认及运行冻结方案；保留未保存草稿、场景和蓝图布局。优先使用用户指定方案，否则读取窗口选中项，不静默改为默认方案。
4. 展示紧凑功能总览：基础移动/跳跃/下落；地面加速/刹车与独立空中控制；缓冲/土狼/短跳/顶点与下落重力/限速/边缘悬停/起跳响应；二段跳/墙面/地空冲刺/下穿/挂边翻越/落地与翻滚/踩头反弹；能力次数/CD和可选效果。根据当前资产标记启用与新游戏开放，运行可用性另看当前实例，不能用开关代替。只展开本次相关类别，字段见 [参数与依赖](references/parameters.md)。

## 候选与执行

- 将用户目标转成“真实资产与字段、原值→候选值、单位、预期变化、副作用、依赖”。用当前数值和运动计算估算起点；只问会改变选择的缺失信息，尊重已有授权，不逐字段重复确认。
- “更利落”通常先看起步、刹车、转向和输入窗口；“更轻飘”先分清是延长上升、顶点停留还是减慢下降。不要把所有开关一起打开，也不声称复刻某游戏的精确参数。具体推导见参数参考。
- 内置只读方案先用 `PlayerSchemeWorkflow.Copy` 建完整独立自定义副本；自定义方案按用户意图原地修改或另存，先查共享配置。复用 `Configuration/Validate/Compare/Save`，保持效果、动画、规则所有权。常规改值使用 SerializedObject 与 Undo，不手改 YAML 或创建另一套 JSON 运行配置。
- 保存资源、应用到下次白盒、重启、设为项目默认是不同动作。只执行任务已授权的动作；调参不自动设默认。当前会话与恢复候选仍使用冻结 A。
- 使用正常 Play → Main → 新游戏进入白盒，读取真实运动曲线并与同条件基线比较。记录输入、固定步长、方案和作用机制；基础公式、Jump 状态片段、完整滞空实测分别标识。碰撞、动作优先级和最终观感以 Unity 为准。

## 交付

给出改动表、方案资产路径、保存/下次试跑/默认状态、实测结果和体验入口。未执行的实测明确保留，不以编译或公式代替体验验收。本技能采用统一 Unity 窗口与白盒，不生成浏览器物理模拟；取舍和测量方法见操作参考。
