# 视觉小说图片导入与配表

把用户指定的图片变成项目可用资源。图片分析只提供建议；图片归属和角色身份必须由用户确认，确认前不复制、移动、修改导入设置或配表。

## 开始前

- 确认实际 Unity 项目根目录和 MCP 连接实例，读取项目规则。通过 Unity MCP 调用 `Ember.Core.Editor.EmberProjectSetup.GetTemplateSkillExecutionBlockReason("ember-vn-import-images")`。返回非空原因时停止写操作，报告原因并指向项目中心的模板技能预览/同步。API 缺失意味着框架不支持此工作流，不能凭目录存在跳过。无 MCP 时可查看图片、保存选择草稿和准备方案，不能声称已完成导入。
- 读 [项目映射与配表](references/project-mapping.md)，核对目标项目的实际表定义、源文件和资源布局。兼容继承此 Skill 的派生模板：以正式安装归属检查为准，不强制当前模板 ID 等于 `visual-novel`。
- 只处理用户指定的文件或目录范围。读取图片本身，检查尺寸、透明通道及可见内容；不能只凭文件名判定。看不到图时明确说明并让用户指定类型，不假装完成分析。

## 本地交互确认页面

必须先读并执行 [确认服务操作说明](references/confirmation-workflow.md)。本技能随附 `scripts/confirmation.py` 和 `assets/confirmation.html`，用本机回环 HTTP 服务生成页面，并把草稿/确认/取消写入本批 `.utmp/vn-image-import/<批次>/`。不得用静态图片总览或 `request_user_input_async` 代替此页面；工具调用成功不等于页面已打开，更不等于用户确认。

1. 扫描指定范围、实际查看图片、读取真实角色表与表定义。AI 建议可写入 suggestions JSON；没有建议的图片默认跳过。所有预填均为草稿，不能当成用户决定。
2. 启动服务，**实际打开返回的 URL**，检查页面标题、图片加载和控件可见，再将可点击 URL 与批次目录交给用户。打开失败时报告具体错误并修复，不宣称“确认页面已展示”。不要在实际素材批次中代替用户点击“确认导入”、直接调用 confirm 接口或制造 confirmed 文件。
3. 用户在页面逐图选择立绘、背景、其他用途或跳过，填写剧情、已有/新建角色、角色 ID/显示名、表情/变体、场景名。批量操作只影响勾选的图片，仍可逐图调整。保存草稿后刷新可恢复；未保存选择不能保证恢复。
4. 页面生成最终计划，列出资源 ID、目标路径、Resources 路径、拟修改表行、已有引用与冲突策略。当前最小实现支持更名、同内容且同绑定复用、跳过；不同内容替换会阻断。确需覆盖时另行展示完整影响并重新确认，不能擅自把策略改成覆盖。
5. 只接受本批 `decision.json` 的 `status=confirmed`，并运行 `verify` 成功，才进入执行阶段。`draft`、`pending`、`cancelled`、无文件、超时、关闭页面或聊天提问无回复均不授权导入。取消为终态，禁止继续本批。用户说已提交也应读取结构化回执，不能从截图猜测选项。
6. 用户尚未提交时保持任务等待确认，或明确告知“页面已打开，等待提交，尚未导入”后让用户返回当前任务继续；保留服务和批次，不把工作标为已完成。无需假设页面能主动唤醒 Codex。已提交后仍重新核对 Unity MCP 与正式技能身份；无 MCP 时只能浏览和保存草稿，页面明确禁用确认导入。

其他用途包含标题 UI、CG、图标、遮罩等，目前只生成资源复制计划、不自动接线或写入小说背景表。CG 需现有背景指令播放时，应解释这一语义并由用户在页面选择背景。项目改动过资源布局或表结构时先适配映射，不能通过忽略校验强行导入。

## 确认后执行

- 执行前运行确认脚本 `verify --work <本批目录>`，读取其完整计划并再次调用 MCP 身份闸门；通过后才备份和写入。批次源文件、配表、表定义和既有资源指纹由服务在展示前记录，确认提交与执行前均复核。路径或表内容在确认后变化时重新展示差异，不能套用旧确认。拒绝越出项目受管资源目录的路径、`..`、非法文件名和链接路径；重复资源键按实际表的唯一性检查。
- 默认复制外部原图、保留原件。项目内资源需要移动时使用 Unity `AssetDatabase.MoveAsset` 保留 GUID；已在正确路径的资源不重复复制。不自动抠图、裁剪、缩放、重压缩或换画风。立绘没有透明背景时在确认清单中提示，请用户决定是否原样导入。
- 同名同内容且表行一致时复用，重复执行不增加行。不同内容/不同绑定时让用户选择新 ID/文件名或跳过；本页面不支持不同内容覆盖，不得执行计划以外的替换。备份受影响的图片、`.meta`、CSV 及将改变的生成产物到项目 `.utmp/vn-image-import/<批次>/`，不放在 Resources 或技能发现目录；备份不得被本批覆盖。
- 经 Unity MCP 导入图片。立绘/背景设为 Sprite、Single，保留原图尺寸和透明度，参考同用途资源的设置；不要批量改无关平台压缩配置。校验 `AssetDatabase.LoadAssetAtPath<Sprite>` 能得到资源。
- 按引用顺序更新 CSV：需要时先新增角色，再新增立绘；背景只改背景表。使用支持 CSV 引号、逗号和换行的解析/写入方法，保留无关行和稳定 ID。导入后经既有配表 API 校验、烘焙，见映射文档；禁止手工修改 bytes 或生成 C#。
- 本批图片、源表、烘焙共同算作完成。中途失败时停止后续写入，按备份恢复本批改动；只有当前文件仍等于本批写出的指纹时才自动恢复或移除本批新文件，出现其他修改时保留备份并报告人工恢复项。不要声称跨图片与配表天然具备事务原子性，也不要删除原始素材或用户并发修改。

## 验证和交付

检查角色外键、资源 ID 唯一性、每个 Resources 路径加载到 Sprite、表校验与烘焙结果。只导入资源，不擅自把图片插入现有剧情节点、不改默认剧情、不清存档。Unity 自动刷新、编译和测试只通过 MCP，遵守项目的失败停止规则。

结果逐图报告：导入/复用/跳过/失败，角色与表键、落盘路径、烘焙结果和备份位置。区分静态检查、Unity 资源加载和实际画面验收；未烘焙不能称为配表完成。模板作者的源修改留在 Assets，通过正式 SaveTemplate → Bump 才能随模板交付，不直接写包内快照或 hash。AI 客户端部署技能后可能需要新会话；每次执行仍重新检查模板身份。
