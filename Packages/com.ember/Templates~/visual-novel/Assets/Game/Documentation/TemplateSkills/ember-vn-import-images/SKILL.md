# 视觉小说图片导入与配表

把用户指定的图片变成项目可用资源。图片分析只提供建议；图片归属和角色身份必须由用户确认，确认前不复制、移动、修改导入设置或配表。

## 开始前

- 确认实际 Unity 项目根目录和 MCP 连接实例，读取项目规则。通过 Unity MCP 调用 `Ember.Core.Editor.EmberProjectSetup.GetTemplateSkillExecutionBlockReason("ember-vn-import-images")`。返回非空原因时停止写操作，报告原因并指向项目中心的模板技能预览/同步。API 缺失意味着框架不支持此工作流，不能凭目录存在跳过。无 MCP 时可查看图片、收集确认和准备方案，不能声称已完成导入。
- 读 [项目映射与配表](references/project-mapping.md)，核对目标项目的实际表定义、源文件和资源布局。兼容继承此 Skill 的派生模板：以正式安装归属检查为准，不强制当前模板 ID 等于 `visual-novel`。
- 只处理用户指定的文件或目录范围。读取图片本身，检查尺寸、透明通道及可见内容；不能只凭文件名判定。看不到图时明确说明并让用户指定类型，不假装完成分析。

## 交互确认

优先使用当前 AI 客户端的选择框工具。Codex 中可用 `request_user_input_async`：每张图片给出自包含的问题和建议选项，提交后等用户实际回答再做依赖操作；预选值、超时、无回复不是确认。不以 Unity 阻塞式模态框代替客户端提问。客户端没有选择框工具时，明确说明并以编号选项等待文字确认。

1. 展示图片缩略图或可点击路径、简短分析。询问“这张图片用作什么？”选项为“角色立绘”“场景背景”“其他用途”“跳过”，将建议类型排在首位。透明人物、完整横向环境只是判断线索，不是硬规则；带人物的场景图也可能是背景。
2. 立绘：从实际角色表列出候选 `displayName (id)`，提供“新建角色”；询问所属角色、表情/变体和所属剧情。不能通过外貌猜定角色。用户说“主角1”时先匹配已有名称，重名时展示 ID；不存在则收集并确认新角色显示名和建议的稳定 ID。不得擅自复用样例的林晚、alice 等角色。
3. 背景：确认所属剧情、场景名和时段/变体。不追问无关角色信息。
4. 其他用途：询问是剧情 CG、UI 图标、遮罩/特效贴图还是其他。只有用户确认 CG 使用现有背景指令播放时才按背景配表。其他类别按实际用途提出路径和已有配置接入点；没有对应表时明确说明，不硬塞进立绘/背景表，不擅自创建新表或新业务系统。
5. 展示完整导入清单：源图片、类型、剧情、角色 ID/显示名（如适用）、表情、资源 ID、目标文件、Resources 路径、将新增或修改的表行，以及同名冲突。提供“按此导入”“修改信息”“取消”。如果前面的选择框已包含这些具体信息且用户已明确确认，直接执行，不重复确认同一方案。

批量导入按每张图记录决定，允许用户明确将相同角色/剧情应用到选定的一组。不能把第一张的确认扩展到所有图片；未确认的图片保持待处理。无需重新询问用户已经明确提供的字段，但仍让用户确认最终归属和落盘方案。

## 确认后执行

- 先记录源文件、目标和受影响源表的指纹；提交前复核。路径或表内容在确认后变化时重新展示差异，不能套用旧确认。拒绝越出项目受管资源目录的路径、`..`、非法文件名和链接路径；重复资源键按实际表的唯一性检查。
- 默认复制外部原图、保留原件。项目内资源需要移动时使用 Unity `AssetDatabase.MoveAsset` 保留 GUID；已在正确路径的资源不重复复制。不自动抠图、裁剪、缩放、重压缩或换画风。立绘没有透明背景时在确认清单中提示，请用户决定是否原样导入。
- 同名同内容且表行一致时复用，重复执行不增加行。不同内容/不同绑定时让用户选择新 ID/文件名、明确替换或跳过；确认替换前展示原引用和影响。备份受影响的图片、`.meta`、CSV 及将改变的生成产物到项目 `.utmp/vn-image-import/<批次>/`，不放在 Resources 或技能发现目录；备份不得被本批覆盖。
- 经 Unity MCP 导入图片。立绘/背景设为 Sprite、Single，保留原图尺寸和透明度，参考同用途资源的设置；不要批量改无关平台压缩配置。校验 `AssetDatabase.LoadAssetAtPath<Sprite>` 能得到资源。
- 按引用顺序更新 CSV：需要时先新增角色，再新增立绘；背景只改背景表。使用支持 CSV 引号、逗号和换行的解析/写入方法，保留无关行和稳定 ID。导入后经既有配表 API 校验、烘焙，见映射文档；禁止手工修改 bytes 或生成 C#。
- 本批图片、源表、烘焙共同算作完成。中途失败时停止后续写入，按备份恢复本批改动；只有当前文件仍等于本批写出的指纹时才自动恢复或移除本批新文件，出现其他修改时保留备份并报告人工恢复项。不要声称跨图片与配表天然具备事务原子性，也不要删除原始素材或用户并发修改。

## 验证和交付

检查角色外键、资源 ID 唯一性、每个 Resources 路径加载到 Sprite、表校验与烘焙结果。只导入资源，不擅自把图片插入现有剧情节点、不改默认剧情、不清存档。Unity 自动刷新、编译和测试只通过 MCP，遵守项目的失败停止规则。

结果逐图报告：导入/复用/跳过/失败，角色与表键、落盘路径、烘焙结果和备份位置。区分静态检查、Unity 资源加载和实际画面验收；未烘焙不能称为配表完成。模板作者的源修改留在 Assets，通过正式 SaveTemplate → Bump 才能随模板交付，不直接写包内快照或 hash。AI 客户端部署技能后可能需要新会话；每次执行仍重新检查模板身份。
