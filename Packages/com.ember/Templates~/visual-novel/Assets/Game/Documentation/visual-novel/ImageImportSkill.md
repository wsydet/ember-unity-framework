# 图片导入 Skill

新增唯一技能 `ember-vn-import-images`，源文件为 [SKILL.md](../TemplateSkills/ember-vn-import-images/SKILL.md)，登记在 `../TemplateSkills/catalog.json`。本次只实现用户指定的图片导入工作流，没有另加剧情创作或其他技能。

用法示例：“把这几张图片导入项目，这是主角1的素材。”AI 先实际查看图片，再通过客户端选择框确认立绘/背景/其他用途。立绘选择已有角色或新建角色，确认表情、剧情分组和落盘清单后，再复制资源、设为 Sprite、更新源 CSV 并通过既有配表管线烘焙。选择框由 AI 客户端提供；客户端不支持时退为编号文字确认，不是新增 Unity 编辑器窗口。

角色表、立绘表和背景表分别沿用 `novel_characters`、`novel_portraits`、`novel_backgrounds`。UI 图片等没有对应小说表的类别明确报告接入边界，不为凑齐配表擅自扩展 schema。重复导入复用已有内容，冲突需要具体确认；外部原图保留，批次备份位于项目 `.utmp/vn-image-import/`。

## 新项目验收

先修复/确认 MCP 清单预览，审查当前模板差异，再通过正式 SaveTemplate → 显式 Bump 封存。使用包含本地技能系统和新模板快照的框架包，在隔离新项目完整部署模板；仅安装旧发布包或仅升级包不等于部署新模板。客户端重开会话发现技能后测试下列场景，勿在当前视觉小说副本来回切模板。

| 输入或操作 | 应观察到的行为 |
| --- | --- |
| 一张主角1立绘，表中不存在该角色 | 查看图片，确认立绘、新角色名称/ID和表情；最终确认前资源/CSV不变；确认后角色和立绘各新增一行，Sprite可加载，烘焙成功 |
| 已有角色的新表情 | 显示实际角色候选，复用角色 ID，只新增对应立绘行 |
| 一张场景图 | 确认剧情/场景/变体，写 Backgrounds 和背景表，不追问角色 |
| 多张不同类型图片 | 逐张或按用户明确分组确认，不把第一张决定套用全部 |
| 类型改选“其他用途”或取消 | 进一步确认实际用途；取消时没有图片或表写入；UI图标不进入小说表 |
| 同一批重复导入 | 不重复复制、不重复增加表行 |
| 同名不同图、已有资源键、确认后改动源表 | 展示具体冲突或要求重新预览，不静默覆盖 |
| 模拟烘焙失败（隔离夹具） | 不报告完成；恢复本批图片/表/产物，保留用户并发修改及备份 |
| 未部署对应模板或会话残留 | 身份检查阻止业务写入，指向正式部署/同步流程 |

以上为待执行验收场景，不是已通过的测试报告。真实导入需要用户提供图片与归属确认，不拿样例或当前项目素材代替用户的选择。
