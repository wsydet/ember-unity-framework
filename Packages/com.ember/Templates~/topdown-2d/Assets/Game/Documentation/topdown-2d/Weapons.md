# 武器状态机与装备边界

攻击归属于 `Game.Player.Weapons` 中的武器会话。Player负责移动、瞄准、冲刺、生命及输入许可，`WeaponDefinition`持有自己的Graph、攻击参数与Powers。每个装备者捕获独立 `WeaponSpec`、`WeaponContext`、`WeaponRuntime`，即使引用相同源武器，也不共享状态实例、冷却、次数或命中去重集合。没有把战斗能力提升到base。

默认武器图是 `ready → windup → active → recovery → ready`。每个转换使用E01声明和FixedUpdate请求站点；前摇Enter才提交该武器的 `fire` Skill，并捕获本击方向。active跨越很短的物理窗口仍能发出命中；近战每个攻击实例对每个Entity至多命中一次，射线每次攻击只发射一次。预检拒绝不消耗，打断不退款。玩家图不需要知道具体攻击阶段。

训练剑锁住移动及朝向，控制租约归本把武器持有；训练手枪不取得移动租约，可同时走动、瞄准和射击。射线从角色根起算，不越过实体墙，只选择最近敌人，友方和自己不受伤；表现使用短暂黄色射线。示例是即时射击，没有实现飞行弹丸、穿透、追踪、弹匣、换弹、自动连射、背包拾取或掉落，这些可以沿武器边界扩展。

`WeaponLoadout`首版是固定装配列表、单个当前武器（上限16个），不承担背包。Q/左肩键切换；项目也可调用 `PlayerModule.TryEquipWeapon(id)`，仅在有控制许可、稳定移动、非暂停且无进度操作时允许。切换取消旧武器动作和残留命中，释放旧控制租约；每把武器的资源保留，收起时仍推进冷却，不推进其动作图。死亡、受击、角色冲刺或其他互斥角色动作会中断当前武器。暂停冻结角色、武器图、资源时钟与身体，清掉旧输入；恢复按住键不补发旧攻击。

PlayerModule仍是唯一Update/FixedUpdate入口。武器不含MonoBehaviour Update，不自行读取ActionMap，不独立写刚体或结算伤害。玩家输入转为攻击意图，武器图决定是否提交/何时发出命中，场景战斗会话统一收集并稳定结算。`IWeaponActor`只提供朝向、操作许可和可选控制租约，NPC可用自己的适配器接入同一武器协议。

角色扩展动作取得控制时，可先中断当前武器所持租约；不释放其他角色/项目所有者的控制。武器预检在外部控制租约存在时拒绝，不消耗资源，也不能反向抢占。Focus与挥剑的组合已单独覆盖，不要求每个新增角色状态自行猜测武器清理细节。

正式资源在 `Assets/GameResource/Resources/Config/Weapon/`。玩家开发工具列出装配列表，并能打开每把武器自己的蓝图/参数；运行观察器分别列出玩家与各武器的真实实例、路径和资源。源图与冻结图通过ObservationOrigin关联，观察不执行条件或驱动时钟。复制玩家方案会深复制武器Definition、图、状态定义、Powers和Skill，并分配新武器ID；默认示例的两个玩家方案可以共享不可变源武器，但运行宿主始终隔离。

新增武器时，创建新的 `WeaponDefinition` 与面向 `WeaponContext` 的图。可复用四阶段 `WeaponStateDefinition`，或编写自己的 `EmberFsmStateDefinition<WeaponContext, ...>` 与E01站点；首版图以ready为稳定入口。扩展状态通过Context提交资源/开始攻击、发出命中、结束自身控制所有权，不调用PlayerModule主循环。新命中模式或弹丸需要扩展武器发射/场景结算协议；不要把它们重新塞回玩家Attack状态。引用额外可变SO时同时补充捕获、独立复制和进度协议。

快照v2同时保存当前武器稳定ID、装配顺序/集合及每把武器资源；恢复前严格验证身份与资源装配，候选失败不改变旧武器或旧玩家。只在角色idle/move且所有武器ready时接受保存。读档从ready恢复资源，重试使用检查点记录的武器与资源基线；不复活未完成攻击。v1仅为未发布开发格式，本轮明确拒绝，不自动写回或覆盖旧档。
