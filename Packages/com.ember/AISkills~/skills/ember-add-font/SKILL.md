# Ember 添加字体

完成“导入字体 → 登记配置 → 接入实际使用处 → 验证显示”的闭环。不能只把字体加入列表后让用户逐个给控件配置。本技能属于框架公共技能，不依赖模板名称、小说模块或固定页面清单。

## 确认目标和已有机制

读取目标工程的代理规则及实际解析的 com.ember 源码。字体写入用户指定工程的业务资源；不修改 Library/PackageCache 或模板快照。从 UnityFarm 发现的改动先按包内 Documentation~/maintenance/unityfarm-change-routing.md 分流。

确定字体文件、目标皮肤/用途及作用范围。用户已给出文件和范围时直接执行；缺少字体文件时请求路径，不能自行下载替代字体。默认“添加字体”按新增皮肤接入当前项目跟随全局皮肤的文字，保留当前默认皮肤；明确要求立即使用时再切换默认或指定使用处。用户要求在现有皮肤增加标题/正文选项时，按该用途接线；用途无法从请求或已有映射确定时，只询问这项语义，不要求逐个指定控件。

先读取 [字体接线接口](references/font-wiring.md)，核对目标版本中的真实 API。检查项目字体库、TMP 设置、字体资源、UI Prefab、场景、皮肤选择界面和运行时创建/赋字体代码。搜索 TMPEx、SetFontForSkin、SetFontSkin、EmberFontSkins、TMP_FontAsset、fontSharedMaterial、font、FontSkinId 等相关符号并追踪调用方。

## 导入和登记

- 复用同一源字体已有的有效 TMP_FontAsset；新增源字体放在项目已有字体资源目录，缺少约定时放 Assets/GameResource/Fonts/<字体名>/。通过 Unity 导入及当前 TMP API 创建 SDF、材质和图集，不能手写 asset YAML 或伪造 GUID。动态字体保留可用于构建的源字体引用；按实际语言需求设置图集策略并检查缺字，不照搬另一字体的参数。
- 使用项目级 EmberFontSkinCatalog；缺少时使用现有 CreateProjectCatalog 入口创建项目副本，不改框架默认库。保留原有稳定 ID，新 ID 使用计数器并检查冲突，不重排或重用旧 ID；代码名必须可生成合法枚举且不重复。
- 新增整套皮肤时，依据原有语义槽位建立映射；只有一个新字体时，可让新皮肤中所需的正文/标题等槽位都指向它，但图标、符号等专用字体保留原用途。不要为了加一套皮肤就给所有皮肤新增冗余槽位。
- 往既有皮肤增加独立字体选项时，仅增加所需槽位及该皮肤映射，不要求所有皮肤拥有所有槽位。明确替换已有选项时更新其 Font，保持槽位 ID，让已有引用统一生效。
- 调用现有 SaveAndGenerate 保存配置和生成枚举；不手改生成的 EmberFontSkinIds.cs。相同请求再次执行应复用已有字体、皮肤和槽位，避免重复项。

## 自动接入使用处

建立并执行批量接线清单，记录资源路径、组件层级、皮肤 ID、槽位 ID、修改前后值与跳过原因。

1. 遍历授权范围内的 Prefab 和场景，包括非激活子物体、弹窗、列表 Item、输入框文字/占位符及下拉框模板。不能只处理当前打开的场景或运行中的对象。
2. 新皮肤需要为范围内跟随全局的 TMPEx 调用 SetFontForSkin(新皮肤 ID, 对应槽位 ID)。按已有语义/旧皮肤映射保留标题、正文和图标的差异。已有皮肤新增选项时，为匹配用途的控件更新该皮肤映射。不能仅写 font：下一次 ApplyFontSkin 会把它覆盖。
3. FontSkinId 为 -1 的固定字体、指定其他皮肤的控件及已有特殊材质默认保留，并列出原因；用户明确要求它们参与时才转换/调整。普通 TMP、Legacy Text 或 UI Toolkit 不共享 TMPEx 映射，按它们实际机制接入或报告不适用。不要为“添加字体”擅自全项目转换组件。
4. 对只由代码创建、初始化时覆写字体的文字，同步更新实际工厂或配置源，保证后续新实例生效。项目已有字体选择下拉框/设置菜单若使用硬编码清单，补齐真实选项和对应 ID；动态读取库的界面无需重复造一份列表。没有选择界面时不要扩展任务新建界面。
5. 持久化 Prefab 源资源和必要的场景覆盖。优先处理基础 Prefab，再检查变体/嵌套实例，避免制造大量相同 override。用 PrefabUtility 加载、保存并在 finally 卸载；场景编辑保留原打开状态，不丢弃用户未保存内容。保留文本、多语言 Key、字号、布局、Binding 和无关皮肤映射。
6. 改字体需核对材质是否匹配其图集。默认材质可跟随新字体；描边/阴影等自定义材质需保留效果并适配，不能继续引用旧字体图集。只改字体引用不需要重新生成 EUI Binding；若确需转换组件，使用项目现有转换及 EUI 生成入口并核对引用。

新增的是缺字回退字体时，按请求添加到实际主字体的 fallback 链，避免重复和循环；不要把回退字体直接指定为所有文字的主字体。

## 验证与交付

保存后重新加载资源：验证 Catalog.Validate，并逐个核对目标控件的 GetFontSlotForSkin 与 Catalog.TryGetFont，确保映射能解析到预期字体。库的 Validate 通过不能证明控件映射完整。检查运行时初始化不会恢复旧字体，重复执行不会再新增同一配置。

通过 Unity MCP 刷新并做一次有界编译确认，再验证切换新皮肤、切回原皮肤、非激活控件重新启用及动态生成 UI。抽查目标语言、标点/符号、长文本的缺字和布局；临时预览后恢复原状态，除非用户要求将新字体设为默认。

MCP 不可用或首次失败时停止编译验证，不用日志轮询、BatchMode 或 dotnet build 替代。可交付一次性 Editor 接线入口及静态检查，但没有执行和回读证据不能声称已经接线。涉及资源或代码改动且未验证时明确告知：本次未完成 Unity 编译验证。请在 Unity 中手动触发编译；若仍有报错，请提供首条编译错误及完整堆栈。

交付字体与配置位置、实际更新的 Prefab/场景/代码数量、保留项和验证结果。新增皮肤但未设默认时说明使用方式。只有目标使用处已接入，才称为添加完成；待执行部分明确列出。
