# Ember Odin 面板风格记录

用户需指定已认可的脚本/面板；目标缺失时询问目标。读取目标脚本及关联 Drawer/基类，核对实际 Unity/Odin 版本与用户认可的效果。仅源码推断不代表面板已经渲染验证，不自动运行按钮中的业务动作。

## 找到项目记录位置

优先使用用户指定文件或项目现有面板规范。没有既有文档时，已授权记录可创建项目自有 `docs/dev/odin-usage-notes.md`。文档放在当前项目中，不写技能安装目录、框架依赖、PackageCache 或模板快照；这样个人风格不会被技能更新覆盖。

## 提取与核对

- 提取分组、字段展示、按钮布局、列表与动态条件等模式，保留能解释效果的最小示例；不复制产品业务逻辑、项目私密数据或大段无关代码。
- 对照已有项目记录：已有模式不重复；新模式说明适用场景、组合方式、来源文件和局限；与旧建议矛盾时并列记录证据并指出待验证，不能静默把旧结论改成新禁令。
- 区分视觉风格、正确性约束和特定版本历史观察。一个面板满意不能证明某种特性组合普遍兼容，也不能据此批量替换其他脚本。
- 记录序列化/展示差异与公共 API 边界：ShowInInspector 计算属性不等于可替换成 SerializeField，public 字段也可能有业务调用方。
- 完整示例要保留必要特性与分组路径，并使用项目相对来源链接。记录观察时的版本/验证方式，未验证项明确标注；不得将本地绝对路径或观察结果回写为技能本身的固定规则。

只分析时展示候选内容；已明确要求保存/记录时更新文档，不逐条重复请求批准。保留用户未提交文档，检查重复条目与链接并报告新增/冲突内容。后续若使用面板检查技能，优先读取同一项目文档；不要求预装其他技能，也不因记录风格自动修改脚本。
