## 3. 结构与生命周期

已确认六个核心职责单元。这里的“模块”指职责划分，不要求全部实现为 IEmberModule 或全局 Manager；下列类名与具体装配仍是拟实现方案。

| 核心单元 | 边界与复用 |
|---|---|
| 存档模块 | 单局剧情快照、槽位、全局已读与偏好；明确读写结果与恢复边界 |
| 读表模块 | 复用 Table 读取角色、立绘表情、场景背景、音频等配置；将稳定业务键解析成资源信息，再交 Resource 加载 |
| 运行器模块 | 统一管理流程节点调度、段内指令执行、变量、选择、推进、暂停与恢复 |
| 对话执行资源 | 对话段 SO 保存线性指令；选择 SO 保存选项与分支目标；仅保存定义，不保存本局运行状态 |
| 音频模块 | 覆盖 BGM/SFX/Voice 的播放、停止、等待与分类音量；复用并按需补充通用音频能力 |
| 流程可视化编辑器 | 编辑 SO 内容、选项与节点连接，展示路线并校验；Play Mode 下观察玩家执行位置与等待原因，只在 Editor 使用 |

运行器内部区分“下一段播什么”的流程调度与“这一段怎么播”的指令执行，不必拆成两个全局模块。背景、立绘、文字及过渡由演出层承担，运行器不直接包办 EUI 操作。

| 单元 | 职责 | 生命周期 |
|---|---|---|
| NarrativeModule | 管理阅读会话、剧情加载、运行器与演出协调 | Gameplay Phase 的可选 IEmberModule |
| NarrativeRunner | 纯 C# 流程调度、段内指令解释、变量、分支和推进状态 | 由 NarrativeModule 持有，可独立测试 |
| 小说配表接入 | 角色与资源键查询，复用 GameTableModule/EmberTable 能力 | 配置就绪纳入会话 Ready；具体装配待定，不重复创建读表框架 |
| 对话段 SO / 选择 SO | 运行内容和连接的权威定义 | 资产数据；运行器读取，播放不改写 |
| 小说音频适配 | BGM/SFX/Voice 的执行、停止、完成与音量 | 会话内适配通用音频 Manager，具体持有关系待定 |
| 流程可视化编辑器 | SO 编辑、连线、布局、校验与运行观察 | 独立 Editor 程序集，可观察 Play Mode；窗口不进入 Player 构建 |
| NovelPresentation | 背景、角色、文字、音频适配；执行和恢复演出 | 阅读会话内持有资源与页面引用 |
| NovelSaveModule | 存档索引、读写结果、全局已读与偏好 | Global Phase，供主菜单和阅读页访问 |
| EUI 页面与 Item | 显示、收集输入、发出意图 | 由 GamePages 注册并按页面生命周期释放 |

Module 使用现有发现与 Phase 机制；新增 Module 必须显式声明 EmberModule 的 Phase 和 `Enabled = true/false`，不得依赖 Enabled 默认值，配套编辑器入口服从该开关。业务查询通过 Collector，不能用访问 Instance 的方式强行创建被禁用模块。Manager 不依赖上述业务类型。

GameGameplayState 传入 NewGame 或 LoadSave 请求；模块初始化、配表加载、页面打开和资源准备可能先后完成，因此需要显式 Ready 条件，不能假定 OnGameplayEnter 后页面立即可用。状态暂停不自动停止活动 Module 的 Update，会话必须显式检查暂停原因。
离开 Gameplay、重新开始或读档时取消旧会话任务并递增会话代次，丢弃旧资源回调；所有页面订阅、资源 Handle 和音频播放句柄明确释放。

## 4. 剧情数据与编辑

### 4.1 SO 节点与切段规则

首版采用“段落级流程图 + 对话段内有序指令列表”。选择前后的对话分别存入独立 SO，选择本身也存入另一种 SO。图的粒度跟随叙事分支，不把每句台词、每次换立绘都铺成流程节点。

| SO 节点 | 保存内容 | 后续连接 |
|---|---|---|
| 对话段 SO | 稳定 nodeId、内容修订、连续台词与演出指令 | 一个后续节点 |
| 对话选择 SO | 稳定 nodeId、选择提示、选项列表；每项有稳定 optionId、显示文本及可选出现条件 | 每个选项分别保存目标节点，可指向同一目标 |
| 条件分流 SO | 稳定 nodeId、有序条件分支列表，各分支有稳定 optionId | 按顺序取首个满足项，必须配置兜底目标 |
| 结局 SO | 稳定 nodeId、endingId | 显式正常结束，无后继 |
| 章节出口 SO | 稳定 nodeId，标识本章的一个出口 | 在剧情 SO 中配置该出口的有序条件路线与必填兜底章节 |

```text
相遇对话 SO → 选择 SO：如何回应？
                  ├─ 询问来意 → 询问对话 SO ─┐
                  └─ 转身离开 → 离开对话 SO ─┤
                                            ↓
                                       汇合对话 SO
```

对话段播放结束将控制权交回流程调度；选择节点等待玩家选择合法选项，再进入对应目标。用户已确认独立条件分流 SO 和结局 SO：条件按顺序首个命中，未命中走必填兜底；只有结局 SO 正常终止，普通断链报错。改变路线的逻辑统一属于流程层，不在段内再维护 Choice/If/Jump。

分支边界优先切段；较长直线剧情可以按场景、时间或叙事段落拆成顺序连接的 SO。短小分支允许单独存在，不强制凑长度。节点间允许汇合。

### 4.2 数据所有权与稳定标识

SO 是内容和连接的唯一权威数据：对话段保存后继，选择与条件分流保存各分支目标。章节 SO 保存入口、节点清单与局部变量定义；章内节点直接引用同章节点 SO，不跨章共用。剧情 SO 保存所有章节、剧情入口、全局变量和章节出口的条件路线。到达独立章节出口才按其路线顺序选择首个满足条件的下一章，未命中走必填兜底；普通结局节点始终结束整部剧情。

2026-09-17 用户明确将原“首版章节隔离”扩展为两级结构：章内连线仍限制在本章，跨章连线只存在剧情层。运行时从 SO 生成会话内纯数据副本，不另存路线。总览和各章各有一个 Editor 布局 SO，只保存所属资产 GUID、稳定卡片 ID、坐标，放在 `Assets/Game/Module/Narrative/Editor/Layouts/`。窗口使用内置 GraphView 与 IMGUI 内容表单，不新增插件；运行时不依赖窗口或布局。

保留 chapterId 作为章节/流程组织标识，增加稳定 nodeId 定位对话段或选择；段内每条指令有 commandId，选项有 optionId，文本有 lineId，角色有 characterId。ID 不随重排或图上移动改变；复制内容生成新的对应 ID。存档不使用列表下标、节点坐标或 Unity 实例 ID。

SO 只保存定义。当前节点、指令位置、选择结果、变量和已读状态由运行器/存档持有，不在播放时改写 SO。纯 C# 运行核心与 Unity 资产读取适配分离，便于用纯数据测试。

角色、立绘表情、场景背景和音频通过稳定业务键查询配表。配表记录资源映射，Resource 负责加载；具体表结构、资源路径与 Provider 在实现前确定，不能将编辑器能读取资产视为构建后可用。

### 4.3 段内指令与校验

| 指令 | 关键数据 | 完成条件 |
|---|---|---|
| Say | lineId、角色、文本、可选配音键 | 等待用户、自动或快进推进 |
| SetVariable | 变量 ID、类型、值 | 赋值完成 |
| Background / Character | 资源键、槽位、表情、位置、过渡时长 | 过渡完成或按快进规则落到终态 |
| BGM / SFX / Voice | 资源键、音量/循环等参数 | 以指令声明的播放/等待语义完成 |
| Wait | 时长 | 计时完成；暂停时冻结 |

变量首版支持 bool、int、string，并由定义声明类型与默认值。条件与赋值显式选择 Chapter / Global 作用域，同名变量可以分别存在，不隐式遮蔽。全局变量属于一次新游戏会话，跨章保留；每次进入章节都重新初始化该章局部变量。章节间路线只能读取全局变量；章内选择、条件分流与 SetVariable 可访问两种作用域。条件使用 All/Any 与显式比较，不解释代码。现有资产未保存作用域的字段默认 Chapter，保持旧章节语义。序列化使用列表，运行会话使用独立字典。

校验至少覆盖：空/重复 ID、入口或连接目标缺失、选项未连接、未声明或错类型变量、缺失角色/配表键/资源，以及没有可用选项的情况。普通对话节点断链报错，仅结局 SO 表示正常终止。M1 校验配表键和资源路径非空，实际资源存在性/类型及加载失败由 M2 接入 Resource 后验证，不将有路径等同于资源存在。运行时仍要处理条件筛选后零选项、资源加载失败及坏目标。
允许有意的循环连接，但每轮限制连续即时指令与节点跳转的总步数，超过阈值停止并报告 chapterId/nodeId/commandId（选择处提供 optionId），避免空段循环绕过保护。错误呈现可返回主菜单，不无限重试。

### 4.4 流程可视化编辑器

首版必须能在图中创建或选取对话段 SO、选择 SO，编辑段内内容及选项文字/条件，并从每个选项的输出端口连接后续 SO。连线修改直接写入对应 SO 的目标；重新打开图或在 Inspector 修改后，图与 SO 必须一致。支持顺序连接、分支、汇合、断链提示和错误定位。

窗口默认进入当前剧情的章节总览，章节卡显示全部已登记章节及出口路线，双击进入章内画布；“章节总览”返回上层。选中节点默认显示“对话内容”，台词完整换行呈现，展开条目编辑角色、文字或演出参数；“SO 设置”集中显示所属章节、稳定 ID、修订与后续节点以及节点管理操作。指令 ID 和台词修订折叠到“标识与修订”。运行诊断可折叠，不挤占作者阅读台词的首屏。

节点移动只修改布局；内容编辑、连线、断线与删除操作需支持保存及撤销/重做。删除节点应检查入链并提示处理，不能无声破坏引用。窗口负责内容制作与运行观察，实际播放始终由同一运行器读取 SO 定义，不在窗口中另建一套执行逻辑。

基础流程图已纳入首版，取代旧方案“只做章节列表、图编辑延后”的范围。通用自由节点编程、任意 C# 表达式、新脚本语言和编辑时实时回放仍延后；追加的节点静态画面预览不执行剧情、音频或时间轴，不等于实时回放；不使用每句台词一个流程节点的模型。

### 4.5 运行观察与问题定位

首版流程窗口同时支持静态内容编辑与 Unity Play Mode 下的运行观察。运行观察直接显示当前玩家会话的真实状态，用于回答“现在执行到哪个 SO、段内哪条指令、为什么没有继续”。这里的运行时查看指本地 Unity Editor 中观察 Play Mode，暂不包含连接独立 Player。

| 观察内容 | 窗口行为 |
|---|---|
| 当前执行位置 | 高亮当前对话段/选择 SO，显示名称与稳定 nodeId；对话段同时高亮 commandId 对应指令，选择阶段不伪造段内位置 |
| 跟随与定位 | 提供“跟随执行”开关和“定位当前 SO”操作；关闭跟随可自由查看其他节点，浏览选中项与实际执行位置分别显示 |
| 执行与等待状态 | 显示运行器状态、阅读模式、文字显示/点击/配音/选择/资源/过渡等等待原因，以及独立的暂停原因集合；可能同时存在多个原因 |
| 当前变量 | 只读查看当前会话的类型化变量值，帮助判断分支条件；不通过窗口修改变量 |
| 错误定位 | 展示错误摘要和 chapterId/nodeId/commandId 或 optionId，定位对应 SO/指令；资源错误附相关业务键。无法解析资产时仍显示 ID，不跳到无关节点 |

观察信息必须来自运行器及会话演出协调层的只读快照/通知，不能从图中选择、UI 是否可见或编辑器计时猜测。运行侧保留不依赖 UnityEditor 的最小诊断契约；Editor 适配负责解析 SO、绘图及订阅清理，依赖方向仍为 Editor → Runtime。

窗口打开时立即读取当前快照，之后随状态变化更新；诊断带会话代次，读档、重开或退出 Gameplay 后不接受旧会话通知。关闭或重开窗口不得创建新会话、重复订阅或改变运行结果。未运行、无活动会话、已结束与已故障需明确区分；如保留最后错误，必须标明它属于已结束会话，不冒充当前执行位置。

首版 Play Mode 中内容和连线为只读；允许浏览、缩放、查看详情与定位，不通过观察窗口推进、回退、改变量或保存运行状态到 SO。该能力不是编辑时回放，也不自动增加断点、单步或任意跳转。关闭窗口后游戏仍正常运行；观察窗口不得成为运行器的生命周期所有者。

### 4.6 Fungus 参考与采用边界

参考原版 Fungus 的 [Flowchart/Block 组织](https://github.com/snozbot/fungus/wiki/flowcharts)、[Block 执行跟踪源码](https://github.com/snozbot/fungus/blob/master/Assets/Fungus/Scripts/Components/Block.cs) 和 [Say 摘要及完成回调](https://github.com/snozbot/fungus/blob/master/Assets/Fungus/Scripts/Commands/Say.cs)。采用其块内指令编辑、可读摘要和执行位置跟踪思路；等待原因与变量观察按本模板运行器契约设计。

Fungus 的 Block 属于场景组件体系，不能等同于本方案的独立 SO。这里仅借鉴制作和排错体验，保留 Ember 的 SO 数据、运行状态分离及现有 EUI/资源/配表体系，不引入插件依赖。其 [Menu 的隐藏/禁用选项](https://github.com/snozbot/fungus/blob/master/Assets/Fungus/Scripts/Commands/Menu.cs) 可供后续讨论，本轮不自动加入选项禁用提示；存档仍按本方案恢复演出快照，不改成依赖作者逐个补恢复事件的方案。

## 5. 推进与演出规则

运行器状态建议为 Preparing、Executing、Revealing、AwaitingAdvance、AwaitingChoice、Restoring、Ended、Faulted；暂停是独立原因集合，不靠页面是否可见推断。

- Revealing 时第一次继续只补全文字，不能同次点击跨到下一句；下一次继续才推进。
- 输入统一转成 Advance、AutoToggle、SkipHeld、History、QuickSave、QuickLoad、HideUI 等意图；同一帧只消费一次推进。
- 打开设置、历史、存档或确认弹窗时屏蔽底层意图并暂停会话；关窗恢复此前模式。多弹窗用暂停原因计数/集合，避免关闭一层就提前恢复。
- 隐藏对话框时暂停自动和快进，再次操作先恢复显示；隐藏对话 UI 不隐藏背景与立绘。
- 自动播放等待文字显示结束和配音完成，再加配置间隔；无配音按文字量计算最小阅读时间。遇到选项停止等待。
- 已读快进只跨越已读 Say，遇到未读句或选项停止；过渡落到终态，Wait 缩短或跳过，音效/配音跳过，BGM 保留最终曲目。变量与分支仍按正常逻辑执行且只执行一次。
- 句子完整显示时记录已读；历史只追加一次，恢复快照和重绘页面不重复追加。历史首版仅查看，不做回滚。
- 演出串行调度，明确可取消和落到终态的操作；UI 动画时间、剧情等待与全局 Time.timeScale 分开，模态暂停由会话控制。

## 6. 存档与恢复契约

### 6.1 保存边界与内容

首版只在 AwaitingAdvance（当前句完整显示）和 AwaitingChoice（选项准备完成）保存。过渡、资源加载、恢复期间禁用保存并给出状态提示；快速保存也遵循同一规则，不悄悄保存旧进度。自动存档在进入可保存点后按章节/选择策略触发，不在每帧写盘。

快照至少包含：schemaVersion、storyId、storyRevision、chapterId、nodeId、停顿类型、分别标识作用域的全局/局部变量列表、背景键、立绘槽位与表情/位置、BGM 状态，以及有上限的本局对话历史。对话停顿点额外记录 commandId 与完整台词标识；选择停顿点记录选择 nodeId、合法 optionId 列表。槽位元数据包含时间、章节/摘要、版本和可选缩略图。会话全局变量随槽位恢复，不能与账号级已读/偏好混用；恢复当前章节必须采用槽位内局部变量，不能套用正常进入章节的初始化流程。M3 工作副本已实现写盘和稳定点恢复；具体已实现字段见 §16，实际验收边界见 Implementation 当前收口清单。
当前已完整显示的句子读档后继续等待，下一次推进进入下一条；选项读档后重新显示相同合法选项，不能重复执行该节点之前的副作用。

配音恢复默认停止，不追求恢复采样位置；BGM 恢复曲目和循环状态，可从头播放。若以后要求精确时间恢复，另行扩展格式与验收。

全局已读、用户设置与未来解锁记录单独保存，加载旧槽位不得回退它们。全局已读用稳定 lineId 加文本修订标记判断，改写后的台词视为未读。
手动槽不会因退出自动被覆盖；自动槽和快速槽使用独立标识。默认关闭的 PlayerDataModule 不与 NovelSaveModule 同时负责同一份剧情数据，避免退出钩子覆盖手动存档。

### 6.2 恢复顺序

1. 读取并校验 schema/story 修订、流程节点/指令/选项 ID、变量与配表资源键；未知版本或缺失目标明确拒绝，不静默重置存档。
2. 在临时数据中解析目标章节、SO 节点、配表与必要资源。失败时保留当前会话和原存档，可取消读档。
3. 候选会话进入 Restoring，屏蔽推进输入；原会话暂停保留，提交前不取消或释放原会话。将变量与演出快照交给候选会话，准备资源时不影响原画面和音频。
4. 候选会话完成全部校验和资源准备后提交交换，重建背景、立绘、BGM、当前对话/选项；不重播之前的 SetVariable、音效或解锁动作。
5. 成功交换后释放旧会话，退出 Restoring，默认回到手动阅读。提交前失败/取消释放候选会话并恢复原会话；提交后若出现无法恢复的页面/音频错误，释放会话、提示错误并返回主菜单，保留存档，不承诺回滚原会话。具体已确认边界见 §15。

章节改动后仅在稳定 ID 与校验仍兼容时接受旧档；否则需要显式迁移映射或提示不兼容。段内列表重排与图布局改变不应单独导致存档失效；拆分/合并 SO、删除节点或改变选择语义时需要单独评估兼容性，不能仅凭 ID 仍存在就接受旧档。

### 6.3 写盘可靠性

现有 DataSaver 是同步 JSON 写盘且 Save 不返回成功结果，不能直接向玩家保证写入成功。存档实现需有明确结果、临时文件写入、替换/备份与损坏处理；异常时保留原有效文件，UI 仅在成功后更新槽位。先限定桌面目标验证实际文件系统行为。
大截图与大量历史不应随每次小数据保存阻塞主线程；缩略图是附属数据，失败不应破坏剧情快照。通用写盘 API 是否提取到框架，在该阶段根据实际复用范围决定。

## 7. UI、输入与音频

复用主菜单状态与 EUI 路由，新增阅读主页面、选择 Item、历史弹窗、存读档弹窗和结局页；扩展设置页的文字速度、自动间隔、BGM/SFX/Voice 音量。所有页面经 GamePages 注册，业务不散落 Prefab 路径。
背景与立绘归演出层管理，UI 负责显示与意图，不在按钮回调里实现剧情跳转或直接改变量。
输入首版覆盖鼠标继续、键盘确认、快进与菜单；弹窗输入与剧情输入互斥，快速存读档避免重入。具体键位在实现输入资产时记录。

音频适配需要单路可停止的 Voice、配音完成通知和独立音量。先复用现有 BGM/SFX，验证音量行为；通用淡入淡出和播放句柄若进入 EmberAudioManager，应保证现有调用兼容并补对应回归。不得把旁白角色、台词 ID 或剧情变量放进通用 Manager。

## 8. 最小样例与验收目标

样例包含两名角色、多个背景/表情、至少一次变量影响的选择和两个结局；使用占位资源，包含有配音/无配音句子和简单转场。
完整链路：主菜单 → 新游戏 → 对话 → 选择 → 保存 → 返回菜单 → 继续/读档 → 对应分支结局。
重点验收快速重复点击、弹窗暂停、未读快进停止、选择前后读档、资源加载中退出、重复进出 Gameplay，以及新项目部署后直接运行。
同时验收流程窗口能定位当前 SO/指令及实际等待原因；中途打开、关闭重开、关闭跟随、读档换会话与停止 Play Mode 后，观察状态准确且不影响玩家进度，不产生 SO 内容修改。
具体阶段完成标准见 [实施清单](Implementation.md)，本方案本身不代表这些用例已通过。

## 10. M1 实际实现与边界

本节记录 M1 首次交付；M1E 已补齐创建/复制 ID、窗口订阅及 Play Mode 观察，多章节与模块开关扩展见 §11～13。下文的 17 项测试为 M1 历史证据，当前交接以实施清单的收口表及最新 44 项报告为准。

- 代码归属：仅本模板项目 Assets；未发现本阶段必须修改的框架 API。运行核心位于 `Assets/Game/Module/Narrative`，不创建全局 Manager，NarrativeModule 的 Gameplay 接线留给 M2。
- SO：`NarrativeChapterSO`、`NarrativeDialogueSO`、`NarrativeChoiceSO`、`NarrativeBranchSO`、`NarrativeEndingSO`。章/节点/选项 ID 为显式序列化字符串，创建时提供 GUID 初值；指令/台词 ID 在 M1 手动填入。列表重排不生成新 ID；复制 ID 冲突由校验拒绝，自动复制修复待 M1E。
- `NovelChapter` 等纯数据定义只保存在内存；SO 适配器复制指令/条件/变量，运行器维护独立字典与位置。`contentRevision` 和 `storyRevision` 只保存正整数元数据，本阶段不承诺旧档兼容，也未实现迁移。
- 条件为平铺 All/Any；空条件表示无条件。int 支持六种比较，bool/string 仅等于/不等于；字符串使用 Ordinal 比较。SetVariable 是严格同类型赋值，不隐式转换、不解释表达式。
- `NarrativeRunner` 执行 Say/SetVariable/Wait、选择、条件分流和结局。Say 先 Revealing，完成显示后 AwaitingAdvance；一次输入只完成一次状态推进。宿主传入帧号、会话代次和位置版本；旧输入、同帧重复推进、重复选择和取消后的回调被拒绝。
- 连续即时指令与节点跳转共用默认 1024 步预算，空段循环同样受限；预算可在构造时调整。暂停使用每个拥有者独立的 token 集合，Wait 只消费宿主传入的有效时间；关闭一层不解除其他暂停。
- 诊断包含状态、等待标志、独立暂停原因、会话代次、稳定执行位置、只读变量/合法选项、错误与结局。位置版本只因执行变化更新；暂停通知不废弃尚在等待的完成令牌。通知期间拒绝重入，观察者异常不改变剧情结果。M1 阅读模式固定 Manual；Restoring、Auto/Skip 的真实行为及窗口订阅生命周期在后续阶段实现。
- Background/Character/BGM/SFX/Voice 目前只有资源键与演出等待接口。未接演出层时保持等待，不能自动视为播放成功；具体槽位/位置/透明度/音量/循环参数将在 M2/M4 完善，不将这些指令列为 M1 已验证演出。

### 配表实现决定

沿用 ResourcesProvider、Table 的 Definition → ETBL/Binding/Catalog → GameTableModule.Database 流程。新增 `Game.Table.Runtime` 程序集包住 Row 与生成目录；小说运行程序集只引用表与框架，不反向引用 Assembly-CSharp。

| 表 ID | 字段 | 当前源数据 |
|---|---|---|
| novel_characters | id、displayName | alice/小艾、lin/阿林 |
| novel_portraits | id、characterId、expression、resourcePath | 仅表头，M2 添加占位立绘 |

### 目录规范

```text
Assets/GameResource/Resources/Config/Narrative/<剧情名>/
  Story.asset
  Chapters/
    CH01_<章节名>/
      Chapter.asset
      Dialogue/CH01_<章节名>_<段落名>.asset
```

按需创建类型子目录，不建立空目录。章节显示名和文件前缀可分别编辑；前缀只用于随后创建的文件，不自动批量重命名现有资产。现有资产整理必须先预览，再用 AssetDatabase.MoveAsset / RenameAsset 保留 GUID；不得重新生成稳定 ID 或以路径作为运行标识。章节显示顺序采用剧情 SO 登记顺序，目录编号只是作者阅读辅助。

每个剧情和章节的布局仍在 Editor/Layouts，由各自资产 GUID 命名；保存的键分别为 chapterId / nodeId，不保存运行连接。总览按章节登记顺序网格排布，章内按连接分层，二者均可撤销。

### 执行和编辑契约

- NarrativeStorySO 的章节出口配置包含源章节、出口 SO、有序条件路线与兜底章节；目标必须登记在同一个剧情中。章节出口只标识位置，不重复保存路线。
- 在章内创建出口时同步到所属剧情；Project 中手工创建/修改出口后使用“同步章节出口”。失效或重复出口由剧情校验报错，不静默删除作者条件。
- 退出章节与进入下一章在同一运行器内完成，维持会话代次、位置令牌、输入帧保护及暂停集合；跨章循环与章内即时指令共用同一次 Drain 的步数预算。
- StartStory 在开始前验证全部已登记章节与路线；独立 Start 仍支持没有章节出口/全局变量依赖的旧章节。普通 Ending 不进行章节跳转。
- 总览运行时高亮当前章节，跟随不会自动强迫作者进入二级画布；点击“定位当前”进入当前 SO。快照分别提供 StoryId、GlobalVariables 与原有章节 Variables。窗口、章内 Inspector、章节总览与布局写操作均禁止在 Play Mode 修改。
- 移除章节会提示并断开全部跨章入链、移除其出口配置，保留磁盘资产，可撤销。新建文件的撤销仅恢复登记关系，资产文件仍保留，沿用此前约定。

### 缩略图和内容布局

原 MiniMap 在截图对应状态下实际尺寸是 200×200，未采用传入的 160×100；节点与视口边界映射也不符合本窗口需求。新 NarrativeMiniMap 固定为 200×144，将节点与可视视口的联合边界做一次等比映射并留边距，点击定位只更新画布，不写 SO。10% 缩小时视口变大，节点在概览内相应缩小，这是预期行为；两级画布共用实现。

内容页签使用已有表单和真实序列化数据，没有第二套台词副本。默认可见角色/台词全文与指令摘要，参数在条目内展开；SO 设置集中处理 ID、修订、连接与节点管理。选择/分流内容页保留各项条件和目标，因为它们属于这些 SO 的核心内容。

### 15.2 读档失败与会话交换

- 玩家正在 A 进度时加载 B：原会话 A 暂停保留，独立候选会话完成 B 的校验和必要资源准备，准备阶段不抢占原画面/BGM。
- 提交前 B 损坏、不兼容、缺少资源或取消读档：释放候选资源，提示失败/取消，恢复 A；从主菜单发起时保留菜单。原存档不受影响。
- 准备成功才提交切换；成功后释放 A。明确提交边界，防重复读写和旧回调污染，观察显示真实 Restoring/成功/失败状态。
- 提交后若仍遇到无法恢复的页面或音频错误，释放会话、提示错误并返回主菜单，保留存档，不承诺回滚 A，也不长期维持两套可玩的状态。

### 15.3 槽位、自动保存与继续

- 6 个手动槽，由玩家选择保存位置；1 个快速槽，快速保存时覆盖；1 个独立自动槽，不覆盖手动槽。
- 进入新章节、做完选择后，在其后的首个稳定点自动保存：下一句完整显示（AwaitingAdvance）或选项就绪（AwaitingChoice）。不到稳定点不写盘，不在每帧写盘，不以退出自动覆盖手动槽。
- “继续”尝试读取最近一次成功保存的进度；如果该槽损坏或不兼容，提示玩家手动选择其他槽，不自动改读更早的进度。以用户最后看到并接受的明确表述为准，不能实现为过滤坏档后静默挑选更早的兼容档。
- 保存必须有明确成功/失败反馈；写盘失败不显示成功、不更新成功时间。自动/快速保存遵守相同稳定点规则，不能悄悄保存过期位置。

- 演出快照保存当前背景、左/中/右立绘资源键及 BGM。表情由立绘键表达，位置沿用 M2 正式 Prefab 的三个稳定槽位布局；当前没有任意位置指令。只在过渡完成的稳定点保存，恢复直接落到终态。M2 BGM 固定循环，因此 schema 1 记录并校验 loop=true；从头播放，不重播 SFX，无 Voice。
- 候选会话不附着页面、不播放音频，先读取 Story SO、恢复纯数据运行器并准备快照资源。原会话仅增加 RestoreTransaction 暂停。成功时先释放旧会话，再接管真实页面并提交；提交前失败/取消释放候选并恢复原诊断源，提交后不可恢复错误释放会话返回菜单。观察状态增加 Restoring。
- 6 个手动槽索引 0～5，快速槽 6，自动槽 7。章节进入/有效选择增加待自动保存代次，首个稳定点尝试一次；失败反馈而不逐帧重试。手动与快速保存也要求当前稳定点，同槽同帧重复写被拒绝。已有槽覆盖采用页面二次点击确认。
- 存档位于 `Application.persistentDataPath/VisualNovelSaves`。每次先以临时文件＋Flush(true)＋Move 写一个独立槽位快照，再通过临时文件＋File.Replace 提交 `index.json`（保留 `.bak`）；索引提交才代表成功。旧快照与失败留下的未引用快照保留，不自动删除或回退。索引含最后成功槽位指针、UTC 时间、摘要和快照摘要校验；继续只读取该指针，不过滤坏档寻找更旧进度。
- `account.json` 独立保存已读（storyId、lineId、textRevision 组成无歧义键）和阅读/音量偏好。旧槽位不导入账号数据。提供 IsRead/SavePreferences 接口，偏好设置 UI、自动/快进和 Voice 仍留 M4。完整显示时追加本局历史，最多 200 条；恢复/重绘不重复追加，也不把修订后的当前句强行标为已读。单文件读取/槽位写入上限 4 MiB。
- 正式 EUI 由开发中心生成两份新 Prefab/Binding，并追加主菜单继续/读档和阅读页存读档/快存/快读。用户逻辑基于已读取的实际 Binding。生成器默认 PageDef 路径与实际移动目标不一致，本轮修正用户注册区，制作器也保留该修正；没有手写生成字段或 Prefab YAML。

## 17. M4 阅读辅助与配音工作副本

2026-09-18 用户明确授权只实现 M4；不以 M3 待办再次请求授权，不启动 M5。本轮为框架＋模板升级的工作副本开发：扩展现有 NovelSession / NovelSaveModule / EUI 和音频句柄，没有新增 Module、全局事件或平行存储系统。以下是实现语义，实际验证范围见 Implementation 最新记录。

| 指令/状态 | 快进处理 |
|---|---|
| Say | 进入时先查全局已读；未读立即退出 Skip 并正常打字/配音；已读补全后下一帧推进，保留首个稳定点供自动保存 |
| Background / Character | 正常解析并等待资源，然后过渡直接落到终态；包括隐藏，不省略演出状态记录 |
| Wait | 跳过剩余剧情等待，不改全局 Time.timeScale |
| SFX / Voice | 跳过指令，已开始等待的配音资源也不在完成后播放；已播放 Voice 停止 |
| BGM | 正常解析/播放，保留按顺序执行后的最终曲目；仍进入快照 |
| SetVariable / Branch / ChapterExit | 保持运行器原有显式作用域、顺序与一次性副作用，不另行重演 |
| Choice / End / Fault | 结束自动/快进，选项等待玩家显式选择 |

`NovelSession.Reading.cs` 管理阅读模式、文字速度、自动间隔、单路配音等待和隐藏状态。自动不跳过文字或配音；无配音在全文显示后等待至少 0.5 秒或每 20 字一秒，再加用户间隔。手动补全仍只补全，下一次推进停止旧配音。按住快进在未读处停止后不会因该句随后标成已读而自动重新启动，需要新的按下或按钮操作。

暂停沿用集合，弹窗通过 `AcquirePause(reason)` 获得唯一且可幂等释放的 IDisposable；同名的两层拥有者不会合并。历史、存档、覆盖确认和设置分别持有令牌；原有 ReaderModal、GameplayOverlay、Loading 等原因保留。隐藏对话也独立暂停，保留之前的模式，首次恢复显示不在同帧继续自动推进。快进键在弹窗期间释放会取消 Skip，不在关闭弹窗后意外续跑。

Say 使用既有 ResourceKey 作为可选 Voice 键，正文与 Voice 可以同时播放；自动等待二者完成。独立 Voice 指令串行等待本路自然结束，`NovelSession.StopVoice()` 可显式停止；不新增跳过副作用的剧情命令。无配音键正常阅读，缺失资源明确报错。音频资源仍由会话句柄缓存持有；离开当前句清除待消费引用，旧加载结果只能留在旧会话的资源句柄中，不能触发新会话播放。

通用音频仅新增 `PlayOwnedVoice`（不经过 SFX 音量）、句柄 `Tick/Completed/SetVolume`。Completed 只通知自然结束一次，Pause/Dispose 不伪装成完成；调用方逐帧驱动 Tick。NovelAudio 持有单路 Voice，替换/退出时 Dispose。修正无 Mixer 时 BGM 音量未落到 AudioSource 的缺口，并保留既有 PlayBGM/PlaySFX/PlayOwnedSFX 签名。音频回归已编写但本轮未执行。

历史继续使用本局原有 200 条记录，只提供显示名解析后的副本，不引入回滚。存档格式和语义指纹未改；恢复不启动 Say Voice，不重新标记当前修订为已读，不重复追加历史，默认 Manual。账号已读/偏好独立于槽位，Track 会话与设置修改时应用当前偏好。SO、稳定 ID、章节局部/全局变量恢复规则及 PlayerDataModule.Enabled=false 均保留。

正式 UI 通过 NovelM4UIBuilder 和开发中心创建历史页、追加阅读与设置控件，并保存真实 Binding；重复制作保留已存在布局。没有修改启动主菜单，Gameplay 布局窗口仅增加四个 Gameplay 控件目标。本轮不保存模板快照；后续若封存工作副本，版本说明必须同时包含 M3＋M4，不能标作纯 M3。
