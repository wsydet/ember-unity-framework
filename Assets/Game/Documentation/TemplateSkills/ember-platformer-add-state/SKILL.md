# 玩家新状态接入

读取项目 AGENTS.md、CLAUDE.md 及适用规范，确认真实 Unity 项目。调用 `Ember.Core.Editor.EmberProjectSetup.GetTemplateSkillExecutionBlockReason("ember-platformer-add-state")`；非空时停止业务写入并说明修复入口。无Unity连接只做可证实的分析。核对正式平台模板体系（含合法派生）、Player模块启用和当前真实协议/API，不按残留脚本或版本号猜测能力。

## 确定行为与影响

新增普通攻击段、停顿派生、冲刺攻击或连招连接优先转 `ember-platformer-add-attack`，复用通用攻击状态与联合事务；只有真实新行为超出现有攻击模型时才新增状态类。

读取用户目标、实际图/状态、方案、Entity能力和规则；先判断已有机制、参数或三个air入口的附加条件是否足够。若用户明确需要独立阶段，按真实状态接入，不降格为仅改Animator。读 [行为与源码路由](references/behavior.md)，只确认尚未确定且会改变行为的语义。

明确父节点、进入/退出、阶段/优先级/打断、失败、消费和清理、暂停/恢复/保存，以及可选启用来源。列出共享图与配置引用的受影响方案。用户已授权的常规编码自主处理；真正涉及配置所有权、模块边界、持久化或不明确的共享修改范围时，给出源码依据与选项，停止相关依赖工作并在当前对话确认。

## 实施完整链

按 [接入协议与验证](references/integration.md) 创建状态、Definition、声明和真实图绑定，补齐唯一参数来源、必要输入/能力/效果、捕获与完整方案工作流、动画和观察。用当前E01请求位置协议，条件只查询，预检拒绝不消费；不沿用旧的“请求前查一次、Guard再查一次”写法。

状态负责决策，Context提供本角色能力，Motor/Sensors/效果执行；PlayerModule保持唯一驱动。无次数/CD等语义的状态不强造Ability/Skill。方案冻结A和每宿主资源隔离保持，不在共享SO保存运行计时或持有角色引用。

保留旧节点ID和当前布局；新节点只安排自己的位置。补全全部图节点动画槽和必要Controller目标，动画不决定玩法退出。保存恢复明确按已有快照事实恢复，不自动保存状态对象、动作进度或Animator时间，不自动迁移旧档。

## 交付与验证

通过Unity MCP验证真实进入、持续、退出与打断，关闭/拒绝零消费、故障停止、暂停/恢复/取消清理、多实例、冻结配置、资产重载和正式/白盒同驱动。需要用户观感时展示实际画面或请用户试跑。缺动画、缺图绑定、只有空生命周期脚手架或测试未运行时，不能宣称完成。

交付影响图/方案与文件归属、使用及启用方法、动画素材需求、保存恢复行为、已测与未测项。测试示例只留隔离夹具，不为了演示Skill永久扩展正式默认图。普通保存、设默认、模板保存、Bump和发布分别按授权，不自行扩大任务。
