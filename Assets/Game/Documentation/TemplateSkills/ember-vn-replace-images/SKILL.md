# 视觉小说图片匹配与替换

用户指定的是替换用的新图，旧图从实际项目中查找；新图也可以已在项目内。若用户只指定了待替换的旧图却未给出新版本，先查清方向，不倒置新旧资源。只修改确认的目标，不删除新图、不自动替换同组全部差分。

## 检查与匹配

1. 读取项目规则，核对 Unity MCP 的项目路径，调用 `Ember.Core.Editor.EmberProjectSetup.GetTemplateSkillExecutionBlockReason("ember-vn-replace-images")`。非空则报告原因并停止写入，指向项目中心的模板技能同步。支持正式继承此技能的派生模板。无 MCP 可扫描和制作草稿，不能启用最终确认或执行替换。
2. 列出用户指定的新图，读取实际像素、尺寸、透明区域；旧图限定到项目 `Assets/GameResource` 的实际业务图片，优先用户指定剧情或用途。排除本批新图、备份、生成预览和包缓存。不得扫描整台电脑。读取实际立绘/背景源表和 Definition，用角色、表情、资源路径和已有引用缩小候选。
3. 同内容 SHA256 表示无需替换；视觉相似只作为候选排序。结合构图、角色身份、服装、表情、姿态、场景、昼夜、文件名与路径提出多个候选并说明理由。相似度分数不是正确率，不设置“超过阈值即可自动覆盖”。可用感知哈希辅助筛选，但必须实际查看新图和候选旧图，无法看图时明确标为待核对。
4. **差分不是重复文件。** 检查同角色/同背景系列，区分表情、睁闭眼、口型、服装、姿态、昼夜、天气及局部道具。把候选差分和未覆盖的同组变体列在页面警告中。角色/场景不一致、多候选难区分、一张新图拟覆盖多个旧差分时默认跳过，不能把整组图折叠成一个匹配。用户可以在页面明确选定一个旧图；其他差分保留。
5. 核查旧图的 `.meta`、GUID、Sprite 模式、切片 fileID、尺寸、透明度、pivot、pixelsPerUnit 和九宫格；查找源表 Resources 路径与序列化 GUID 引用，并通过 Unity 检查依赖。动态字符串引用无法穷举时写明检索范围，不能宣称“没有引用”。同路径覆盖会影响全部引用者，页面必须展示。多 Sprite 切片、格式不一致或需重排切片的目标先阻断；需要改变导入设置的另拟完整计划，不偷偷套用新图的 `.meta`。

## 确认页面

统一编排例外：由同级 `ember-vn-sync-images` 调用时，读取该技能并通过其统一 `verify`，以已确认回执的 `plan.replacements` 作为本技能授权计划；不再启动本节页面或要求独立 decision。首次业务写入前统一核对全批指纹与三项技能身份，之后按本技能执行和验证规则处理替换组。不得伪造本技能独立 confirmed 回执。单独调用仍遵守下面的页面确认流程。

读取 [确认服务与计划格式](references/confirmation.md)，用本技能随附 `scripts/confirmation.py` 和 `assets/confirmation.html` 启动本地页面。候选由上面的分析产生，脚本负责图片校验、尺寸/透明度提醒、选择、指纹和确认回执；它不是语义识别模型，也不直接写业务图片。

实际打开返回 URL，检查新旧缩略图、候选选择、差分警告、引用影响和最终计划。向用户给出可点击链接。候选默认跳过；用户逐图选择目标，有警告时须逐项勾选“已核对差分和影响”。允许保存草稿、重新预览和取消；选择改变即使旧预览失效。不得用聊天问题或静态拼图代替确认页面，也不得代替用户点击确认、调用 confirm 或制造回执。

只有本批 `verify --work ...` 输出 `status=confirmed` 且成功退出才执行。未提交时保留服务并说明等待页面提交；取消、关闭页面、超时、草稿都不授权替换。用户提交后回到聊天即可继续，不能假定页面会自动唤醒代理。

## 执行与验证

- 执行前再次通过 MCP 核对项目和技能身份，运行 verify，重新核对计划中的目标、引用范围和 Sprite 导入条件。新图、旧图、`.meta`、引用文件、分析计划或项目文件集合变化必须新建批次重新确认。
- 对全部选中目标先备份图片及 `.meta` 到本批 `backup/`，记录原 SHA256 与预期输出 SHA256。保留备份，不用 Git reset 清理用户改动。
- 按确认计划把新图原始字节写到旧图片路径，保留旧 `.meta`、GUID、Resources 路径、表键、切片标识和导入设置。只支持实际编码相同的独立图片；不能把 JPEG 字节塞进 PNG 文件，不隐式转码、裁剪、缩放或抠图。同内容记为无需修改。目标互相依赖或一图多目标需单独计划，本页面拒绝多个来源竞争同一目标。
- 通过 Unity MCP 导入受影响图片，验证 Sprite 可加载、GUID 与引用保持、画面尺寸/透明区和九宫格可用。只改图片字节时无需修改 CSV 或烘焙表；发现需要变更表或布局时停止该项，展示扩展计划再确认。实际查看受影响的剧情/页面预览，区分资源加载检查和画面验收。
- 中途失败停止后续写入，只对仍等于本批输出指纹的文件自动恢复；其他并发修改保留并报告。记录逐项执行结果防止把同一回执重复执行。重试先核对已完成项，不以覆盖方式绕过陈旧指纹。
- 报告替换/无需修改/跳过/失败、保留的差分、受影响引用、备份与实际验证范围。MCP 不可用遵循仓库手动编译提醒规则。模板作者修改留在 Assets，经正式 SaveTemplate → Bump 交付，不直接改模板快照或 hash。
