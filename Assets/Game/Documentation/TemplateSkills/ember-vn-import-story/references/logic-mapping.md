# 逻辑剧情映射与能力审计

先阅读目标项目实际 NarrativeData、NarrativeRunner、NarrativeValidator、NovelCheckpoint 和编辑接口。此文描述包含 CalculateVariable / RandomVariable / NovelTextBinding 的版本；旧项目缺 API 时先升级，不能只改技能便声称运行器支持。

## 分清来源数据与执行计划

- 台词、选项菜单、分支回答、事件头、逻辑备注、制作备注、空占位分开记录。逻辑可出现在台词、美术、变化或无标题的额外列，不能只搜某一列。
- 一格内的“选项1/选项一”“选项1回答”分别展开为 Choice 路线与互斥对话段；保留每段文字的原单元格与原始字符跨度。选项标签和控制指令不作为 Say 播放；逐字核对时对照提取片段，来源清单仍保存完整原单元格。
- 只有经确认的控制标记才能从显示正文中分离。例如【金钱-10】可能是执行指令，而“本月收入增加了”只是提示，不能二者重复扣款或计收益。原文存档不改；正文显示差异在预览中明确展示。
- 事件边界综合编码、分类、场景、空行和连续对话判断。重复编码、编码落在连续对白中、孤立编号、空选项、空结局、未指定跳转均列为阻断；不要自动生成可运行空事件。
- 条件语义要区分：第三次执行、遇见后第一次执行、执行过一次、每月第2或4天、随机且可重复、一次性关键事件。分别使用计数与完成标记；明确计数在进入还是完成时递增、何时清零、关键事件是否优先。

## 现有节点组合

| 需求 | 映射与验证 |
| --- | --- |
| 询问后解锁新话题 | Choice 条件过滤 + 完成话题后的 SetVariable(bool) + 回到话题菜单；全部完成时 Branch 进入主线 |
| 多级 AND/OR 条件 | NovelCondition 仅平铺 All/Any；嵌套条件拆多个 Branch，或等价展开为条件互斥的路线，保留短路语义，不能直接塞表达式字符串 |
| 跨页事件 | 工作表不是章节；按业务组织章节，同章 Connect、跨章 ChapterExit + Story 路线。明确回到哪个时段/入口，不把每页都强制做成 Chapter |
| 日/月循环 | 整数 day/slot/month + 条件分支 + 选择/对白停点。无停点循环触发 StepLimit；每段日程只推进一次 |
| 第N次与只出现一次 | 全局动作计数 + eventSeen 布尔；关键事件按明确优先级选取，完成后置标记。月计数与总计数分开 |
| 支付 | Choice 条件 money >= price；选择后 CalculateVariable(Subtract)。永远不能按最大可负债额度猜规则；余额不足的返回/兜底路线需要明确 |
| 好感、计数 | CalculateVariable(Add)，负值或 Subtract 表达下降。跨章节持久数据必须 Global，Chapter 变量重新进入章节会复位 |
| 月收入 | 用整数变量逐步计算，不执行源表公式文本。例如 income = cleanCount + plantCount；income *= 5；income += 20；money += income；结算后清零月计数。先确认源表是否已逐次入账，避免双算 |
| 随机事件池 | 先判断资格与一次性优先级，再 RandomVariable 抽整数，Branch 按不重叠区间路由；有明确兜底。未给概率、权重、可重复性或优先级时留待定，不能默认为等概率 |
| 昵称/当前金额 | Say 使用 NovelTextBinding(token, variableId, scope)，明确绑定【主控昵称】/【主角昵称】等原文占位符。原始 Text 不变，运行显示/打字长度/历史使用解析后的副本；不支持固定字位 TextBeats 与动态绑定混用 |

CalculateVariable 的 integerOperation 为 Assign/Add/Subtract/Multiply/Divide/Modulo；integerOperand 为常量，operandVariableId 非空时改取 operandScope 指定的整数变量。目标使用 variableId/scope。运算溢出或运行时除零报错并保留该条目标原值，前面已成功的指令不会回滚。多步交易先检查全部前置条件，不依赖错误实现撤销。

RandomVariable 的 randomMin/randomMax 均包含边界；会话保存随机状态，恢复稳定点不重放扣费、不重新抽取已执行事件。Schema 7 新存档记录 RandomState；旧存档只在语义一致且不含随机指令时可恢复。新增指令参数和文字绑定进入兼容指纹，旧故事没有新增字段时保留旧指纹格式。

## 计划与验收

逻辑计划至少记录 source(sheetId,row,column,原文)、事件范围与来源指纹、变量类型/作用域/初值、触发条件、优先级、权重、只执行一次标记、选项显示条件、分支入口与汇合点、成本/收益生效位置、日程返回点与待定字段。计划中有待定字段的路径不可接入正式入口。

逻辑升级验证至少包含：第三次/只一次事件，循环不锁死，余额不足，数值增减和月结算不重复，所有互斥分支与汇合，跨章持久变量，存档恢复后不重扣或重抽，空事件池与无有效选项的明确兜底。仅在内存测试或专门测试资产中验证，用户要求先不导入时不要拿正式源剧情做试导入。

没有具体数值的“好感上升/下降”、不完整学习项、概率未知、未写结局判定属于策划缺项，不是让代理填入默认玩法的授权。把具体页名、行号和需要的决策报告给用户；可完成通用能力补充，不承诺整本已能自动导入运行。

## 通用概率与数值配置示例

通用能力的实现/发布不依赖某份策划案写完。用户只要求补框架能力时，以独立测试验证；未定的概率、角色初值、结局和业务规则留给具体项目，不阻断通用能力交付，也不创建示例源表的正式剧情。

- **30% 概率**：声明 Int 变量 roll；RandomVariable 写入 0–99；Branch 的第一条路线为 roll < 30，fallback 指向未触发路径。必须只抽一次，不能每检查一个条件就重新抽。
- **20%/30%/50% 三事件**：同一次 0–99 抽样，优先路线 roll < 20 → A，下一条 roll < 50 → B，其余 fallback → C。Branch 按顺序首个命中，预览必须保留此顺序。
- **权重2/3/5**：可用0–9与阈值2、5等价表示。当前不是自动归一化的权重池节点；事件资格改变时，先分流到资格集合对应的抽样/区间配置，或明确“不合资格结果落兜底”，不能悄悄重抽而改变概率。
- **0%/100%**：直接分流到未触发/必触发路径；不要创造空随机范围。小数百分比可提高整数精度，例如0–9999与阈值125表示1.25%。
- **数值事件**：CalculateVariable(Add, 15)累加好感；Subtract扣费；Assign从另一个变量复制，再Multiply/Add组合结算公式；Divide为整数截断，Modulo可配合周期判断。运算没有自动限幅或余额约束，需要按项目规则用Branch/Choice前置条件表达。
- **一次性事件**：先检查Global的seen=false，再概率判定；触发并完成时置true。标记何时生效由项目决定。第N次事件使用独立计数变量；通用测试覆盖第3次触发且不重复。

这些是能力示例，不能拿30%、2/3/5、15等示例数字填补用户真实策划表的空白。随机状态和所有数值保存于会话稳定点，恢复不会重放已执行的扣费、奖励或抽样。
