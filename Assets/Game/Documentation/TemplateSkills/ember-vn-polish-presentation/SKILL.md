# 剧情演出优化

## 范围与基线

经 Unity MCP 核对项目，调用 `Ember.Core.Editor.EmberProjectSetup.GetTemplateSkillExecutionBlockReason("ember-vn-polish-presentation")`。非空、API 缺失或无连接时只出建议，不写资产。读取目标项目规则及正式编辑 API 的限制，消费端不被支持时明确阻断，不伪造模板编辑记录。

确认用户指定的 Story/Chapter/节点范围；可使用上一步导入清单定位，但必须读取当前资产，不能把导入时的草稿当当前状态。保存优化前资产、`.meta`、来源清单和指纹到 `.utmp/vn-presentation/<批次>/`。

建立“剧情保持项”快照：每个稳定 line ID 的完整台词与说话角色、Voice 绑定、每条路径上的 Say 顺序；选项 ID/文本/顺序/条件/去向、变量声明和赋值、章节入口/出口、节点连接与结局。保持原标点、空格、换行、括号和省略号，不拆句合句，不更换说话者，不增删选项或角色关系。原节点/command/line ID 继续使用；新增演出才创建新 ID。

## 只用当前项目已有能力

先读 `Assets/Game/Documentation/visual-novel/EffectConfiguration.md`、`Authoring.md`，再核对 `Assets/Game/Module/Narrative/NarrativeData.cs`、校验器、演出执行实现、实际配表和资源。文档与代码不符以实际实现为限，不只凭枚举名认定效果能工作。

重点能力与限制：

- `Shake` 是舞台/人物震动，不移动对白 UI；使用现有减弱/关闭偏好，不制作连续强闪或用其他效果绕过偏好。
- `Flash` 短暂闪光结束恢复原遮罩；`Cover` 的最终遮罩会留下，需要安排撤幕。两者共享遮罩通道，核对并行接管。
- 背景/人物 `Opacity` 只改变透明度，不是亮度或黑幕。双图渐变用 `CrossFade`，目标必须已显示且新资源存在。
- 人物移动/强调依赖在场实例，不把角色键、立绘键、实例 ID、动作 ID 混用。动作结束、退场和分支汇合后的状态要明确。
- 文字节奏使用结构化数据，不往台词添加控制标记；At 按 Unicode 标量计算，不按 UTF-16 长度。不能为了适配效果改正文。
- 镜头、粒子、音量渐变等仅在项目已实现且资源合适时使用。现有模板不自动具备高阶滤镜、动态立绘、口型或视频；不能把“模糊”备注假装实现。

## 制作与核对

根据原场景、美术/变化备注和已发生的剧情安排演出，优先轻量过渡、说话者强调和适当停顿。不能从一句情绪推断未写的打斗、天气、时间跳跃或人物动作；有歧义时询问。无需给每句都加效果。

先展示逐位置方案：节点/台词锚点、前后效果、目标、参数、持续时间、并行或等待关系、清理/复位位置、理由和所需现有资源。用户已授权优化的清晰范围可按方案执行；改变解释、强效果或缺资源时用选择框解决，不能编造资源键。保留作者手工编排，重复优化比较已有记录，不重复叠加相同效果。

通过项目公开编辑接口或受支持的 Undo/SerializedObject 修改命令序列，插入位置准确，不能把所有效果追加到节点末尾。提交前再次核对资产指纹；其他修改出现时重做差异。只调整选定范围，分支需分别检查入口状态，不能依赖另一条未走过的分支已经 Show 或启动动作。WaitActions 只能等待本路径已启动的动作，持续粒子/环境音不能被当作有限等待对象。

运行真实 Story/Chapter 校验，并比较全部剧情保持项；任何非预期差异都视为失败，恢复本批修改而不是解释为“只是润色”。按项目规则增加内容修订；台词未变不随意提升 textRevision。演出也参与语义指纹，旧存档可能不兼容，不删除存档或绕过检查。

在用户允许的试播范围，通过现有单节点/章节试播检查背景、遮罩撤除、人物实例、动作等待、分支汇合、结束复位；避免自动启动完整游戏并改变用户存档。通过 MCP 检查错误，实际视觉质量由用户验收，不能把静态校验说成画面通过。失败时停止并恢复本批未被并发修改的文件，保留备份及诊断。

把实际新增/修改效果、参数、锚点、优化前后指纹、剧情保持项比较结果及验证范围记录到 `Assets/Game/Documentation/NarrativeImports/<批次ID>-presentation.json`（schemaVersion=1）。仅报告已真正写入的效果，未实现项列待办。交付后可由回写 Skill 从当前资产生成策划可读流程；本 Skill 不自行修改飞书。
