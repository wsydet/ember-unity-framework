# Ember C# Region 整理

读取用户指定目标和存在的项目编码规则；已给路径不重复询问。无项目专门规定时采用下表。只给方案时不写入；用户已明确要求整理时执行已确定范围，不重复确认。大范围或涉及生成代码时先明确目标边界。

| 顺序 | Region | 默认内容 |
|---|---|---|
| 1 | 编辑器面板参数 | Unity 可序列化的实例字段、SerializeField / SerializeReference 字段 |
| 2 | 内部参数 | 非面板字段、常量、静态/只读字段、属性、事件、委托 |
| 3 | 生命周期 | 依据实际基类识别的 Unity 生命周期回调 |
| 4 | 内部方法 | private/protected 方法与私有辅助类型 |
| 5 | 外部方法 | public/internal 方法 |

空块省略；块间沿用文件的分隔注释。普通类不凭方法名套用 MonoBehaviour 生命周期；序列化条件还需考虑字段类型、NonSerialized、static/readonly，而不是仅看 public。

## 保持行为

- 仅处理项目自有源码，跳过 PackageCache、第三方、生成绑定和 Templates~/ParentSnapshot~。框架开发任务中的自有包源码须有明确目标授权。
- 注释、特性与成员保持关联，不改变可见性、类型、签名或方法体。嵌套类型完整保留；不要顺手调整业务逻辑。
- 保持静态与实例字段初始化表达式的相对执行顺序。重分组会跨越初始化依赖时保留原序或只加边界，不为了整齐改变语义。
- 条件编译块不可拆散；partial、多个顶层类型或跨成员指令逐类型评估，无法安全重排的部分保持原样并说明。
- 拆除旧 region 时只替换分组标记；不把已有逻辑嵌套结构或有效注释当作无用内容删除。

检查 diff 确认只改变组织方式，region/预处理边界配对、注释和特性未脱离成员。按项目 Unity 验证规则处理，不能以括号配对代替编译结果。报告处理范围和保留未重排的部分。
