# Ember 模块 API 文档

用户指定源码与输出时直接核对；缺少目标时扫描项目自有业务模块并让用户选定，不默认遍历所有框架/第三方包。读取实际命名空间、最近的 asmdef、依赖 package.json 和现有文档，项目布局不必是 Assets/Game/Module。

优先维护现有权威文档。项目已有 API 模板时使用它；否则使用随技能分发的 [API 文档结构](references/api-documentation.md)。这些资料不依赖开发仓库的 docs/dev。

## 输出归属

业务文档写入用户指定的项目路径、既有业务模块 README 或项目 docs。消费端读取已安装框架 API 时，结果也写入项目文档，不写 Library/PackageCache、外部依赖或安装包。框架源码开发任务才可在明确授权的框架仓库修改随包文档；模板快照不作为输出位置。

## 按实现核对

- 完整阅读目标源码，排除生成文件、第三方、测试与示例，除非它们是用户目标或验证证据。公开契约只列外部程序集可用成员，internal 可解释内部流程但不冒充业务可调用 API。
- 保留签名的关键类型、泛型、参数、返回值、可选参数与约束。依据真实实现说明默认值、生命周期、同步/异步、失败路径、资源释放和序列化行为，不能只复述注释。
- 用最近的 asmdef 和实际类型使用确认依赖，using 语句不等于程序集依赖。
- Ember Manager 与可选 Module 分开表述；Module 查询按实际 Collector API，不机械使用 Singleton.Instance。示例须使用实际安装版本的公开接口。
- 提炼少量关键调用链、修改影响和实际陷阱。推断标注不确定性；不因发现 TODO 就声称缺陷已证实。

已授权生成/更新且路径明确时写入；只要求预览则不落盘。保留原文独有设计和未提交内容，检查链接及示例接口。说明源码覆盖、输出位置和验证限制；文档示例未经 Unity 编译时不声称可编译。
