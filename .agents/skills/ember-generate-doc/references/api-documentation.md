# 模块 API 文档结构

按目标模块裁剪以下结构；已有项目模板优先，不为凑章节制造内容。

1. 快速上手：最短的真实调用示例，写清获取实例/传入依赖的方式、必要配置与清理。
2. 职责与边界：模块负责什么、属于运行时还是编辑器、由谁持有和启动。
3. 依赖：实际 asmdef、包和可选能力；写清需要与不需要的生命周期状态。
4. 文件与类型：按职责说明核心类型，不列无用的全目录清单。
5. 公开 API：完整且可区分重载的签名、参数含义、返回值、错误和副作用。internal 实现不放入消费 API 表。
6. 关键流程：调用顺序、回调、事件、资源所有权；区分请求发出与实际完成。
7. 修改影响：常见需求应修改的位置、已有调用方以及配置/数据兼容影响。
8. 限制与验证：源码确实存在的约束、已执行的检查和未验证内容。

示例依实际代码选择构造、注入、Manager 获取或 Module Collector 查询。不要默认所有类都是单例，不默认异步方法一定在后台执行；保留必要的泛型、取消和释放参数。
