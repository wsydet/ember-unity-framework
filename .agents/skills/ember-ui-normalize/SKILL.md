# Ember UI 规范整理

将用户指定范围的既有 UI 调整到项目实际采用的 Ember 规范，保留业务行为、美术表现和资产身份。此技能是跨模板公共技能，消费项目的修改只落自有 Assets 与项目文档，不因模板名称限制执行。

## 确认规则与范围

1. 阅读项目代理规则，按 UPM 实际解析位置读取 Ember 的 `Documentation~/ui/naming-and-paths.md`、`maintenance/business-directory-layout.md`、`maintenance/unity-validation.md`，并读取项目覆盖规则。包可能位于 PackageCache 或外部目录，只读使用；缺少新规范时先说明版本缺口，不把其他工程规则当作当前已安装能力。
2. 记录当前 Git 状态、生成配置、正式活动/编辑模板、实际加载后端和原场景/Prefab 编辑状态。按用户范围审查；“整理当前项目”不授权迁移其他项目、重部署模板、修改依赖包或删除业务。
3. 修改前在本次任务专属 `.utmp` 中备份拟移动/修改文件、meta 和受影响配置。备份工作区版本，不用 HEAD 替代本地改动。

## 建立可执行清单

从生成配置确定代码根和资源根，不硬编码某个项目的 UI 根。扫描范围内 Page/Item、骨架、公共库、变体与嵌套 Prefab，核对名称、Binding 角色、类名、ClassPath、实际脚本路径和页面注册。推荐名称不是批量重命名历史资产的依据；明确的问题修正，兼容名称保留并说明。

逐项记录：原路径、GUID、目标路径、类别、实际用途、固定引用/动态选择、消费者、动态地址及修改位置、导入参数、来源和验证方法。图片尺寸从真实文件或导入资产读取。按使用方式分类：

- Prefab 固定引用且适合集合打包的小图放 Atlas。
- Prefab 固定引用的独立图片放 StaticTexture。
- 按 ID/表格/配置选择内容的图片放 DynamicTexture；小头像也可能属于此类。

查找 Prefab/场景/ScriptableObject 的 GUID 引用，以及代码、CSV/TSV、配置和运行数据中的字符串路径。检查导入工具默认目录、BUI/制作请求、测试夹具、公共库和动态拼接地址。静态零引用不代表可以删除；用途不明只阻塞相关项，不猜测归类。

Common 按真实公共用途判断；模块私图归实际消费者。字体图集、Shader 数据、特效、RenderTexture 和原始素材单独核查。512×512 仅为缺少项目预算时的复核建议，不凭尺寸批量缩图或机械迁出 Atlas；保留九宫及高 PPU 图的合理例外并记录。

## 实施调整

- 先预检目标路径、重名和大小写冲突。用 Unity `AssetDatabase.MoveAsset` 移动正式资产/脚本，检查返回错误并保持 meta/GUID；不用文件复制、重建 meta 或直接编辑 Prefab YAML 代替 Unity 资产操作。
- 分离类、脚本路径和图片路径的迁移。仅移动图片不重写无关绑定；需要调整 ClassPath/名称时，用真实 Binding 的序列化配置或正式快照 API 修改，再通过 UI 中心/公开生成 API 重新生成。保留用户逻辑、IsFramework、代码模式与嵌套所有权，不手改 Binding.cs、EmberManaged 或生成注册。
- GUID 保留后仍须更新 Resources/其他后端字符串地址。修改配表源后走项目正式生成入口更新运行数据，不直接改 bytes 冒充烘焙；工程外源表按真实配置定位，不擅自另建项目内第二来源。同步导入默认值与制作来源，避免下次制作回到旧目录。
- 新建分类目录只服务实际资源或用户指定模块模板；需要传播目录时使用现有中心的预览/同步服务，不给所有模块堆空目录。
- 消费端不调用 SaveTemplate、Bump 或父子同步。框架维护任务才通过正式加载 → Assets 编辑 → 保存处理各模板；切换前告知目标及可能的人工弹窗，保护原工作区。升版、提交和发布按现有授权分别处理，不修改快照或父基线绕过中心。

若某项操作返回错误或超时，先回读路径/GUID/回执和编辑身份，不重复执行结果未知的移动、生成或模板加载。只恢复本任务有明确备份和所有权的对象。

## 验证与交付

移动后回读原 GUID 指向的新路径、实际 Sprite/Texture 类型、Prefab 嵌套/变体引用、ClassPath 与生成文件，核对资源名和运行时地址。按项目 Unity 规则通过 MCP 刷新；代码/生成结果变化后主动请求编译，确认本轮编译和域重载完成并检查 Console。

选择直接受影响的页面打开、动态图片加载、列表复用/释放和相关测试；无需全量回归。不可用的 MCP 按项目有界重连规则处理，不用 dotnet 或日志轮询替代。分别报告资源调整、正式生成、编译、行为验证和未覆盖项；纯审查不宣称已整改，目录对齐不宣称图集已打包。

交付实际迁移清单、保留的兼容/预算例外、未决项及恢复原编辑现场的结果。只有用户要求清理时才处理已证明无用的资源；不要顺带删除历史素材或重新制作图片。
